# 计算目标 DAG 与节点详情验收

## 实现

- 计算任务中心按计算目标显示列表，展开一个目标时才绘制依赖图。
- 原子因子、复合因子、指标公式、质量校验节点分别显示名称、版本和状态。
- 点击节点打开详情抽屉，查看版本 ID、节点 ID、目标、快照、执行次数、执行实例、起止时间、租约和源数据信息。
- 在抽屉点击上游名称，可以查看同一目标内对应的节点；仅失败节点提供重试，并保留二次确认。
- 刷新同一批次保留展开的目标及当前详情，详情内容使用刷新后的节点数据。切换批次时清除旧选择。
- 缺失或循环依赖明确提示，不根据列表顺序推断连线。图在小屏内部滚动，不撑宽整个页面。
- 起始节点左对齐、分列显示计算层级，使用平滑连线和类型色条，支持缩放、还原及相关依赖高亮。

## 接口补充

原接口：`GET /api/v1/calc/batches/{batchId}`。没有新增查询接口，也不改变计算和重试机制。

目标新增字段：

| 字段 | 说明 |
| --- | --- |
| targetCode | 基础目标或下钻目标编码；targetKey 仍是内部标识，不作为页面标题 |
| periodType | 计算周期类型 |
| periodStart、periodEnd | 统计开始和结束日期，结束边界不包含在区间内 |
| grain | 此目标实际保存的分组字段列表 |
| drillPathName、drillLevelName | 对应版本的路径和层级名称，缺少元数据时允许为空 |

节点新增字段：

| 字段 | 说明 |
| --- | --- |
| dependencies | 此目标内上游节点的 nodeCode 列表，来自已保存的节点配置 |
| nodeName | 因子名称、指标名称或质量校验名称 |
| ownerType、ownerVersionId、versionNo | 节点实际执行的业务对象和版本；因子节点不使用指标版本冒充因子版本 |
| startedAt、finishedAt | 最新执行尝试的开始和结束时间 |
| updatedAt | 最新执行尝试的更新时间，不冒充精确心跳时间 |

批次详情仍使用 3 次数据库连接借用，不在节点映射过程中逐个查询元数据。

## 直接依赖修复补充

- 新批次从冻结公式的 root 表达式读取 FACTOR_REF，不再把复合因子展开后的全部因子都连到指标。
- 如果公式确实同时引用复合因子及某个上游原子因子，两条直接依赖都保留，不用简单的传递约简代替公式解析。
- 新批次创建时检查直接引用对应的节点确实存在，避免创建永远无法就绪的公式节点。
- V33 Java 数据迁移分批读取已结束批次，仅在冻结公式有效、原依赖包含全部直接引用时移除多余依赖。运行中的批次不修改，无法安全判定的历史节点跳过。
- 原依赖保存到节点配置的 legacySchedulingDependencies，计算公式、编译产物、快照和计算结果不改动。
- 真实批次 10 个目标逐个验证：每目标 6 个节点、5 条依赖，无原子费用因子到指标的多余直连。
- 部署前后对比该批次全部目标 ID、快照 ID、节点 ID、执行状态、尝试次数、开始/结束/更新时间，完全一致，没有重新计算。
- 后端定向测试通过；应用、基础设施、Web、Worker 和迁移回归通过。全量命令中的本地 IdmpApplicationTests 启动测试因缺少平台数据库凭据失败，排除该环境测试后其余回归通过；实际 API 和 Worker 启动在服务器验证通过。
