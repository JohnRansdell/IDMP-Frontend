## 内部标识及错误分支

这些不是本次已隐藏的“资源编码”，但仍不适合强迫普通用户复制输入：

- `FactorTemplateEditor.vue:51` 下钻路径版本 ID；`IndicatorMapping.vue:73、81` 指标版本 ID；`CalculationTaskCenter.vue:124` 场景版本 ID；`ComponentScopeInspector.vue:17` 场景版本 ID；`WarningWidgetInspector.vue:7、8` 指标版本 / 规则 ID。建议改为名称选择，必要时在诊断详情保留 ID。
- `FactorExpressionNode.vue:9` 选项尾部直接拼接 ID；因子 / 指标详情头部、模板实例化完成页、计算目标与依赖面板还显示版本或结果 ID。版本号有意义，内部数据库 ID 默认可隐藏，运维追溯按权限保留。
- 指标编辑脚本存在“后端未返回指标 ID / 版本 ID / 试算任务 ID / 正式批次 ID”等异常文案（`IndicatorEditor.vue:1574、1675、1792、1909、2027`），值集版本创建存在“后端未返回新版本 ID”（`ValueSetDetail.vue:70`），元数据保存存在“后端未返回编辑所需的版本号或可空信息”（`features/meta/fieldUpdate.js:3`）。这些确有契约异常，面向用户应提示“保存 / 查询失败，请重试”，细节写诊断，不可静默成功。
- 下钻名称补全异常（`features/analysis/trendGrain.js` 中根结果 ID、版本或快照不一致）和图表唯一粒度异常（`features/dashboard/bindingEngine.js`）属于真实异常，建议使用“数据上下文已更新，请重新查询 / 维度结果重复，请联系管理员”等业务描述。
- 请求层已使用 `utils/userMessage.js` 清理部分路径、traceId 和技术字段，但页面直接展示 `error.message` 的分支仍会绕过统一措辞。不能仅删除静态横幅就认为提示治理完成。

## 不应误删的内容与开发隔离

- `DashboardGridPoc.vue` 的 PoC、GridStack save(false)、Zero-Reactivity、localStorage key 均为开发验证信息；路由在 `import.meta.env.DEV` 中注册，生产环境不可达。本次不是生产泄漏项，应继续保持隔离。

- “暂无完整结果，请先计算”是否误导需要计算状态证据，单独在任务 4 处理；本审查不凭空断言未计算。
