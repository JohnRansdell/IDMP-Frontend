# 场景关联交互预览操作说明

本预览分支：`feat/scenario-association-ux-20261113`。基于远程 main 的 `6c840b1` 创建，使用独立工作目录，不替换主工作区代码。仅调整前端，复用现有后端接口。此文记录当前可操作范围，未将后端未支持的功能描述为已完成。

## 一、构建与上传

进入预览分支的目录，然后沿用原来的上传命令：

```powershell
cd F:\document\project\bilin\ruoyivue_goview\IDMP-Frontend\IDMP-Frontend-scenario-preview
scp -r .\dist\* ljh@192.168.123.14:/home/ljh/IDMP_UI/
```

`dist` 是此预览分支的生产构建，包含本次交互。不要在主工作区目录执行上传，否则可能上传主分支的其他构建。

上传会替换服务器当前前端页面。访问现有地址后刷新；若仍显示旧页面，使用 Ctrl+F5。此操作不部署后端、不自动执行关联变更或发布场景。实际点击“确认加入”“确认移出”“确认发布”仍会使用服务器业务接口，因此建议用专门的验收场景操作，核对无误再用于正式业务场景。

如需本地预览，运行 `npm run dev -- --host 127.0.0.1 --port 5186`。真实接口应通过现有代理配置接入；自动浏览器测试则全程使用模拟接口。

## 二、从哪里进入

1. 从指标目录打开“查看指标”。
2. 页面中直接显示“关联场景”卡片，无需进入完整指标编辑流程。
3. 关联针对页面当前选中的指标版本。只有已发布指标版本可以加入或移出场景。
4. 指标编辑页的“场景关联”页签也使用同一套操作。

页面会分别核对场景的当前发布版本和待发布草稿，而不是把历史版本中的关系当成当前关系。读取失败时显示“待核对”及错误原因，不把未知状态当成“未关联”。

## 三、加入场景

1. 点击“加入场景”。
2. 按场景名称搜索，勾选一个或多个场景。列表明确显示“已发布”或“未发布”。
3. 已有关联、已有待加入变更、待移出、停用、权限不足或读取失败的场景会说明原因，不能重复加入。
4. 点击“确认加入”。
5. 系统自动使用现有可编辑草稿；若场景只有正式版本，自动从该版本创建草稿。
6. 加入成功后，卡片显示“待加入”。此时只保存了变更，没有自动发布。
7. 点击该场景的“查看变更”，进入场景“关联指标”页，核对后发布。

系统会保留其他指标的周期、组织范围、组合粒度和上报要求，不替换已发布配置。多选场景逐个保存；若部分失败，会显示已完成数量及失败原因，剩余项目可核对后重试，不承诺跨场景事务。

## 四、移出场景

1. 在“已生效”的场景行点击“移出场景”。
2. 确认框说明：操作先保存为待移出，历史结果保留。
3. 确认后，系统自动找到或创建草稿，并只移除当前指标版本。
4. 列表变为“待移出”。正式版本此时仍保留原关联。
5. 进入“查看变更”，发布场景变更后，当前正式配置才不再包含该指标。

若后端配置或资源版本在确认后变化，停止提交并提示刷新，不自动覆盖其他人的修改。若自动创建草稿后保存关联失败，会明确提示草稿可能已存在，需刷新核对。

## 五、撤销待发布操作

- **撤销加入**：移除草稿中新加入、尚未正式生效的关联。
- **撤销移出**：把正式版本的关联恢复到草稿，保留原有周期、范围、粒度和上报设置。
- 两种撤销都不会自动发布。
- 若撤销加入会让草稿变成空集合，仍会触发下文的后端限制，不能假装撤销成功。

## 六、核对与发布

1. 场景页顶部显示本次加入、移出及关联设置调整的数量。
2. 关联列表将新加入项标为“待加入”，移出的指标另列在“待移出的指标”区域，可以撤销移出。
3. 点击“发布变更”，先打开复核对话框，展示指标增减清单；此步骤不保存、不发布。
4. 确认本次包含的全部配置，尤其是已有草稿中其他人保存的修改。
5. 点击“确认发布”，才执行保存、后端校验与发布。
6. 点击“返回核对”或关闭复核框，不发布。
7. 发布后新场景版本生效，历史发布版本及历史计算结果保留。

发布确认包含该场景全部已保存变更及当前页面修改，并非只发布刚才点击的那一项。对话框打开后若页面配置发生变化，需要重新核对。

## 七、当前后端限制：最后一个指标

现有接口要求场景指标集合至少一项，空集合在请求校验和服务层均被拒绝；空场景也不能发布。目前没有已接入的场景停用/归档操作。

本预览版在移出或撤销前检查最后一项，明确解释并停止操作，不创建无用草稿，不发送必定失败的空集合请求。场景页也在点击移出时提示，避免最后才发现无法保存。

因此，以下设计目标尚需后端配合，并不属于本次已实现能力：

- 将已有草稿清空后保存。
- 撤销只有一个指标的草稿中的唯一加入操作。
- 移出最后一个正式指标时，停用或归档场景。

后端需要同步调整集合最小长度校验、空集合对应的覆盖规则清理 SQL，并定义最后一个正式关联的退出规则。前端不能通过删除历史关联或仅隐藏列表来代替这些处理。

## 八、建议验收步骤

使用至少包含两个指标的测试场景：

1. 查看指标，确认能区分已生效、待加入、待移出。
2. 对一个只有正式版本的场景执行加入，确认无需选草稿即可保存待加入。
3. 在发布前查看正式场景，确认原正式配置未变。
4. 撤销加入，确认其他指标及其设置仍在。
5. 对已生效场景执行移出，检查待移出提示；撤销移出后检查原关联设置恢复。
6. 再次移出，进入场景页查看增减摘要。
7. 打开发布复核再取消，确认未发布；重新核对后明确确认发布。
8. 检查新正式版本不含移出的指标，历史发布版本仍可追溯。
9. 使用单指标场景尝试移出，确认显示限制且不提交空集合。
10. 使用只读账号、草稿指标及手机宽度检查按钮状态、提示和布局。

- `npm test`：全量单元和组件测试。
- `node test/scenario-association-preview.e2e.mjs`：真实浏览器、全模拟接口，验证加入/移出/撤销/复核/发布、并发保护及桌面和手机布局，不写服务器业务数据。
- `npm run build:prod`：构建上传使用的 dist。

浏览器测试证据在 `.tmp/scenario-association-preview/`，不进入 Git；模拟测试通过不等于已在远程业务场景执行验收。
