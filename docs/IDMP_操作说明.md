# IDMP 操作说明

> 文档状态：操作说明
>
> 接口基线：IDMP 当前实现接口文档与测试样例（基于方案 revision 1047）0907.md
>
> 适用前端：IDMP-Frontend 当前工作区页面
>
> 最后整理：2026-09-08
>
> 面向角色：数据管理员、指标管理员、场景管理员、映射审核人员、预警处置人员、验收人员

本手册按实际操作顺序介绍数据治理、值集、因子、指标、场景、计算任务、分析下钻、指标映射和预警处置。平台的主业务链是“原始数据 → 统一业务口径 → 因子 → 指标 → 场景 → 正式计算 → 分析/下钻 → 预警处置”；指标映射则是一条独立的跨政策口径治理链，不会改变指标公式或重新计算结果。可以从头阅读，也可以根据要完成的工作直接跳到对应章节。文中的表格用于说明页面信息和判断标准，不需要填写。

## 1. 如何使用

### 1.1 按工作内容查找章节

|要完成的工作|查看章节|
|---|---|
|准备来源表、数据域和语义字段|3.数据治理|
|维护标准值、连续值或源值转换规则|4.值集与源值标准化|
|创建因子或使用因子模板|5.因子管理、6.因子模板|
|配置指标或场景|7.指标管理、8.场景管理|
|查询计算任务、正式结果、场景对比或下钻数据|9.计算任务、10.指标分析、场景对比、下钻与追溯|
|维护跨政策指标关系|11.指标映射人工治理|
|配置预警、查看通知和处置异常|12.预警规则、事件与通知|
|走一遍完整业务流程|13.端到端验收案例|
|排查异常或判断是否验收通过|14.常见问题与状态判定、15.验收判定依据|

### 1.2 文中的提示怎么看

- **入口**：从左侧导航进入功能页面的路径。
- **前置条件**：开始操作前必须已经完成的准备工作。
- **风险提示**：该操作可能修改共享配置、覆盖集合内容或发布新版本，执行前需再次确认。
- **预期反馈**：操作完成后，页面应该显示的状态或结果。验收时不能只看“操作成功”的弹窗，还要核对页面回显和数据状态。

### 1.3 操作前先确定使用现有数据还是新建测试数据

有两种操作方式：

1. **查看现有数据**：使用已经发布的对象，只查询列表、版本、结果和任务，不修改原有配置。
2. **新建测试数据**：为本次操作创建一套独立对象。建议使用统一且唯一的后缀，例如 `TEST_20260827_01`，并将该后缀用于数据域、值集、因子、指标和场景编码，便于查找和清理。

不要在查看现有数据的过程中改动原对象，也不要用测试对象覆盖历史样例。如果确实需要调整已发布内容，应新建草稿版本；如果只是验收或练习，优先新建一套独立的测试对象。

## 2. 开始操作前需要了解的事项

这一章集中说明各页面都会遇到的导航、权限、版本和任务状态。遇到按钮找不到、保存冲突或任务状态不明确时，可以先回到这里检查。

### 2.1 从哪里进入功能页面

|导航分组|菜单|主要用途|
|---|---|---|
|总览与分析|指标总览、指标分析、预警中心|查看汇总、趋势和分析结果|
|指标配置|指标目录、因子管理、因子模板、场景管理、指标映射|配置因子、指标和场景|
|数据治理|数据源管理、数据域管理、值集管理|准备计算所需的数据|
|计算运行|计算任务|查询任务进度，处理取消或重试|
|平台管理|系统管理|管理登录会话和系统功能|

准备数据时，一般按“数据源管理 → 数据域管理 → 值集管理”的顺序操作。请从左侧导航进入页面，不使用旧的 `/data` 兼容地址。

### 2.2 找不到菜单或按钮时先检查权限

不同角色看到的菜单和按钮可能不同。如果页面缺少某个入口，先确认当前账号是否具备相应权限，不要通过手工拼接 URL 进入受限页面。

|动作|通常需要的权限或角色|
|---|---|
|同步来源、创建数据域、映射字段|数据管理员|
|维护值集和转换规则|数据管理员或标准管理员|
|创建、发布因子及模板|指标管理员或模板管理员|
|创建、发布指标|指标管理员|
|维护场景|场景管理员|
|创建映射、提交审核|映射管理员|
|审核映射、使映射失效|映射审核人员|
|取消批次、重试节点|计算运维人员|
|配置预警规则、启停预警规则|指标管理员或预警管理员|
|确认、关闭预警事件|预警处置人员或质量管理人员|

即使按钮可见，提交时仍可能因为权限不足返回 403。遇到这种情况，记录页面返回的 `traceId`，交给管理员或开发人员定位。

### 2.3 编辑和复制 ID 时需要注意什么

- 因子、指标、值集、模板和场景都有版本。版本发布后通常不能直接编辑，需要基于已发布版本新建草稿。
- 多人同时编辑一个草稿时，后保存的人可能看到 409。此时先刷新页面，对比最新内容后再修改，不要连续重复提交。
- 复制业务 ID 时按文本处理。不要在 Excel 或其他工具中把 ID 转成数字，否则较长的 ID 可能丢失精度。
- 发布、删除或恢复对象前先刷新详情，避免基于旧页面执行操作。

页面中的 `resourceVersion` 用来判断当前内容是不是最新版本，通常不需要手工填写。

### 2.4 计算提交后怎么看任务状态

试算和正式计算不会立即返回最终结果。提交后先保存页面显示的 `taskId`、`batchId` 和时间范围，再用这些信息查询进度和结果。

|状态|含义|操作建议|
|---|---|---|
|`QUEUED`|已受理，等待执行|等待或刷新状态|
|`RUNNING`|正在执行|继续查询任务或批次|
|`SUCCEEDED` / `SUCCESS`|任务成功结束|读取结果，并检查质量状态|
|`FAILED`|任务失败|查看节点错误、`traceId` 和源数据状态|
|`CANCELLED` / `CANCELED`|已取消|确认是否需要重新创建批次|
|`PARTIAL_SUCCEEDED`|部分目标成功|逐个检查失败目标，不能整体判定通过|

任务显示成功后，还要继续确认结果已经生成且可以读取。验收正式结果时，还需检查 `qualityStatus`、源数据状态以及结果是否已激活。只有这些条件都正常，结果才可以用于后续分析。

### 2.5 创建因子或指标前先检查数据

创建因子、指标或发起试算前，先确认对应的数据域、语义表和字段已经准备好：

|数据条件|作用|
|---|---|
|数据域与语义表|限定因子能够使用的数据范围|
|默认时间字段|决定试算周期和正式计算周期如何作用于数据|
|数值度量字段|用于求和、平均值和连续范围筛选|
|维度字段|用于枚举筛选、分组、排名和下钻|
|已发布值集|为字段提供标准值或连续值规范|
|可用数据周期|决定试算和正式计算是否能够得到结果|

如果下拉框中找不到目标数据域、语义表或字段，通常不是手工输入名称就能解决的问题。请回到“数据治理”和“值集与源值标准化”，依次检查来源是否已同步、字段是否已映射、默认时间字段是否已设置，以及值集是否已发布并绑定。

### 2.6 页面中常见的技术词

|页面术语|含义|
|---|---|
|对象 ID / 版本 ID|系统为对象及其版本生成的唯一标识；以页面回显为准|
|`taskId`|异步任务标识，用于查询试算或计算进度|
|`batchId`|计算批次标识，用于查询一组计算任务及结果|
|`traceId`|错误追踪标识，用于定位后端异常|
|`resourceVersion`|并发控制版本号；页面数据过期时可能返回 409|
|DSL|因子筛选和统计口径的结构化技术表达，通常由页面配置自动生成|
|`qualityStatus`|结果质量状态，用于判断结果是否可用于后续操作|
|`nextLevels`|当前下钻结果允许继续进入的下一层级|
|`__UNASSIGNED__`|源数据缺少维度编码时使用的未分配归桶|
|已激活正式结果|已由正式批次成功生成并切换为可供分析使用的结果；试算结果不属于正式结果|
|语义组|把不同政策下可能表达同一业务主题的指标版本归在一起，并指定一个基准指标版本|
|映射|两个已发布指标版本之间经人工核对后的关系；用于口径治理和对比，不参与计算|
|预警规则|对已发布指标版本、统计周期、场景范围和判定条件的版本化配置|
|预警事件|正式结果激活后，符合已启用预警规则而生成的待处理事项|
|站内通知|向接收人发送的消息；“已读”不等于预警事件已确认或已关闭|

## 3. 数据治理

### 3.1 数据源管理：同步并查看来源结构

**目标**：让后续数据域工作台可以选择真实的来源表或视图。

**入口**：数据治理 → 数据源管理。

**操作步骤**：

1. 点击“同步数据结构”。
2. 在确认框中确认本次同步范围。
3. 等待页面显示同步结果；如失败，先查看错误信息后再重试。
4. 在“数据表与视图”区域按名称、对象类型或注释筛选。
5. 点击“查看字段”，核对字段名、类型、可为空和注释。

**预期反馈**：来源表或视图出现在列表中，所需字段可被读取。

**不通过处理**：

- 列表为空：确认后端来源连接、同步权限和同步任务状态。
- 新建语义表时来源表下拉为空：先回到本页完成同步，不要手工输入未发现的表名。
- 字段类型与预期不一致：以来源结构为准，重新选择语义字段数据类型和业务角色。

### 3.2 数据域管理：创建并进入工作台

**目标**：按业务主题隔离语义表、语义字段和后续因子引用范围。

**入口**：数据治理 → 数据域管理。

**操作步骤**：

1. 点击“新建数据域”。
2. 填写唯一的数据域编码、名称和说明。
3. 点击“确认创建”。
4. 在数据域目录中定位新记录，点击“进入工作台”。

**预期反馈**：目录可查询到新数据域，工作台顶部显示对应名称和编码。

> 风险提示：当前页面重点覆盖创建、语义表和字段映射。若后端要求数据域处于已发布状态才能在因子编辑器中选择，请在创建因子前确认该前置状态；不要为了绕过限制改用其他业务对象。

### 3.3 数据域工作台：创建语义表

**目标**：将一张已同步的来源表或视图纳入数据域。

**入口**：数据治理 → 数据域管理 → 目标数据域 → “进入工作台”。

**操作步骤**：

1. 在“语义表”区域点击“新建语义表”。
2. 在“来源物理表”中选择已同步对象。
3. 填写语义表编码和名称。
4. 点击“确认创建”。
5. 在语义表列表中选择刚创建的语义表，作为下方字段映射的上下文。

**预期反馈**：语义表列表显示来源物理表、默认时间字段和状态；右侧或下方显示当前语义表上下文。

### 3.4 数据域工作台：映射语义字段

**目标**：将物理字段赋予可被因子和指标理解的标准业务含义。

**入口**：数据域工作台 → 选择语义表 → “语义字段映射”。

**操作步骤**：

1. 在“来源字段”列表中点击目标物理字段。
2. 填写标准字段编码、业务名称和标准数据类型。
3. 选择业务角色：
   - 维度：用于筛选、分组和值集绑定；
   - 度量：用于金额、数量等数值聚合；
   - 属性：用于描述性信息。
4. 必要时标记敏感信息。
5. 点击“保存字段映射”。
6. 刷新或在“标准业务字段”列表核对映射状态、来源字段、数据类型和业务角色。

**重点**：数据类型与业务角色必须分别选择。例如性别通常是 `STRING/CODE + DIMENSION`，金额通常是 `DECIMAL + MEASURE`，不能只凭字段类型推断用途。

### 3.5 配置默认时间字段

**目标**：为语义表提供统计周期的默认绑定字段。

**入口**：数据域工作台 → 选择语义表 → 页面下方“默认时间字段”。

**操作步骤**：

1. 确认时间字段已经完成映射，数据类型为日期或日期时间。
2. 在下拉框选择该字段，例如“出院时间（OUT_TIME）”。
3. 点击“保存默认时间字段”。
4. 刷新语义表列表，确认“默认时间字段”列已回显。

**预期反馈**：因子编辑器选择该语义表后，能够识别统计周期字段。

### 3.6 字段画像

**目标**：在建值集或标准化规则前确认真实源值分布。

**入口**：数据域工作台 → 标准业务字段列表 → “字段画像”。

**操作步骤**：

1. 选择已映射字段。
2. 点击“字段画像”。
3. 核对总记录数、空值数、不同值数，以及离散值的记录数和占比。
4. 根据真实源值决定值集项和转换规则，不能仅凭字段名称推测取值。

**预期反馈**：不能根据字段名猜测 `1/2/9`、`Y/N` 等源值含义；应以画像和业务确认结果为准。

## 4. 值集与源值标准化

### 4.1 当前页面可操作的值集类型

|业务数据形态|值集匹配模式|适用示例|
|---|---|---|
|固定编码的一一对应|精确枚举（`EXACT`）|性别、状态、是否标识|
|连续数字或日期|连续值集（`CONTINUOUS`）|金额、数量、日期时间|

连续值集只约束单位、精度和合法边界，不维护“1000 至 5000”这样的值项；实际范围在因子筛选条件中填写。

### 4.2 创建精确枚举值集

**入口**：数据治理 → 值集管理 → “新建值集”。

**操作步骤**：

1. 填写值集编码、名称、值类型、来源标准名称和说明。
2. 在“数据组织方式”选择“精确枚举”。
3. 创建后进入值集详情，打开草稿版本。
4. 在“值项维护”中维护编码、标准值、标签和排序。
5. 点击“保存值项”。这是全量替换操作，保存前确认未误删既有项。
6. 点击“校验版本”，处理诊断信息。
7. 校验通过后点击“发布版本”。

**预期反馈**：版本状态变为已发布；已发布版本可用于字段绑定。

### 4.3 创建连续值集

**入口**：数据治理 → 值集管理 → “新建值集”。

**操作步骤**：

1. 填写编码、名称和说明。
2. 选择数值、日期或日期时间值类型。
3. 选择“连续数值/日期”。
4. 填写连续范围规范：
   - 数值：单位、总精度、小数位、可选最小值和最大值；
   - 日期/日期时间：单位，以及可选时间粒度和时区。
5. 点击创建并进入详情。
6. 在版本编辑页核对“连续值规范”，不维护枚举值项。
7. 校验并发布版本。

**校验要点**：整数不允许小数；小数位不得超过定义精度；最小值不能大于最大值；单位不可缺失。

**预期反馈**：详情页显示连续值规范，值项数为零是正常现象。

### 4.4 将值集绑定到语义字段

**入口**：数据域工作台 → 标准业务字段 → “绑定值集”。

**操作步骤**：

1. 选择已映射字段。
2. 点击“绑定值集”。
3. 确认当前绑定状态。
4. 选择类型和匹配模式兼容的已发布值集。
5. 点击“确认绑定”，再刷新字段列表确认结果。

**风险提示**：重新绑定会影响后续因子筛选可引用的已发布值集版本。共享字段的变更必须经过影响评估；隔离验收应使用新字段。

### 4.5 源值标准化

**目标**：将各来源系统的物理值转换为统一的标准值项。

**入口**：数据域工作台 → 目标维度字段 → “标准化”。

**操作步骤**：

1. 先完成字段画像和值集发布、绑定。
2. 打开“源值标准化”页面，查看当前源字段和已有规则。
3. 新建或编辑转换规则，将每个真实源值映射为标准值项编码。
4. 预览规则，重点检查未匹配数量。
5. 校验并发布规则。

**验收标准**：所有业务范围内的源值均有明确处置；未匹配值为零，或页面显示的未匹配情况已得到业务确认。

### 4.6 值集改版和归档

已发布值集不可直接覆盖修改。需要调整时，在值集详情点击“复制为新版本”，编辑草稿、校验、发布。当前生效版本不能直接归档。

## 5. 因子管理

### 5.1 新建因子

**入口**：指标配置 → 因子管理 → “新建因子”。

**前置条件**：数据域、语义表、必要语义字段已经准备完成；如需要运行期周期，语义表已配置默认时间字段。

**操作步骤**：

1. 在“基础信息”填写唯一因子编码、名称、业务分类和说明。
2. 在“计算口径配置”选择数据域和语义表。
3. 确认页面显示的统计周期字段是否符合预期。
4. 在“统计方式”选择记录计数、去重计数、求和、平均值、最小值或最大值。
5. 按统计方式选择统计字段；`COUNT` 不选择字段时表示统计全部记录。
6. 按需要选择分组维度；不选择表示总体结果。
7. 在“筛选范围”选择全部记录，或选择显式筛选条件。
8. 点击“保存因子定义”。保存成功后，页面显示因子 ID 和草稿版本 ID。

**预期反馈**：页面进入“编译、试算与发布”步骤，并显示保存后的版本上下文。

### 5.2 因子筛选条件

|条件类型|操作要点|
|---|---|
|统计周期|选择日期/日期时间字段和“使用试算周期”；该条件写入运行期 `period` 参数|
|枚举值集|选择已绑定枚举值集的维度字段，再选择标准值项，不直接填写物理源值|
|连续范围|选择已绑定连续值集的数值/日期字段，填写开始值和结束值|
|逻辑组合|使用 AND、OR、NOT 组织条件，检查口径预览是否符合业务含义|

连续范围按左闭右开区间 `[开始值, 结束值)` 执行。页面应自动引用字段当前绑定的已发布连续值集版本，操作人员不应手工填写版本 ID。

> 注意：页面会显示默认时间字段的自动周期绑定说明；对需要在因子 DSL 中明确限定运行期范围的业务口径，仍应按页面提供的“使用试算周期”条件配置并在“查看技术配置”中核对。最终以发布前编译诊断和接口返回的 DSL 为准。

### 5.3 编译、推荐周期、试算和发布

**入口**：因子编辑页 → “编译、试算与发布”。

**操作步骤**：

1. 点击“编译并校验”。
2. 处理诊断后，确认编译状态为通过或通过且有可接受警告。
3. 等待页面读取后端推荐的真实数据周期；如业务需要，可手工修改为自定义周期。
4. 点击“试算并查看结果”。
5. 任务未结束时点击“刷新状态”或再次点击继续查询。
6. 读取结果，检查结果值、`qualityStatus`、源数据状态和分组维度。
7. 满足发布门禁后点击“发布因子版本”。

**发布前检查**：编译已通过、试算已成功、结果已读取、质量状态正常、版本未发布。

### 5.4 编辑已有因子和新建版本

在因子管理中按编码查询并进入编辑。修改后应重新保存、编译和试算。已发布版本不能直接作为可写草稿时，应按后端允许的版本演进方式创建或使用新的草稿版本；不要把历史发布结果当作本次编辑的验证结果。

### 5.5 删除影响、删除和恢复

**入口**：指标配置 → 因子管理 → 目标因子的删除操作；恢复入口为“回收站”。

**操作步骤**：

1. 先查看删除影响，确认依赖指标、模板实例或历史版本。
2. 仅在影响已经确认且具备授权时执行删除。
3. 删除后进入“回收站”，按编码或名称查询。
4. 先查看回收站详情及保留版本，再点击“恢复”。

**风险提示**：删除是软删除，但可能影响对象可见性和后续引用。恢复前需确认不会与已新建的同编码对象冲突。

## 6. 因子模板

### 6.1 模板的适用场景

当多个人工因子只有少量业务输入不同，例如性别、科室、日期范围或标准值项不同，而数据域、统计方式和主体过滤逻辑相同时，应优先使用模板。模板发布后，业务用户只填写显式暴露的预留参数，后端生成对应的实例因子草稿。

### 6.2 创建并发布模板

**入口**：指标配置 → 因子模板 → “新建模板”。

**操作步骤**：

1. 填写模板编码、名称、说明和适用因子范围。
2. 配置数据域、语义表、统计方式、统计字段、输出与允许粒度。
3. 如适用，引用已发布下钻路径版本。
4. 在“模板参数”中添加业务用户可填写的参数，明确编码、展示名、类型、是否必填、默认值和可选值。
5. 在“参数化筛选条件”中选择语义字段、判断方式和对应参数。
6. 创建或保存模板草稿。
7. 执行校验，处理诊断后发布模板版本。

**预期反馈**：模板目录显示已发布版本；页面可进入“创建因子”。

### 6.3 从模板创建因子

**入口**：指标配置 → 因子模板 → 已发布模板 → “创建因子”；也可从因子管理点击“从模板创建因子”。

**操作步骤**：

1. 填写实例因子的编码、名称、分类和说明。
2. 填写模板显示的预留参数。
3. 在“创建确认”核对参数和值。
4. 点击“创建因子草稿”。
5. 继续执行编译、可选试算和发布。

**验收标准**：实例因子能够在因子目录中查询到，且来源显示为模板；实例的最终 DSL 与填写的参数一致。

## 7. 指标管理

### 7.1 创建指标和草稿版本

**入口**：指标配置 → 指标目录 → “新增指标”。

**操作步骤**：

1. 在“1 基础与版本”填写指标编码、名称、分类、统计周期、定义等基础信息。
2. 点击“保存并进入公式配置”。以保存成功后页面回显的指标编码和指标 ID 为准。
3. 在“2 公式与试算”完成公式选择后，首次点击“创建版本并保存公式”。页面会同时创建首个指标版本。
4. 页面回显指标 ID 和指标版本 ID，后续公式、试算和发布均基于该版本。

**预期反馈**：页面进入可编辑的“2 公式与试算”状态。

### 7.2 配置公式和下钻能力预检

**入口**：指标编辑页 → “2 公式与试算”。

**操作步骤**：

1. 在可用因子中选择已发布且业务口径正确的因子版本。
2. 通过公式编辑器配置一个分子因子和一个分母因子，形成简单比率公式。
3. 保存公式。
4. 点击“预检下钻能力”。
5. 根据返回的 `supported`、`maxLevel`、`levels` 和限制因子，选择可用下钻路径与最大层级。
6. 编译指标公式。

**重要原则**：下钻预检的能力上限只表示“最多可到哪里”，不表示该路径已经在指标版本中启用。实际发布版本的路径配置才是分析页和下钻页的依据。

### 7.3 指标试算、发布和正式结果

**操作步骤**：

1. 选择完整的试算周期。
2. 点击“试算并查看结果”。任务处理中时继续查询状态。
3. 核对结果值、分子/分母、质量状态和失败信息。
4. 点击“发布指标版本”。
5. 如需查看分析，使用“生成正式结果并去指标分析”或在计算任务中创建正式批次。
6. 等待正式批次成功并确认结果已激活，再进入分析页。

**关键区分**：试算结果用于验证定义；指标分析页读取正式结果。不能把试算成功直接判定为分析和下钻通过。

### 7.4 指标与场景关联

指标详情页可查看当前关联的场景及实际引用的指标版本。指标编辑页的“场景关联”用于查看配置边界；场景的新增、替换和发布操作应在“场景管理”中完成。

### 7.5 指标删除和回收站

**入口**：指标配置 → 指标目录 → “回收站”。

执行删除前必须先查看影响。删除后在回收站中查看详情、保留版本并按当前资源版本恢复。恢复后再次检查场景关联和分析入口是否符合预期。

## 8. 场景管理

### 8.1 创建场景和首个草稿

**入口**：指标配置 → 场景管理 → “新建场景”。

**操作步骤**：

1. 填写场景编码、名称、类型、默认周期、主管部门和说明。
2. 点击“创建并编辑”。
3. 确认页面进入场景编辑页，首个版本为草稿。

### 8.2 编辑基本信息和关联指标

**入口**：场景编辑页 → “基本信息”“关联指标”。

**操作步骤**：

1. 若页面为只读，点击“编辑场景”创建或进入可编辑草稿。
2. 在“基本信息”调整名称、主管部门、默认统计周期、生效日期、说明和默认排除规则。
3. 在“关联指标”中仅选择已发布指标版本。
4. 对每项指标设置是否必选和上报要求。
5. 点击“保存草稿”。

> 风险提示：关联指标保存采用完整集合语义。页面中删除一项再保存，表示该项会从场景版本中移除，不是仅提交增量。

### 8.3 配置覆盖规则、预览、校验和发布

**入口**：场景编辑页 → “覆盖规则”“合并预览”“校验诊断”。

**操作步骤**：

1. 在“覆盖规则”新增场景全局或单指标覆盖。
2. 填写作用范围、覆盖类型、目标路径、覆盖值和优先级。
3. 覆盖值必须是合法 JSON。
4. 保存草稿。
5. 在“合并预览”点击“刷新预览”，核对后端生成的最终有效口径。
6. 点击“校验”，处理错误或警告。
7. 校验通过后点击“发布”。

**预期反馈**：发布后版本转为只读，目录显示正确状态和指标数。

### 8.4 创建下一草稿和处理 409

已发布场景需要继续变更时，基于发布版本创建下一草稿，不修改历史发布版本。

出现 409 时：停止重复提交 → 刷新版本 → 比较当前页面输入和服务端最新数据 → 决定重新录入、合并或放弃本次修改 → 使用最新 `resourceVersion` 保存。

## 9. 计算任务

### 9.1 查询任务和批次

**入口**：计算运行 → 计算任务。

**操作步骤**：

1. 输入异步任务 ID，点击“查询任务”。
2. 输入计算批次 ID，点击“查询批次”。
3. 查看任务状态、批次概览、计算目标与节点。
4. 展开失败节点，查看目标、节点编码、状态、错误信息、尝试次数和 `traceId`。

### 9.2 手工创建计算批次

仅在因子/指标页面无法覆盖的运维场景下使用。

1. 选择对象类型：因子版本或指标版本。
2. 粘贴对象版本 ID。
3. 选择批次类型：试算、正式计算或重算。
4. 对指标的正式计算或重算，如需按场景口径计算，选择该指标已关联且已发布的场景版本；留空表示非场景计算。
5. 选择开始与结束时间。开始时间包含、结束时间不包含，例如月度周期为 `[2026-04-01, 2026-05-01)`。
6. 点击“确认并创建批次”，页面返回新批次 ID。

**重要原则**：选择场景版本后，批次会使用该场景已发布的指标集合和覆盖规则；不能把一个场景 ID 当作普通备注填写。分析页的“创建场景计算”会预填正确的指标版本、场景版本和周期，优先从该入口发起。

### 9.3 取消与失败重试

**取消批次**：仅对尚未终止且确认不应继续的批次执行。取消后刷新批次确认最终状态。

**重试节点**：仅对可重试的失败节点执行。重试前先确认问题不是配置错误、权限不足或无数据；否则会重复制造失败任务。

## 10. 指标分析、下钻与追溯

### 10.1 查看指标正式结果

**入口**：总览与分析 → 指标分析。

**前置条件**：指标版本已发布，所选周期存在已激活的正式结果。

**操作步骤**：

1. 选择指标和指标版本（如页面提供）。
2. 选择结果周期或趋势粒度。
3. 点击“查看分析”或“查看报告”。
4. 核对当前值、分子、分母、趋势、结果时间范围和状态。
5. 打开“数据说明/数据诊断”，查看可用数据范围、结果追溯和当前可用性状态。

### 10.2 判定结果是否可用

|页面或接口状态|含义|验收结论|
|---|---|---|
|已有正式结果|所选周期可展示真实结果|可继续趋势、排名和下钻验证|
|数据待计算/计算中|存在可计算对象，但正式任务尚未完成|属于待计算状态，不判定分析通过|
|无共同可用周期|引用因子的可用源数据范围没有交集|调整周期或检查因子数据|
|部分可探测|部分因子或数据可用|不能将整体结果当作完整可用|
|有数据但计算失败|源数据存在，但计算或配置发生错误|按失败处理，查看节点和错误信息|
|无数据|该周期没有匹配源数据|不是接口故障，按业务规则判断是否可接受|

### 10.3 趋势和科室排名

在“趋势分析”中切换月、季、年粒度或指定日期范围。分析接口的周期查询按日期传递；若试算/正式批次保留日期时间，应以页面实际归一化后的日期参数为准。

在“科室排名”中确认页面标签是否显示“后端维度数据”。若仅显示演示数据，不得作为真实环境验收证据。

### 10.4 场景结果对比

**入口**：总览与分析 → 指标分析 → “场景对比”。

**前置条件**：当前选择的是已发布指标版本；至少一个已发布场景已经关联该指标版本。要显示真实数值，该场景还必须完成场景化正式计算并存在已激活结果。

**操作步骤**：

1. 选择已发布指标版本，点击“场景对比”。
2. 选择需要对比的场景版本；不选择时，页面查询当前指标关联的全部已发布场景。
3. 按需限定报告期，查看每个场景卡片中的统计周期、结果状态、值和质量状态。
4. 对已有正式结果的场景，可从卡片进入该结果的下钻；对“尚未生成已激活正式结果”的场景，点击“创建场景计算”，确认预填的指标版本、场景版本和周期后提交。

**如何理解结果**：场景对比并列展示各场景的原始统计周期，不会把月度结果强行汇总成年度结果，也不会为便于比较而改写场景口径。因此，必须先看周期范围、质量状态和场景覆盖规则，再比较数值。`NO_DATA` 表示该周期没有符合口径的源数据，不等于计算失败；`NO_ACTIVE_RESULT` 表示场景配置存在，但尚未生成可分析的正式结果。

### 10.5 下钻分析

**入口**：指标分析 → “下钻分析” → 选择结果，或进入“结果下钻”页面。

**操作步骤**：

1. 确认当前结果来自正式批次，且版本实际启用了相应下钻路径。
2. 从根层级逐级进入下一层。
3. 每次下钻核对当前路径、结果 ID、`nextLevels` 和页面面包屑。
4. 到达版本配置的最大层级时，页面应显示已到末级；没有下一层不表示接口失败。
5. 出现 `__UNASSIGNED__` 时，确认其代表缺失维度编码的归桶；它不应被直接删除，否则汇总与明细会不一致。

### 10.6 因子结果追溯

在某一指标结果中打开“因子追溯”，核对分子、分母因子版本和对应因子结果。应同时检查：

- 追溯的因子版本是否与指标公式引用一致；
- 结果是否匹配；
- 质量状态和源数据状态；
- 结果周期是否与当前指标结果一致。

## 11. 指标映射人工治理

指标映射用于说明不同政策文件或指标体系中的两个指标版本是什么关系、能否比较以及依据是什么。它不改变任一指标的公式、因子、场景配置或历史计算结果；计算链与映射链应分别验收。

### 11.1 先理解语义组、基准指标和映射关系

- **语义组**：围绕同一个业务主题组织不同政策下的指标版本，例如不同文件中的“住院死亡率”。
- **基准指标版本**：语义组中作为源侧参照的已发布指标版本。创建映射时，页面自动使用它作为源指标。
- **目标指标版本**：同一业务主题下待比较的另一已发布指标版本。
- **映射类型**：说明两者是同一业务含义、包含关系还是部分重叠；包含关系始终以源指标为参照。
- **可比性**：说明两个结果能否直接比较，或必须带条件解释。

### 11.2 创建语义组和映射草稿

**入口**：指标配置 → 指标映射。

**前置条件**：源侧和目标侧均为已发布指标版本；如需显示政策名称或维护引用，相关政策版本应已发布。

**操作步骤**：

1. 切换到“语义组”，点击“创建语义组”。
2. 填写唯一编码、名称、说明，并选择一个已发布指标版本作为基准指标。
3. 返回“映射关系”，点击“创建映射”。
4. 选择语义组，再选择目标已发布指标版本；源指标由语义组的基准指标自动确定。
5. 点击“下一步：核对口径”，查看名称、定义、公式、因子与过滤、政策依据、单位、统计周期、粒度和组织范围的结构化差异。
6. 点击“下一步：确认映射”，选择映射类型和可比性，填写人工核对依据及差异说明，创建草稿。

**为什么必须先对比再创建**：名称相似不代表计算口径相同。先展示结构化差异，可避免把“同名但统计范围不同”的指标错误标为可直接比较。

### 11.3 提交、审核、修订和失效

**入口**：指标映射 → 映射关系 → “查看”。

**操作步骤**：

1. 在草稿详情再次核对“口径差异”“人工依据与审核”“政策依据”。
2. 点击“提交审核”，状态转为待审核。
3. 审核人员选择“审核通过并发布”，可填写审核意见；或选择“驳回”，必须填写驳回意见。
4. 被驳回后，回到草稿补充证据或差异说明，保存后重新提交。系统保留原版本和驳回记录。
5. 已通过并发布的映射若不再适用，点击“人工失效”，填写失效原因。
6. 分别从源、目标指标详情反查有效映射；失效后，反查不再返回该映射，但详情、历史版本、审核意见和失效原因仍可查询。

**并发提示**：映射的提交、审核和失效也受 `resourceVersion` 保护。收到 409 时刷新详情后再判断，不要按旧页面反复提交。

**当前范围**：当前支持人工创建、口径对比、审核、发布、失效和双向反查；自动推荐、批量导入和映射报告导出不属于本手册的已完成操作范围。

## 12. 预警规则、事件与通知

预警只针对已发布指标版本的**后续已激活正式结果**评估。创建或查询规则本身不会产生事件；必须在规则发布、启用后，由新的正式计算结果激活触发后端评估。

### 12.1 创建、发布和启用预警规则

**入口**：总览与分析 → 预警中心 → “预警规则” → “创建预警规则”。

**前置条件**：目标指标版本已发布；需要限定场景时，该场景版本已发布并已关联该指标版本；接收用户可在系统用户列表中查询到。

**操作步骤**：

1. 填写规则编码、名称、预警类型、严重程度、已发布指标版本和统计周期。
2. 需要限制生效时间时填写开始、结束日期。有效期按正式结果的半开统计周期判断，例如月度 `[4 月 1 日, 5 月 1 日)` 的最后覆盖日期为 4 月 30 日。
3. 在“评估范围”选择场景版本；留空表示不按场景 ID 限制。明确选择是否纳入无场景正式结果。
4. 配置判定条件：阈值规则填写比较符和阈值；趋势和波动规则按页面填写度量及窗口；场景差异规则必须选择已发布的基准指标版本和基准场景版本。
5. 在“站内通知”选择接收用户，点击“创建草稿”。
6. 在规则列表中点击“发布”，再点击“启用”。

**状态顺序**：草稿可以编辑；已发布版本只读；只有“已发布 + 已启用 + 有效期覆盖结果周期”的规则会参与预警评估。修改已发布规则时，应按后端允许的版本演进方式创建新草稿，而不是改写历史版本。

### 12.2 触发和查看预警事件

1. 在“计算任务”或场景对比页发起与规则匹配的正式计算。
2. 等待批次成功，确认结果已激活；再进入“预警事件”刷新列表。
3. 按规则、指标版本、状态或严重程度筛选事件。
4. 打开事件详情，核对当前值、阈值、比较上下文、指标结果 ID 和站内投递记录。
5. 如需解释异常来源，点击“查看结果下钻”，从该正式结果继续分析。

**趋势与场景差异注意事项**：趋势和波动只使用统计边界连续相邻的历史周期，不会随意选取更早结果作为基线；场景差异只使用规则中明确指定的基准场景，不会从其他场景中随机取值。

### 12.3 通知已读、事件确认和事件关闭的区别

|动作|含义|不会改变什么|
|---|---|---|
|标记通知已读|接收人已阅读站内消息|不会确认或关闭预警事件|
|确认预警事件|业务人员已知悉该异常|不会关闭事件，仍可继续跟踪|
|关闭预警事件|异常已完成判定或处置|必须填写关闭原因编码|

**操作步骤**：

1. 在“站内通知”查看当前用户通知，可逐条标记已读或全部已读。
2. 在“预警事件”打开待处理事件，完成初步核实后点击“确认”。
3. 完成数据核对、业务确认或整改后点击“关闭”，填写原因编码，例如 `DATA_CONFIRMED`；测试产生的事件应使用明确的测试清理原因，不使用业务原因冒充测试记录。
4. 关闭后刷新列表确认状态；需要追溯时仍可从详情查看事件和投递记录。

**当前通知范围**：当前预警页面和已验证服务端链路只使用 `IN_APP` 站内通知。邮件、企业微信、钉钉等第三方渠道不作为当前验收或演示承诺。

## 13. 端到端验收案例

本章通过固定示例说明完整操作链路，不包含待填写内容。示例编码用于帮助理解对象之间的关系，不表示当前环境一定存在同名对象。实际操作时，应从页面下拉中选择当前环境已经准备好的数据域、语义表和字段。

### 13.1 案例 A：枚举值集过滤到双因子指标下钻

**目标**：将来源性别值标准化为“男、女、未知”，创建男性分子和全部分母，形成比率指标，并验证正式结果和下钻。

**示例对象关系**：

|对象|示例值|作用|
|---|---|---|
|数据域|`DEMO_ENUM_DRILL_20260813_01`|限定住院数据范围|
|语义表|`DEMO_INPATIENT_DISCHARGE`|承载住院记录|
|性别字段|`PATIENT_SEX`，维度字段|标准值筛选与下钻|
|时间字段|`OUT_TIME`，默认时间字段|限定统计周期|
|枚举值集|`VS_PATIENT_SEX_DEMO`|定义男、女、未知三个标准值|
|男性因子|`F_MALE_DEMO`|统计男性记录数|
|基线因子|`F_ALL_DEMO`|统计同期全部记录数|
|占比指标|`I_MALE_RATE_DEMO`|男性因子除以基线因子|

#### 13.1.1 确认数据域可用于本案例

1. 点击“数据治理 → 数据域管理”，在列表中找到示例数据域，点击“进入工作台”。
2. 在语义表列表中选择 `DEMO_INPATIENT_DISCHARGE`，核对 `PATIENT_SEX` 为维度字段，`OUT_TIME` 为日期或日期时间字段。
3. 在“默认时间字段”区域选择 `OUT_TIME`，点击“保存默认时间字段”。
4. 若字段不存在，点击“新建语义表”或在现有语义表中选择来源字段后点击“保存字段映射”；按“数据治理”补齐后再回到本案例。

**预期结果**：页面回显默认时间字段为 `OUT_TIME`。字段或数据域下拉为空，说明当前环境的数据准备尚未完成。

#### 13.1.2 创建、发布并绑定性别枚举值集

1. 点击“数据治理 → 值集管理 → 新建值集”。
2. 输入编码 `VS_PATIENT_SEX_DEMO`、名称“患者性别标准值集”；值类型选择 `STRING`，匹配类型选择 `EXACT`，点击“创建并维护值项”。
3. 在值项编辑区依次添加 `MALE`（男）、`FEMALE`（女）、`UNKNOWN`（未知），设置排序后保存。
4. 点击“校验版本”。校验通过后点击“发布版本”，在确认框中确认。
5. 返回数据域工作台，选择 `DEMO_INPATIENT_DISCHARGE` 和 `PATIENT_SEX`，绑定刚发布的 `VS_PATIENT_SEX_DEMO` 版本。

**预期结果**：值集版本状态显示“已发布”，`PATIENT_SEX` 的绑定区域显示该值集版本。

#### 13.1.3 配置来源值到标准值的转换规则

1. 在 `PATIENT_SEX` 的标准化区域进入规则编辑。
2. 示例中将来源值 `1` 映射为 `MALE`，`2` 映射为 `FEMALE`，`9` 映射为 `UNKNOWN`。真实环境应以字段画像或数据字典显示的来源值为准。
3. 保存后点击预览，核对命中数、未匹配数和输出值。
4. 预览符合预期后依次点击“校验”和“发布”。

**预期结果**：预览中每种来源值的输出值正确，未匹配值都有明确处理。若预览为空或未匹配异常增多，不发布；先核对来源字段、规则条件和当前环境数据。

#### 13.1.4 创建并发布两个因子

男性因子和基线因子使用相同的数据域、语义表、默认时间字段和统计周期，区别仅在于是否包含性别条件。

1. 点击“指标配置 → 因子管理 → 新建因子”。男性因子使用编码 `F_MALE_DEMO`，基线因子使用编码 `F_ALL_DEMO`；两者均选择示例数据域和语义表。
2. 两个因子都添加以 `OUT_TIME` 为字段的试算周期条件。
3. 男性因子额外添加 `PATIENT_SEX = MALE`；基线因子不添加性别条件。
4. 分别点击“保存草稿并继续”“编译并校验”和试算按钮。
5. 试算结果正常后，分别点击“发布因子版本”。

**预期结果**：两个因子均显示已发布，且存在可读取的试算结果。男性因子结果应不大于基线因子；若为零，应先结合源数据核对是否确无男性记录，而非直接判定页面错误。

#### 13.1.5 创建占比指标并完成分析验证

1. 点击“指标配置 → 指标目录 → 新建指标”，输入示例名称“男性占比”和说明后保存基础信息。页面会自动生成实际指标编码，应以页面回显为准。
2. 进入公式配置，选择简单比率公式：分子选择“男性因子”的**已发布版本**，分母选择“基线因子”的**已发布版本**。点击“创建版本并保存公式”（已有版本时按钮为“保存公式”）。
3. 按页面显示的步骤完成编译、试算与发布。
4. 在“计算任务”创建该已发布指标版本的正式计算批次，或使用页面“生成正式结果”入口；查询批次，确认成功、结果质量正常且结果已激活。
5. 在“指标分析”中选择该指标和与正式批次一致的周期。只有页面明确显示后端正式结果及相应批次时，才能继续正式分析验收。
6. 打开趋势、排名和“下钻分析”，逐层点击页面提供的下一层；到达末级后停止。最后打开“因子追溯”，核对分子、分母版本与公式配置一致。

**通过判定**：`0 ≤ 分子 ≤ 分母`；性别规则预览符合预期；两个因子和指标均通过页面门禁；分析页读取的是后端正式结果；下钻未超过页面返回的最大层级。

### 13.2 案例 B：连续值集到费用范围因子

**目标**：为住院总费用建立连续值集，并统计指定费用范围内的记录。

**示例对象关系**：

|对象|示例值|作用|
|---|---|---|
|数据域|`TEST_CONT_COST_20260827_01`|限定住院费用数据范围|
|语义表|`TEST_INPATIENT_COST_20260827_01`|承载费用记录|
|金额字段|`TOTAL_COST`，`DECIMAL + MEASURE`|费用范围筛选|
|时间字段|`DISCHARGE_TIME`，默认时间字段|限定统计周期|
|连续值集|`VS_CONT_COST_DEMO`|约束金额单位、精度和合法边界|
|范围因子|`F_COST_1000_5000_DEMO`|统计费用在 1000 至 5000 范围内的记录|
|基线因子|`F_COST_ALL_DEMO`|统计同期全部记录|

#### 13.2.1 核对金额字段和时间字段

1. 点击“数据治理 → 数据域管理”，进入示例数据域工作台，选择 `TEST_INPATIENT_COST_20260827_01`。
2. 选择 `TOTAL_COST`，确认它是数值度量字段；选择 `DISCHARGE_TIME`，确认它是默认时间字段。
3. 对 `TOTAL_COST` 查看字段画像，确认页面能够返回非空数据概览。

**预期结果**：金额字段和时间字段均能从页面下拉中选到。金额字段不是数值类、无数据或没有默认时间字段时，停止后续操作并由数据管理员修正映射。

#### 13.2.2 创建并发布连续值集

1. 点击“数据治理 → 值集管理 → 新建值集”。
2. 输入编码 `VS_CONT_COST_DEMO`、名称“住院总费用连续值集”；值类型选择 `DECIMAL`，匹配类型选择 `CONTINUOUS`，来源字段选择 `TOTAL_COST`，点击“创建连续值集并继续”。
3. 示例规范为单位 `CNY`、总精度 `18`、小数位 `2`、最小值 `0`、最大值 `100000000`。真实操作时，这些值应与字段定义和业务口径一致。
4. 点击“保存连续值规范”，再点击“校验版本”。校验通过后点击“发布版本”，完成确认。
5. 返回示例数据域工作台，选择 `TOTAL_COST`，绑定刚发布的 `VS_CONT_COST_DEMO` 版本。

**预期结果**：连续值集详情展示单位、精度、边界等规范，而不是枚举值项；金额字段的绑定区回显当前发布版本。校验提示精度、边界或小数位不合法时，按提示修改后重新保存和校验。

#### 13.2.3 创建费用范围因子

1. 点击“指标配置 → 因子管理 → 新建因子”。输入编码 `F_COST_1000_5000_DEMO`、名称“费用 1000 至 5000 人数”，选择示例数据域和语义表。
2. 添加以 `DISCHARGE_TIME` 为字段的试算周期条件。
3. 添加金额条件：字段选择 `TOTAL_COST`，操作符选择 `BETWEEN`，开始值输入 `1000`，结束值输入 `5000`。数值中不包含货币符号或千分位。
4. 保存草稿后点击“编译并校验”。编译通过后点击试算，读取任务状态和试算结果；成功后点击“发布因子版本”。

**预期结果**：金额条件可正常保存，试算结果有可读取的结果值和质量状态。该范围按半开区间 `[1000, 5000)` 判断，即包含 1000、不包含 5000。

#### 13.2.4 创建基线因子并进行对照

1. 再次点击“新建因子”，输入 `F_COST_ALL_DEMO`、名称“费用基线人数”，并选择同一个数据域和语义表。
2. 仅添加与“创建费用范围因子”相同的周期条件；不要添加金额条件。保存、编译、试算和发布步骤相同。
3. 比较两个因子在相同周期下的结果值和质量状态。

**通过判定**：连续值集已发布并绑定，两个因子在同一周期下均有正常结果，且 `范围因子结果 ≤ 基线因子结果`。若范围结果大于基线，或两者使用了不同周期，不通过并保存页面证据。

### 13.3 案例 C：模板实例化因子

**目标**：将通用的筛选逻辑发布为模板，再由业务用户填写参数创建实例因子。

1. 点击“指标配置 → 因子模板 → 新建因子模板”，填写模板编码、名称、说明和参数定义；保存草稿后校验并发布版本。
2. 在模板目录选择刚发布的模板，点击“从模板创建因子”。输入实例因子的编码和名称，并按模板展示的参数完成配置。数据域、字段和周期均从页面现有选项中选择。
3. 在确认页核对模板版本、参数值和生成的最终 DSL；确认无误后创建草稿，页面会显示新因子 ID 和版本 ID。
4. 点击“编译并校验”，再按页面推荐或自定义周期试算；结果正常后点击“发布因子版本”。
5. 返回模板实例列表，以模板编码和本次因子编码搜索，核对实例参数、最终 DSL、来源模板版本与因子目录记录一致。

**判定**：实例参数、最终 DSL、来源模板版本和因子目录记录一致。

### 13.4 案例 D：场景版本闭环

**目标**：为多个已发布指标版本创建一个可审计的版本化场景。

1. 点击“指标配置 → 场景管理 → 新建场景”，填写唯一编码、名称和说明，点击“创建并编辑”。
2. 在草稿页点击“编辑场景”，填写基础信息；在指标关联区选择本次已发布的指标版本并保存草稿。
3. 如业务确有覆盖需求，点击“新增覆盖”，粘贴经校验的合法 JSON；没有已审批的 JSON 时不创建覆盖规则。
4. 点击“刷新预览”，逐项核对页面展示的合并结果、关联指标数量和覆盖优先级，然后点击“校验”。
5. 校验通过后点击“发布”；返回目录，确认状态和指标数。需要继续修改时，基于发布版本创建新的草稿，不能直接改写已发布版本。

**判定**：校验失败时不可发布；发布后只读；旧 `resourceVersion` 保存能被正确识别为并发冲突。

### 13.5 案例 E：场景对比到预警处置

**目标**：将同一个已发布指标用于不同统计场景，完成场景化正式计算、原始周期对比、预警触发和处置。

**前置条件**：已存在一个已发布指标版本、至少两个已发布关联场景和可用于对应统计周期的源数据。为避免污染共享环境，测试规则、场景和批次应使用唯一后缀，并在结束后按授权停用规则、关闭测试事件。

1. 在场景管理中创建月度质控和年度评审两个场景，均关联同一个已发布指标版本；按业务需要配置覆盖规则，预览、校验并发布。
2. 分别为两个场景创建正式计算批次。查询批次，确认目标成功、结果质量正常且结果已激活。
3. 进入“指标分析 → 场景对比”，选择该指标版本，核对每张场景卡片的场景名称、统计周期、结果状态、数值和质量状态。
4. 不将不同统计周期的结果直接当作同比或环比；先解释其分别代表月度和年度口径。必要时从卡片进入下钻，解释数值来源。
5. 在预警中心创建一条阈值或场景差异规则，选择该指标版本、周期、范围、接收用户和判定条件；创建草稿后依次发布、启用。
6. 再发起一个与规则匹配的正式计算，等待结果激活后刷新预警事件。查询规则、当前值、阈值和比较上下文是否符合预期。
7. 查看站内通知，先标记已读；在事件列表确认预警；完成核对后填写原因关闭事件。

**通过判定**：场景对比读取的是各自的已激活正式结果；预警事件由规则启用后的正式结果触发；通知已读、事件确认和事件关闭的状态分别可见；事件详情可回到对应正式结果下钻。

### 13.6 案例 F：跨政策指标映射人工治理

**目标**：对两个不同政策来源的已发布指标版本建立可审计的人工映射，而不改变任何计算结果。

1. 确认两个已发布指标版本分别绑定了正确的政策引用；如页面未显示政策名称，先补齐已发布政策版本引用。
2. 创建语义组，将较稳定、可作为比较基准的指标版本设置为基准指标。
3. 创建映射，选择目标指标版本，先查看结构化口径对比。
4. 选择映射类型、可比性，填写人工核对依据和差异说明，创建草稿并提交审核。
5. 审核人员可先驳回，要求补充依据；修订后重新提交，并审核通过发布。
6. 在源、目标两个指标详情反查有效映射，核对均能找到同一关系。
7. 若映射不再适用，执行人工失效并填写原因；再次反查不应显示为有效映射，但详情历史必须保留。

**通过判定**：映射状态按“草稿 → 待审核 → 已通过/已发布 → 已失效”流转；驳回意见、人工依据、差异快照和失效原因均可追溯；映射前后指标公式、因子和正式结果不发生变化。

## 14. 常见问题与状态判定

|现象|优先检查|处理建议|
|---|---|---|
|数据域或语义表下拉为空|来源是否同步、对象状态、权限|完成来源同步；确认可用状态；不要手输对象名|
|无法使用试算周期|默认时间字段|回到数据域工作台配置日期/日期时间字段|
|值集绑定窗口没有可选项|值集是否已发布、类型是否兼容|发布正确类型的值集后刷新|
|连续值集详情没有值项|值集类型|正常；检查连续值规范，不维护枚举项|
|范围条件无法填写或校验失败|字段绑定、数据类型、起止值、精度|确认已绑定连续值集，检查 `start < end` 和小数位|
|编译通过但试算无结果|任务状态、批次、周期、源数据状态|查询 taskId/batchId，区分无数据、失败和结果尚未读取|
|发布按钮不可用|编译、试算、结果读取、质量状态|逐项完成门禁，不绕过页面状态|
|分析页没有真实结果|指标是否发布、正式批次是否成功、周期是否正确|创建或等待正式结果；不能用试算结果替代|
|场景对比没有结果|场景是否发布并关联指标、是否已创建场景化正式批次|先确认场景版本和指标版本，再从场景卡片创建正式计算|
|场景对比出现 `NO_DATA`|该场景在所示周期是否有匹配源数据|这是无数据，不是计算失败；核对周期和场景口径|
|场景对比无法直接比较数值|场景的统计周期、覆盖规则、质量状态|保留各自原始周期解释；不要把月度和年度结果强行聚合|
|下钻页为空|正式结果、实际启用路径、根结果 ID、最大层级|从分析页重新进入；检查版本配置与 `nextLevels`|
|出现 `__UNASSIGNED__`|源数据维度编码|作为缺失维度归桶保留，修复源数据或标准化规则|
|保存场景返回 409|资源版本过期|刷新最新版本、比较修改、再提交|
|映射提交、审核或失效返回 409|映射资源版本过期|刷新映射详情，核对最新审核状态后再操作|
|映射列表或政策依据为空|是否选择已发布指标版本、政策引用是否已维护|先确认指标版本发布状态和政策引用，再创建或查询映射|
|预警规则启用后没有事件|规则是否已发布启用、正式结果是否在启用后激活、周期和场景范围是否匹配|创建匹配规则的新正式批次；查询规则范围和有效期|
|趋势预警没有触发|是否存在精确连续的相邻历史周期|先补齐相邻周期正式结果，再重新计算当前周期|
|通知已读但事件仍待处理|已读与确认、关闭是不同状态|在预警事件中执行确认或关闭，并填写关闭原因|
|指标或因子不再可见|软删除或权限|检查回收站、删除影响和权限|

## 15. 验收判定依据

本章说明如何判断一条业务链路是否完整，不作为待填写的验收表使用。

### 15.1 单个对象的判断

|对象|通过条件|常见的不通过情况|
|---|---|---|
|数据域与语义表|来源表可选，字段映射和默认时间字段正确|来源未同步、字段类型或角色错误|
|值集|版本已发布，类型与字段兼容，字段绑定正确|仍为草稿、绑定了错误版本|
|转换规则|预览输出符合标准值定义，校验通过|存在未处理的来源值或错误映射|
|因子|编译、试算、结果读取和发布均完成|仅编译成功，或试算结果尚未读取|
|指标|公式引用正确，试算通过，版本已发布|分子分母版本错误，或只存在试算结果|
|场景|关联指标、覆盖规则和合并预览正确，校验后发布|覆盖值不是合法 JSON，或校验未通过|
|指标映射|两个版本均已发布，口径对比、人工依据、审核状态和历史可追溯|只按名称判断、未审核即对外使用、失效后仍作为有效映射|
|预警规则|草稿内容正确，已发布并启用，范围和基准场景符合业务定义|仅创建草稿、把查询当作触发、未区分无场景和指定场景结果|
|预警事件|能查看结果和投递记录，确认、关闭及关闭原因完整|通知已读即视为已关闭，或未核实便关闭|

### 15.2 完整业务链路的判断

一条完整的指标计算与应用链路应依次满足：来源结构已同步；语义表和字段映射正确；默认时间字段可用；值集已发布并正确绑定；因子完成编译、试算和发布；指标完成公式配置、试算和发布；场景完成关联、预览、校验和发布（如业务需要）；正式批次成功并激活结果；分析页显示后端正式结果；场景对比保留正确的原始周期；下钻和因子追溯与发布版本一致；预警规则发布并启用后能对新的正式结果生成可处置事件。

试算成功只说明定义可以执行。只有正式批次成功、结果已经激活且分析页显示后端数据时，才能判定分析与下钻链路完整。
