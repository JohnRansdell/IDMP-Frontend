# IDMP 下钻功能展示操作实例

> 适用版本：前端当前工作区版本；后端接口基于 revision 1036，测试环境为 `http://192.168.123.14:8081`。
>
> 本文用于现场演示和验收，重点说明：因子应如何配置粒度、指标应如何选择公式与下钻路径、如何生成正式结果，以及最终在哪个页面查看组织下钻、病种下钻和因子结果追溯。

> 核实记录（2026-08-13）：已使用当前服务器逐级复测组织三层、病种三层及因子追溯接口。前端已按结果路径分别选择锚点，且下钻请求不再发送自行拼接的 `period` 或其他路径的 `snapshotId`。本文以下内容以本次复测结果为准。

## 1. 演示目标

完成本文操作后，应能展示以下效果：

1. 指标趋势按月度、季度、年度切换。
2. 组织路径逐级下钻：医院 → 出院科室 → 主治医师。
3. 病种路径逐级下钻：全部病种 → 单病种 → 病例。
4. 从某条指标结果追溯到公式中的分子、分母因子及其正式结果。
5. 缺失的主治医师或单病种编码进入 `__UNASSIGNED__` 归桶，不丢失汇总数据。

## 2. 演示前准备

### 2.1 服务地址

|项目|地址|
|---|---|
|前端开发地址|`http://localhost:5173`|
|后端 API|`http://192.168.123.14:8081/api/v1`|

前端 `.env` 或运行环境应至少包含：

```dotenv
VITE_API_BASE_URL=http://192.168.123.14:8081/api/v1
VITE_DEFAULT_DRILL_PATH_CODE=ORGANIZATION
VITE_DEFAULT_DRILL_MAX_LEVEL=OUT_DEPT
```

如果前端部署在其他主机或端口，本文中的 `http://localhost:5173` 替换为实际前端地址即可。

### 2.2 数据与权限要求

- 后端服务可访问，健康检查正常。
- 当前用户具备因子、指标、计算批次和分析结果的读取权限；若要创建示例，还需要相应写入和发布权限。
- 因子和指标版本必须完成发布，正式计算必须成功并激活结果。
- 所有后端 ID 都按字符串原样复制，不要在 Excel 或 JavaScript 中转成数字，避免超大整数精度丢失。

### 2.3 推荐演示顺序

现场展示优先使用第 3 节的已验证真实指标，不需要新建任何数据。需要展示配置过程时，再执行第 4～8 节。

## 4. 实例二：从创建因子开始构造一个可组织下钻的指标

以下示例用于演示前端配置过程。经当前服务器元数据复核，性别标准化数据域和完整下钻数据域并不是同一个数据域：

- `INPATIENT_DISCHARGE_RECORD` 适合演示 `SEX → MALE/FEMALE/UNKNOWN` 标准化统计，但当前缺少标准 `HOSPITAL_CODE/HOSPITAL_NAME`，不能按本文原先写法直接构造完整组织下钻指标。
- `DRILL_DEATH_DISCUSSION_20260811171525` 具备医院、科室、主治医师、病种和病例粒度，才是第20章真实下钻指标使用的数据域。

因此，本实例调整为“死亡病例讨论完整率”，公式为“已填写死亡讨论记录数 / 死亡讨论记录总数 × 100%”。

> 当前前端指标编辑页一次只能提交一条下钻路径，且界面可选最大层级为 `HOSPITAL` 或 `OUT_DEPT`。因此本实例通过页面创建时选择组织路径并下钻到出院科室。组织 + 病种多路径的完整演示请使用第 3 节已经发布的真实指标。

### 4.1 前置语义数据

推荐使用：

|项目|选择值|
|---|---|
|数据域下拉显示|`Drill death discussion 20260811171525（DRILL_DEATH_DISCUSSION_20260811171525）`|
|语义表下拉显示|`Death discussion drill table（DRILL_DEATH_DISCUSSION_TABLE_20260811171525）`|
|默认时间字段|`VISIT_DATE`|
|组织维度|`HOSPITAL_CODE`、`HOSPITAL_NAME`、`OUT_DEPT_CODE`、`OUT_DEPT_NAME`、`ATTENDING_DOCTOR_CODE`、`ATTENDING_DOCTOR_NAME`|
|病种/病例维度|`SINGLE_DISEASE_CODE`、`DIRECT_DEATH`、`VISIT_ID`、`PATIENT_NAME`|

前端现在把元数据下拉项显示为“名称（编码）”，可输入中文/英文名称或业务编码搜索。`INPATIENT_DISCHARGE_RECORD` 在页面中对应“住院出院病案记录（INPATIENT_DISCHARGE_RECORD）”。

### 4.2 文档选择项与当前页面核对表

|文档操作项|当前接口是否存在|当前页面是否可选|核实说明|
|---|---|---|---|
|`INPATIENT_DISCHARGE_RECORD`|是，`PUBLISHED`|是|页面显示“住院出院病案记录（INPATIENT_DISCHARGE_RECORD）”；适合性别标准化统计|
|`YUNNAN_VMQ_VMQ_BASICINFORMATIONBA`|是，`PUBLISHED`|是|选择上述数据域后显示“vmq_basicinformationba（YUNNAN_VMQ_VMQ_BASICINFORMATIONBA）”|
|`SEX`|是|是|字段显示“患者性别（SEX）”，源值通过转换规则标准化为 `MALE/FEMALE/UNKNOWN`|
|`HOSPITAL_CODE/HOSPITAL_NAME`（出院病案域）|否|否|该域当前不具备这两个标准字段，不能直接完成完整组织下钻|
|`OUT_DEPT_CODE/OUT_DEPT_NAME`（出院病案域）|是|是|只能支持科室字段本身，不能替代缺失的医院路径字段|

|`DRILL_DEATH_DISCUSSION_TABLE_20260811171525`|是，`PUBLISHED`|是|默认时间字段为 `VISIT_DATE`，具备完整下钻字段|
|`COUNT(DEATH_DISCUSSION)`|字段存在|是|在“记录计数”下选择计数字段 `DEATH_DISCUSSION`；业务范围保持“全部记录”|

|组织 + 病种多路径同时选择|后端支持|当前不能新建配置|当前指标编辑页只提交一条路径；完整演示复用第3节指标|

如果仍看不到带编码的新标签，说明浏览器访问的仍是旧构建产物。需要重新构建/部署前端并强制刷新浏览器缓存；仅重启后端不会改变下拉框显示。

## 5. 创建分母因子：死亡讨论记录总数

操作路径：左侧菜单“因子管理” → “新增因子”。

### 5.1 基础信息

|字段|示例值|
|---|---|
|因子编码|`F_DEMO_DEATH_DISCUSSION_TOTAL_20260813`|
|因子名称|演示-死亡讨论记录总数|
|业务分类|医疗质量|
|说明|统计死亡病例讨论记录总数，按组织、病种和病例粒度输出，用作完整率分母。|

### 5.2 计算口径

1. 数据域搜索并选择 `DRILL_DEATH_DISCUSSION_20260811171525`。
2. 语义表搜索并选择 `DRILL_DEATH_DISCUSSION_TABLE_20260811171525`。
3. 统计方式选择“记录计数（COUNT）”。
4. “计数字段”选择 `RECORD_ID`，即生成 `COUNT(RECORD_ID)`。
5. 业务范围选择“全部记录”，不要添加筛选条件。
6. 分组维度按展示范围选择；为了复现第20章完整路径，选择以下字段：

建议粒度：

```text
HOSPITAL_CODE × HOSPITAL_NAME ×
OUT_DEPT_CODE × OUT_DEPT_NAME ×
ATTENDING_DOCTOR_CODE × ATTENDING_DOCTOR_NAME ×
SINGLE_DISEASE_CODE × DIRECT_DEATH × VISIT_ID × PATIENT_NAME
```

如果只需要下钻到科室，可至少选择 `HOSPITAL_CODE`、`HOSPITAL_NAME`、`OUT_DEPT_CODE`、`OUT_DEPT_NAME`。编码字段用于稳定关联，名称字段用于页面展示。

### 5.3 保存、编译、试算、发布

1. 点击“保存草稿并继续”。
2. 记录页面返回的因子 ID 和版本 ID。
3. 点击“编译并校验”，状态应为 `VALID` 或校验通过。
4. 试算周期选择一个源表确实有数据的月份，例如：

   ```text
   2026-04-01 00:00:00 ～ 2026-05-01 00:00:00
   ```

5. 点击“试算并查看结果”，确认结果包含已选组织和病种/病例维度，质量状态为 `PASSED`。
6. 点击“发布因子版本”。
7. 复制已发布的分母因子版本 ID，后续指标公式必须引用版本 ID，而不是因子 ID。

## 6. 创建分子因子：已填写死亡讨论记录数

再次进入“因子管理” → “新增因子”。

### 6.1 基础信息

|字段|示例值|
|---|---|
|因子编码|`F_DEMO_DEATH_DISCUSSION_DOCUMENTED_20260813`|
|因子名称|演示-已填写死亡讨论记录数|
|业务分类|医疗质量|
|说明|统计已填写死亡讨论内容的记录数，粒度与分母一致。|

### 6.2 计算口径

数据域、语义表、统计方式和分组维度必须与分母保持一致：

```text
数据域：DRILL_DEATH_DISCUSSION_20260811171525
语义表：DRILL_DEATH_DISCUSSION_TABLE_20260811171525
统计方式：COUNT
计数字段：DEATH_DISCUSSION
分组维度：与第 5.2 节分母完全一致
```

业务范围选择“全部记录”，不要点击“添加条件”。最终口径是：

```text
COUNT(DEATH_DISCUSSION)
```

SQL 的 `COUNT(字段)` 只统计非空字段，正好表达“已填写死亡讨论记录数”。真实已发布分子 `102027642458347882` 也是 `filters=TRUE + COUNT(DEATH_DISCUSSION)`，不是“非空筛选 + COUNT(*)”。

如果已经选择了“按条件筛选”并看到“条件尚未完成，请先选择字段、判断方式和值”，请执行：

1. 将业务范围切回“全部记录”；未完成的条件行不会进入 DSL。
2. 在“统计方式”区域确认“记录计数”。
3. 在新增的“计数字段”下拉框中选择 `death_discussion（DEATH_DISCUSSION）`。
4. “查看技术配置”确认：

   ```json
   {
     "filters": { "nodeType": "TRUE" },
     "aggregation": {
       "function": "COUNT",
       "fieldCode": "DEATH_DISCUSSION"
     }
   }
   ```

不要填写任意固定文本的“等于”条件来代替 `COUNT(DEATH_DISCUSSION)`，两者统计口径不等价。

### 6.3 因子粒度检查

创建可下钻指标时，分子和分母必须满足：

- 来自可对齐的数据范围与统计周期。
- 分组维度一致，或至少能被后端安全聚合到指标要求的下钻层级。
- 选择 `OUT_DEPT` 作为指标最大下钻层级时，两个因子都应具备 `HOSPITAL_CODE/HOSPITAL_NAME/OUT_DEPT_CODE/OUT_DEPT_NAME`。
- 因子版本均已发布。

如果指标版本创建或编译时提示下钻粒度不满足，先返回因子编辑页补齐分组维度，重新生成并发布新的因子版本，再在指标公式中选择新版本。

## 7. 创建指标并绑定组织下钻路径

操作路径：左侧菜单“指标管理” → “新增指标”。

### 7.1 “1 基础与版本”页签

填写示例：

|字段|示例值|
|---|---|
|指标编码|`I_DEMO_DEATH_DISCUSSION_COMPLETION_20260813`|
|指标名称|演示-死亡病例讨论完整率|
|指标简称|死亡讨论完整率|
|指标分类|医疗质量 / 质量安全|
|指标属性|定量|
|计量单位|百分比（%）|
|指标导向|监测比较|
|统计周期|月度|
|指标定义|已填写死亡讨论记录数占同期死亡讨论记录总数的比例。|

在“指标结果下钻路径”中选择：

```text
路径编码：组织下钻（ORGANIZATION）
最大层级：出院科室（OUT_DEPT）
```

点击“保存并进入公式配置”或“为当前指标创建草稿版本”。创建版本时前端会提交：

```json
{
  "drillPaths": [
    {
      "pathCode": "ORGANIZATION",
      "maxLevel": "OUT_DEPT"
    }
  ]
}
```

服务端会解析并固化当前已发布的路径版本。

### 7.2 “2 公式与试算”页签

1. 计算模式选择“比率型”或保持当前简单比率模式。
2. 在“可用因子”中搜索“演示-已填写死亡讨论记录数”；若未新增等价分子，则选择已发布因子“多路径-已填写死亡讨论记录数”。
3. 搜索“演示-死亡讨论记录总数”；若未新增，则选择已发布因子“多路径-死亡讨论记录总数”。
4. 确认公式预览为：

   ```text
   已填写死亡讨论记录数 ÷ 死亡讨论记录总数 × 100%
   ```

5. 点击“保存公式”。
6. 点击“公式校验”。
7. 点击“发起试算”。
8. 任务成功后点击“查看结果”，确认有展示值和批次 ID。

### 7.3 发布指标版本

可在“2 公式与试算”页签直接点击“发布指标版本”，也可进入“6 发布检查”页签检查发布门禁后发布。

记录以下值：

```text
指标 ID：<页面返回的 indicatorId>
已发布指标版本 ID：<页面返回的 publishedVersionId>
```

后续创建正式计算批次时使用“指标版本 ID”。指标分析页 URL 中使用“指标 ID”。

## 8. 生成正式结果

仅有试算结果不一定能支持稳定的历史分析和正式下钻。发布指标版本后，建议创建 `FULL` 正式批次。

操作路径：左侧菜单“计算运行” → “计算任务” → “创建计算批次”。

填写：

|字段|值|
|---|---|
|对象类型|指标版本（INDICATOR）|
|对象版本 ID|第 7.3 节记录的已发布指标版本 ID|
|批次类型|正式（FULL）|
|开始时间|`2026-04-01T00:00:00`|
|结束时间|`2026-05-01T00:00:00`|

点击“确认并创建批次”，记录返回的 `taskId` 和 `batchId`。随后在同一页面查询任务和批次，直到满足：

```text
status = SUCCEEDED
failedCount = 0
```

如果状态是 `QUEUED` 或 `RUNNING`，继续刷新；如果是 `FAILED`，展开错误信息检查因子粒度、路径字段、统计周期和源数据连接。

## 9. 查看新建指标的下钻效果

### 9.1 从指标分析页进入

1. 左侧菜单选择“指标分析”。
2. 顶部指标下拉框搜索新建指标名称或编码。
3. 切换到该指标。
4. 在“趋势分析”确认当前值、质量状态和结果批次。
5. 切换到“科室排名”，确认后端维度对比数据。
6. 切换到“下钻分析”。
7. 下钻维度选择“组织维度”。
8. 从医院记录点击“查看下一级”，进入出院科室。
9. 如果页面显示“查看因子追溯”，点击后核对分子、分母结果。

也可使用直达 URL：

```text
http://localhost:5173/analysis?indicator=<指标ID>&indicatorVersionId=<指标版本ID>
```

### 9.2 判断页面是否使用真实结果

下钻区域顶部应显示“真实接口”。同时检查：

- 页面有真实 `resultId`，而不是空值或 `MOCK-*`。
- 质量状态为后端状态，例如 `PASSED`。
- 每次点击下一级后，面包屑和“当前层”发生变化。
- 表格记录及 `nextLevels` 随当前层变化。
- 因子追溯中的版本 ID 与指标公式引用的已发布因子版本一致。

如果分析页显示“当前指标尚无可下钻的已激活结果”，说明指标本身已经可以进入通用分析页，但当前查询粒度下没有可用的正式 `resultId`。此时应先检查第 8 节的正式批次。

## 10. 当前前端能力边界

### 10.1 新建指标页面当前只提交一条路径

当前指标编辑页会提交一个 `drillPaths` 元素，界面仅直接提供：

- `ORGANIZATION`
- 最大层级 `HOSPITAL` 或 `OUT_DEPT`

后端接口实际还支持 `DISEASE`、`TIME`、`FACTOR_TRACE`、`SCENARIO` 等路径编码，但当前页面尚未提供已发布路径列表和多选能力。因此：

- 新建指标可通过页面稳定演示组织下钻和因子追溯。
- 需要组织 + 病种完整多路径时，优先使用第 3 节的真实已发布指标。
- 不要通过手改前端运行时数据伪造多路径配置；路径版本应由服务端校验并固化。

### 10.2 病例级结果受权限保护

当前页面根据后端 `nextLevels` 允许逐级进入 `CASE`，但页面只能展示后端授权后返回的受控字段。正式上线前仍需由后端实施数据范围、脱敏、访问目的和审计控制；前端不应自行绕过后端权限。

### 10.3 多路径结果需要正确锚点

同一个指标版本可以产生多个路径目标结果。组织路径和病种路径的锚点 `resultId` 不一定相同：

|路径|本例锚点 resultId|
|---|---|
|组织路径|`102027642458358187`|
|病种/病例路径|`102027642458358201`|

如果使用病种结果 ID 请求组织层，或使用组织结果 ID 请求病种层，后端可能返回路径不匹配或无数据。现场完整演示应使用本文给出的对应直达链接。

从指标分析页进入时，前端会依据分析接口 `dimensionComparison` 中的维度结构自动选择对应锚点：包含科室/主治医师维度的结果作为组织锚点，包含单病种/病例维度的结果作为病种锚点。切换下钻维度时会同时切换 `resultId`，不会复用另一条路径的快照。

### 10.4 周期参数以结果快照为准

下钻接口会严格校验结果周期。当前前端下钻请求发送空的业务筛选 `filters={}`，由 `resultId` 绑定的结果快照确定 `periodStart` 和 `periodEnd`；页面在成功响应后显示该快照周期。不要把用于展示的 `2026-04`、`2026-Q2` 等文本直接作为下钻 `filters.period` 发送，否则会触发“period 与结果计算周期不一致”。

## 11. 常见问题排查

### 11.1 指标下拉框能看到指标，但下钻页为空

依次检查：

1. 指标版本是否已发布。
2. 是否创建了 `FULL` 正式批次。
3. 批次是否为 `SUCCEEDED`。
4. 分析接口是否返回 `dataAvailable=true` 和 `overview.resultId`。
5. 当前选择的月度、季度或年度是否存在已激活结果。

### 11.2 创建指标版本时提示因子粒度不满足

检查分子和分母因子的 `groupBy`：选择 `OUT_DEPT` 下钻时，两个因子都需要可对齐的医院和出院科室维度。修改因子定义后必须重新编译、试算、发布，并在指标公式中改选新的因子版本。

### 11.3 下钻结果出现 `__UNASSIGNED__`

这表示参与汇总的源记录缺少相应维度编码。它是数据质量表现，不是接口失败。可通过语义字段映射、源值标准化或源系统补录改善，但不应直接删除该归桶，否则会造成汇总数与明细数不一致。

### 11.4 因子结果追溯加载失败

因子追溯不依赖下钻响应中的 `lineageAvailable`。当前页面始终提供“查看因子追溯”按钮和“因子结果追溯”下拉项，并直接调用 `/analysis/results/{resultId}/factors`。如果加载失败，检查：

- 当前 `resultId` 是否为指标结果，而不是因子结果。
- 指标公式是否引用了正式发布的因子版本。
- 正式批次是否保存了计算快照和因子结果关联。
- 当前结果是否已激活。

### 11.5 因子追溯显示“未匹配”

后端会按批次、快照、周期、目标和粒度匹配因子结果。常见原因是分子/分母粒度不一致、因子结果未激活、使用了不同批次，或公式发布后未重新计算正式批次。

### 11.6 页面显示 0.00%，是否表示失败

不是。应结合质量状态判断。第 20 章真实实例中，病例层分子为 0、分母为 1，计算结果自然为 `0.00%`，同时质量状态为 `PASSED`、因子结果均已匹配，属于正确结果。

## 13. 最短演示脚本

时间有限时，按以下顺序即可完成核心展示：

1. 打开真实指标分析页，切换月度、季度、年度。
2. 打开组织下钻直达链接，依次进入云南省第一人民医院、血管外科、未维护主治医师。
3. 打开病种下钻直达链接，展示全部病种和当前死亡诊断文本。
4. 点击“查看下一级”进入病例层，展示就诊号 `ZY0010100111395`。
5. 点击“查看因子追溯”，展示分子 0、分母 1、两条结果均已匹配。
6. 在计算任务中心查询批次 `102027642458358114`，展示 6/6 目标成功。

至此可证明：指标正式结果、组织路径、病种路径、病例定位、因子结果追溯和计算批次状态均已形成完整可展示链路。
