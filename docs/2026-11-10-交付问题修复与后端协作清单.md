## 已落实的前端修改

### 看板编辑错误隔离

`Dashboard.vue` 在草稿读取成功后进入编辑态。指标目录加载失败改为“草稿已打开”警告；组件预览失败不再冒充草稿读取失败，其他组件仍可继续加载。

`completeDashboardSourceBindings` 默认保留原有严格读取行为。仅编辑草稿明确传入 `onBindingError` 时，允许保留无法补全身份的组件，其他组件继续解析。组件原有版本、绑定和样式不被清空或替换；取消请求及 401/403 仍向上传播。该选项在 API 层剥离，不作为 HTTP 请求参数发送。

交付包中的同名报错存在于后端 `JdbcDrillPathResolver`，涉及 `meta_drill_path_level.payload_json` 的下钻字段解析。因此，本轮容错不代表已经修复后端字段缺失，也不能保证主草稿接口本身异常时仍可编辑。

### 批次查询

删除任务 ID、批次 ID 默认填入的 `101996817981379215`。默认空白，仅从真实响应或独立路由参数取得关联 ID。查询前拒绝空值、非整数、科学计数法和超出后端 Long 范围的值；不使用 Number 或 parseInt 转换 ID。真实 ID 不存在和无权限分别提示。

固定测试值是已证实的前端缺陷，不能作为甲方所有批次查询错误的唯一根因。真实请求仍报错时，需要失败请求 URL、HTTP 状态、响应体与 traceId，定位后端日志。

### 查询条件中文名称

统一优先使用有效的 `displayName`、`label`、`name`，其次使用已知参数中文映射，如 `deptCode` 显示“科室编码”。未知且无显示名称的参数保留原编码，避免猜测业务含义。名称等于编码时仍允许使用已知中文映射。

输入值绑定和查询 payload 仍使用原参数编码，科室查询仍提交 `parameters.deptCode`。SQL 导入展示链路保留名称元数据；提交定义时保持现有字段契约，避免向旧后端写入未经确认的字段。

### 模板展示和权限

模板管理资格使用会话中的 PATCH API 授权判断，不再固定为 true。普通使用者请求已发布模板，并仅保留具有当前已发布版本的条目；管理者可查询合法草稿和其他状态。新建操作仍使用独立的新建权限。

管理版本优先选择 DRAFT，其次当前已发布版本，再其次其他 PUBLISHED 版本，不把 ARCHIVED 版本当作草稿。该改动规范展示，不执行任何数据库脏数据清理。

## 后端协作要求

以下是待转交清单，接口路径为建议，需由后端确认契约后接入；不是已上线接口。

### 1 下钻字段配置

- 根据失败看板绑定的指标版本、计算快照和路径版本，定位异常层级。
- 检查 `dimensionFieldCode`、`memberKeyFieldCode`、`displayFieldCode`、允许列及实际字段的一致性，区分虚拟根层级和业务层级。
- 对历史数据给出明确迁移或兼容策略，不能凭名称随意补字段或改变历史快照口径。
- 在保存和发布路径时提前校验，错误信息返回路径、层级等定位线索。

### 2 政策解除关联

建议 `DELETE /api/v1/meta/policy-file-relations/{relationId}`。查询返回稳定的关系 ID；确认已发布版本可否解除关联、并发版本校验、删除权限、操作审计及重复请求语义。

前端联调时增加“解除关联”、二次确认、提交禁用和成功后重查。只删除关系记录，保留政策文件、版本和附件。

### 3 真实计算批次异常

现有 `GET /api/v1/calc/batches/{batchId}` 与交付包路由一致。真实批次查询失败时，按 404、403、500 分别排查记录/可见性、授权和详情查询异常。BIGINT ID 建议统一按字符串返回。

### 4 参数显示名称

编译产物 `parameterSchema.parameters` 应提供明确的中文显示名称，并在保存、编译、上游依赖继承时保留。需明确统一字段为 `displayName` 或其他约定字段；若参数编辑写接口也支持名称，应同步确认写入契约。

### 5 模板脏数据

先导出疑似记录的模板 ID、版本、名称、创建来源、状态和实例引用，形成确认清单。未被引用的测试数据可清理，被引用记录需评估停用、归档或迁移。检查初始化、测试脚本或历史导入是否反复生成测试记录。合法草稿不得作为脏数据自动删除。

### 6 数据源摘要

当前页面使用 `/meta/source-tables`，交付包 `SourceTableDto` 仅有 `tableName`、`tableType`、`comment`、`fieldCount`；其中 `tableType` 是表/视图对象类型，不是数据库类型。未发现可供该页使用的连接摘要契约。

建议提供只读摘要：数据源名称、用途、主机/IP、端口、数据库类型、库名。支持多数据源，从实际生效配置提取，单独校验查看权限。不返回密码、令牌及可能包含凭据的完整 JDBC URL。若配置使用域名，显示实际配置主机，不伪造为 IP。

### 7 移除数据域接入的物理表

建议接口：

```http
GET /api/v1/meta/data-domains/{domainId}/physical-tables/{tableName}/deletion-impact
DELETE /api/v1/meta/data-domains/{domainId}/physical-tables/{tableName}
```

删除对象是数据域接入绑定及可安全移除的专属映射，不执行 DROP TABLE，不删除源库数据，不破坏其他数据域的独立绑定。也可采用稳定绑定 ID 作为资源标识，由后端确定。

影响查询返回 `deletable` 和引用清单，包含对象类型、ID、名称、版本、阻止原因。检查因子及模板定义、字段/表关联、转换配置和仍依赖该配置的任务等真实依赖；有效草稿引用也需阻止删除。仅存在未被外部使用的专属字段映射，不应导致永远无法纠错，可由事务一并清理。

DELETE 内再次检查引用及资源版本，保证检查与删除的一致性；出现并发新增引用时拒绝删除并返回最新引用清单。建议冲突状态 409。落实删除权限、审计、逻辑删除及重新接入规则；同步来源结构不得复活已移除的数据域绑定。

前端联调：点击“移除”先检查影响；有引用显示清单并阻止提交；无引用确认后删除。成功重查列表和数量，清理被移除表的选择、字段映射与异步加载状态，允许重新接入。

## 审核和验收

1. 未带参数进入任务中心：任务 ID、批次 ID 均为空；空值和非法 ID 不发送查询。
2. 分别使用完整真实任务/批次 ID：请求 ID 无精度损失，关联 ID 正确回填；404/403 有对应提示。
3. 查看因子：`deptCode` 显示“科室编码”，后端提供中文名称时优先展示业务名称；查询仍使用原编码。
4. 看板草稿读取成功、单个绑定或预览失败：原组件和固定版本保留，其他组件继续加载，可调整配置；主草稿读取失败仍显示错误。
5. 普通模板使用者不展示不可用草稿；有管理权限者可管理合法草稿，不默认打开归档版本。
6. 后端完成第 2、6、7 项契约后另行联调，当前分支不把缺失接口的功能标记为已完成。
