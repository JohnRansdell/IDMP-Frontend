# IDMP 医疗质量指标数据管理平台前端

IDMP Frontend 是医疗质量指标数据管理平台的 Web 前端，用于数据资产配置、因子与指标生命周期管理、场景配置、计算任务跟踪、指标分析和结果下钻。

项目基于 Vue 3 和 Vite，当前集成版本提供连接真实后端的业务前端。核心流程已有页面、接口和部分真实环境验收记录；完整权限治理、部分业务场景及生产部署仍需逐项验收。

业务页面统一读取真实接口，接口失败时显示错误和重试入口，空结果按空状态展示。已取消指标、因子目录和指标详情的演示兜底，以及看板和下钻的演示入口；`dashboardDemo=1`、`VITE_DASHBOARD_PREVIEW_MODE` 不再启用模拟业务数据。后端保存的旧 `MOCK` 看板只提示重新配置，进入编辑时在本次编辑中清空演示组件，需添加真实指标组件后保存、发布。测试所需的历史演示数据保留在 `test/fixtures/frontend/`，不参与业务构建。

## 快速开始

要求：使用项目声明的 pnpm 版本，并准备兼容当前 Vite 版本的 Node.js 环境。

```powershell
pnpm install
pnpm dev
```

开发服务启动后访问：

```text
http://localhost:5173
```

常用命令：

```powershell
# 运行 Node 自动化测试
pnpm test

# 验证真实数据边界与页面状态（浏览器用例拦截 API，不写入真实后端）
pnpm run test:real-data
pnpm run test:e2e:real-data

# 生成生产构建
pnpm run build:prod

# 本地预览生产构建
pnpm preview
```

## API 配置

前端默认使用同源 API 前缀：

```text
/api/v1
```

如需覆盖，可在本地环境文件中配置 `VITE_API_BASE_URL`。仓库中只应保存不含真实地址的示例：

```dotenv
VITE_API_BASE_URL=/api/v1
```

推荐由网关或反向代理将 `/api/v1` 转发到后端服务。不要把内网 IP、正式域名、端口、账号、令牌或 Cookie 写入源码、README、提交记录和构建产物。

### 看板接口与存量配置

看板目录、定义、查询、编辑保存和发布使用现有服务端接口。目录为空时可以创建服务端看板；接口失败时重试当前请求。旧的预览环境变量和 URL 演示参数不再提供数据，浏览器中保留的演示 Schema 也不会恢复为业务看板。

科室全局筛选通过共享科室字典显示名称，查询与下钻继续使用稳定编码。前端依据已知字段契约及指标版本的组织路径，将筛选映射到各数据源的实际成员字段；候选来源不决定作用范围，组件的忽略或不继承设置继续生效。字典加载失败时显示错误及重试，字典中不存在的历史编码保留原编码，不推测名称。

`pnpm run test:dashboard-department` 验证字段映射与作用范围。真实环境验收脚本及其读写边界应以对应测试文件和受控验收说明为准，不在 README 中固定业务看板或环境对象。

## 当前能力

### 数据资产与标准化

- 来源元数据同步、源表与物理字段查询。
- 数据域、语义表和语义字段配置。
- 默认时间字段及字段业务角色维护。
- 值集、值集版本和值项生命周期管理。
- 语义字段值集绑定、源值画像及转换规则配置。

主要入口：

- `/data/sources`
- `/data/domains`
- `/data/value-sets`

### 因子与因子模板

- 因子目录、详情和版本查询。
- 因子 DSL 配置、编译、试算、结果读取和发布。
- 删除影响检查、软删除、回收站和恢复。
- 因子模板目录、版本、校验、发布和模板实例化。

主要入口：

- `/factor`
- `/factor/templates`
- `/factor/recycle-bin`

### 指标管理

- 指标目录、筛选、表格与卡片视图。
- 指标、指标版本及公式生命周期。
- 公式编译、试算、发布和正式计算入口。
- 下钻能力预检、路径和最大层级配置。
- 删除影响检查、软删除、回收站和恢复。
- 指标目录和详情中的已发布场景引用统计。

主要入口：

- `/indicator`
- `/indicator/edit/:id?`
- `/indicator/view/:id`
- `/indicator/recycle-bin`

### 场景管理

- 场景及场景版本管理。
- 关联已发布指标版本，保存草稿、校验与发布。
- 已发布版本只读、创建新草稿及版本冲突处理。

主要入口：

- `/scenarios`
- `/scenarios/:scenarioId/edit`

### 计算、分析与下钻

- 计算批次创建、异步任务查询和批次详情。
- 批次取消，以及失败、跳过和取消节点的恢复入口；具体可重试状态以服务端返回为准。
- 本地布局草稿与服务端看板的管理、查询、保存和发布。
- 月度、季度、年度及自定义月份区间看板查询；指标趋势、维度结果和正式结果入口。
- 指标分析 PDF 导出。
- 组织、病种等路径下钻以及因子结果追溯。

主要入口：

- `/calc`
- `/dashboard`
- `/analysis`
- `/analysis/drill`

### 认证与系统管理

- `/login` 提供工号、密码登录，`/system` 提供会话与用户角色管理。
- Bearer Access Token 请求认证。
- 现有会话模块支持当前用户读取、Refresh Cookie 与 CSRF Token 刷新，以及并发 401 后的单次刷新和原请求重试。
- 当前会话退出和全部会话退出。
- 用户列表及角色管理入口。

集成版本启用统一登录与路由授权，支持密码登录、会话恢复、平台单点登录和科室受限看板入口。菜单、路由和按钮依据后端返回的授权展示，数据范围仍由后端校验。医疗看板通过独立受限接口查询，不回退到管理接口。

主要入口：

- `/system`

### 预警中心

- 基于正式指标结果创建阈值、趋势和波动预警规则，支持嵌套条件与总体或分组结果范围。
- 规则经草稿、发布、启用后参与评估；查看事件详情、分组成员、统计周期和站内投递记录。
- 当前界面只提供站内通知，其他通知渠道及目标环境的权限、调度和端到端行为需分别验收。

主要入口：`/alerts`。

## 数据来源与页面状态

业务数据来自真实接口。加载中、空结果和失败状态分别展示，失败时提供重试；缺失字段显示未知或占位符，不补造业务记录、版本、周期或计算数值。顶部仅在看板页面保留真实看板选择器，通用页面不再展示没有筛选作用的固定全局场景。

历史固定数据移到 `test/fixtures/frontend/`，供图表、计算和适配器测试使用。正常枚举、布局配置、样式示意和测试夹具保留；旧演示页面已从源码删除。新增页面回归命令为 `pnpm run test:e2e:real-data`，验证 API 失败、重试、空结果、真实结果和旧配置处理；依赖历史演示入口的旧浏览器脚本不再适用于当前业务入口。

正式验收仍需针对实际部署的后端验证；测试中注入的接口响应不代表真实后端已经通过验收。

### 看板环形图下钻

看板中有同源组织下钻上下文的饼图支持原地展开和面包屑返回，路径遵循结果快照配置，最多到医师；没有上下文的构成图不补造入口。图表与数据表共用当前层数据，绘图度量遵循组件绑定；分子值和指标值保持各自业务含义。刷新、筛选或编辑切换会重置临时下钻状态。

下钻使用在线详细设计的 `POST /api/v1/analysis/results/{resultId}/drill/search`，携带同源快照，区别于离线 DOCX 中的 GET 示例。每页不超过 200 条，整层最多收集 500 条；超限、缺失分子、重复组织或不完整分页仅显示带原因的分页表格。上下文冲突及接口错误不回退为演示成功。

真实联调需要看板提供同源 `drillTarget`，下钻响应提供根结果、快照、指标版本、当前层、父组织上下文、分子和可靠分页信息。只有 `value` 的排名不能替代分子；缺失这些字段属于后端依赖。旧 `source=mock` 下钻链接已停用，需要从真实计算结果重新进入。

- 内网或公网真实 IP、域名、端口和服务拓扑。

## 当前边界

- 公式编辑器已支持嵌套结构、函数与统计量；具体公式仍须通过服务端校验、编译和真实结果核对。
- 场景批量计算、场景结果和跨场景对比尚未形成完整闭环。
- 数据采集、完整清洗转换和独立数据质量模块尚未完整交付。
- 浏览器本地布局与服务端看板并存；本地草稿不会自动成为已发布服务端看板。
- 指标分析支持 PDF 导出，预警支持站内通知；其他导出格式和外部通知渠道需按各自接口验收。
- 统一登录、菜单、路由和按钮授权已接入；目标环境的字段及数据范围权限仍需专项验收。
- 患者或记录级下钻仍需完善访问目的、脱敏、数据范围和审计控制。
- 仓库包含单元、组件、浏览器及真实环境验收脚本；已有验收记录不能替代目标部署的回归、性能、安全和权限验证。

## 构建与部署原则

1. 在受控 CI 或构建环境执行测试和生产构建。
2. 将完整 `dist` 作为同一版本制品发布，不要混用不同构建生成的哈希资源。
3. 使用环境配置或网关提供后端地址，不在前端制品中固化真实服务地址。
4. 部署前核对前端提交、后端版本、数据库迁移和配置清单。
5. 正式环境确认真实接口及空数据、错误、重试状态，并完成权限、安全和审计验收。

### 静态站点部署

`pnpm build:prod` 后必须将**同一次构建生成的整个 `dist` 目录**上传到 Web 根目录，不能只替换 `index.html` 或单个 `assets/*.js` 文件。构建文件名含内容哈希，混用新旧文件会使入口脚本返回 404，表现为浏览器白屏。

若站点部署在子路径，构建前设置相应的公开路径；以下值均为占位符：

```env
VITE_PUBLIC_BASE=/<public-path>/
VITE_API_BASE_URL=/api/v1
```

Nginx 需将前端路由回退到同一构建目录的 `index.html`，并代理后端接口。下列 `<...>` 必须替换为受控部署配置；站点部署在根路径时，应相应调整 `location` 和构建基路径：

```nginx
location /<public-path>/ {
  alias <frontend-root>/;
  try_files $uri $uri/ /<public-path>/index.html;
}

location /api/v1/ {
  proxy_pass <backend-upstream>/api/v1/;
}
```
