# IDMP 完整功能汇总与展示操作手册

整理日期：2026 年 10 月 14 日
最新复核：2026 年 10 月 18 日
适用项目：`IDMP-Frontend/IDMP-Frontend` 当前工作区
使用对象：项目汇报人员、业务操作人员、联调与验收人员

完整展示建议采用“一条贯穿全程的业务案例，加上各模块的补充案例”。主线使用“男性出院病案占比”，依次完成数据接入、标准化、因子建模、指标发布、场景配置、正式计算、分析下钻、政策引用和看板发布；补充展示连续值集、模板实例化、多表关联、SQL 导入、指标映射审核、预警处置、回收恢复和系统管理。

本手册按最新工作区的菜单、页面、事件处理和接口调用复核，包含尚未提交的页面调整。服务器须部署匹配版本的前后端；文中“预期结果”是现场核对标准，不代表本次已经在服务器执行通过。来源数据、账号、对象 ID 和实际计算值均以现场环境为准。服务器联调演示使用正式接口数据，页面显示“演示数据”的看板另作设计效果展示。

### 1.2 需要单独说明的页面边界

|项目|当前展示口径|
|---|---|

|指标编辑页的规则与排除及场景关联|页面提示这些配置暂不随公式一起持久化；正式场景绑定和覆盖在“场景管理”完成，不以编辑页填写作为保存成功|

|系统认证|`/login` 当前重定向到指标总览；需认证时使用“系统管理”的登录表单；顶部管理员名称不能用于确认当前真实身份|

|独立查询周期|报告期即时查询、趋势范围、科室排名周期、下钻周期、场景对比范围分别操作；切换一个控件后，逐区核对当前周期|

|看板独立周期|“固定周期”与看板取交集；“独立周期”可在看板范围之外，仅影响当前组件|
|未出现在菜单中的页面|旧 `SceneManagement`、`DataAssetManagement`、独立 `DashboardManagement` 等文件不作为当前独立菜单展示；Grid PoC 仅为开发入口|

### 1.3 推荐展示顺序

时间为建议安排，异步计算等待时间另留缓冲。

|环节|建议时长|展示方式|
|---|---|---|
|成品总览|5～10 分钟|先打开已准备的真实服务端看板和分析结果|
|主线建设|100～150 分钟|按第 2～14 章，以同一批新对象完成全过程|
|建模扩展|35～50 分钟|按第 15～16 章展示连续范围、模板、多表关联、SQL 导入|
|治理与运行|30～45 分钟|按第 17～20 章展示审核、预警、恢复、系统管理|
|收尾核对|5～10 分钟|按第 21 章检查交付结果|

若汇报只有 60～90 分钟，提前完成数据治理、政策文件、补充案例和连续月份正式计算，现场重点展示“一次因子编译试算、一次指标发布、一次正式计算、分析下钻、看板发布”，其余模块打开已准备对象按对应章节查看。需证明从零建设时，使用上表完整时段和新对象。

|2|若业务接口需要登录，在“用户名”“密码”填写管理员提供的账号，点击“登录并建立会话”。|显示会话反馈；后续业务请求可访问。|

|5|核对性别源值含义、记录唯一性和出院日期格式，准备一个有数据的完整自然月。|确定性别标准化映射；确定记录行数能否称为病案人次；取得可用周期。|
|6|若展示趋势，准备至少三个连续有数据月份；若展示多表关联，再准备关联表和已核实的关联键。|趋势有多个真实点；关联关系有明确字段和对应关系。|

## 3 新建政策文件并上传版本

入口：平台管理 → 政策文件。

准备 TXT 文件，内容可使用项目已有的 `docs/演示用男性出院病案占比口径说明.txt`。如另建附件，写入“统计期内男性出院病案人次除以全部出院病案人次，以百分比展示；按出院时间统计；仅供技术演示，非正式医疗政策”。

|步骤|操作|预期结果|
|---|---|---|
|1|点击“新建政策文件”。|打开基本资料弹窗。|
|2|编码、名称填第 2.2 节政策文件值；类别选择“其他”；说明填写“仅供技术演示，非正式医疗政策”；点击“保存”。|目录新增政策文件。|
|3|点击该文件“查看”，再点击“上传新版本”。|打开版本文件表单。|
|4|点击“选择文件”，选择演示 TXT；发布日期填本次演示日期，例如 `2026-10-18`；无对应日期时生效、失效日期留空。等待文件状态就绪，点击“保存草稿”。|完成上传和版本创建后，版本列表出现草稿；文件信息回显。|
|5|点击该版本“查看文件”。|查看器显示可读取的原文。|
|6|关闭查看器，点击版本“发布”，完成弹窗确认。|版本显示已发布；记录政策文件版本 ID。|
|7|刷新目录，按名称查询后再次查看。|资料、版本和附件可回读。|

### 3.1 编辑基本资料与关联政策版本

|步骤|操作|预期结果|
|---|---|---|
|1|政策文件列表点击本次文件“编辑”，发布机构填“演示资料编制组”，说明保留“仅供技术演示”，点击“保存”。|基本资料更新；编码不可改。|
|2|需要展示文件关系时，另建政策文件 `P_REF_SHOW_20261014_01`，名称“演示补充口径说明”，上传注明“仅供技术演示”的附件并发布。|取得第二个可选的已发布政策版本。|
|3|打开主政策文件“查看”，在“政策文件关系”选择本文件已发布版本。|加载该版本关系和新增关系表单。|
|4|在目标政策选择器选择第二个已发布版本，关系选“引用”，关系说明填“引用本次补充演示资料”，点击“关联”。|关系表显示源版本、目标版本、引用类型及说明。|
|5|重新打开文件并选同一版本。|关系可回读。|

“替代、补充、修订”只在两文件确有对应关系时选择。附件大小和扩展名按上传区实时提示执行；上传失败点“重试”或“更换文件”，发布后如需改文件或日期则“上传新版本”。

### 4.3 核对并保存字段映射

每行先核对“业务字段”列。未映射行点击“映射”，已映射行点击“编辑”。保留已有自动编码，填写下表名称、类型和角色，点击“保存映射”。

|源字段|业务字段名称|本例数据类型|业务角色|敏感标记|
|---|---|---|---|---|
|`VISIT_ID`|就诊记录标识|文本|标识|勾选；正式分类按现场规则|
|`sex`|患者性别|文本，与后续字符串值集匹配|维度|按现场规则，本例不勾选|
|`out_date`|出院时间|若源类型为 `varchar`，保留已验证的文本映射|时间|按现场规则，本例不勾选|
|`out_dept_code`|出院科室编码|文本|维度|本例不勾选|
|`out_dept_name`|出院科室名称|文本|维度|本例不勾选|

|步骤|操作|预期结果|
|---|---|---|
|1|逐行按上表核对或保存映射。|业务字段、配置类型、角色回显正确。|
|2|记录五行实际业务字段编码，填入第 2.3 节记录表。|后续筛选和映射有对应编码。|
|3|在 `sex` 行点击“画像”。|显示真实源值、记录数和占比。|
|4|核对性别编码含义并记录，关闭画像。|得到本次源值到标准性别的对应关系。|
|5|点击工作台“刷新”，重新选择物理表。|字段配置重新读取且保持一致。|

本例 `out_date` 作为文本日期使用时，因子页必须能读到后端返回的“文本日期（抽样识别）”候选。若源值需要转换为日期时间，使用字段编辑弹窗提供的“源数据日期格式”配置并完成现场校验；不把 `create_date` 改称出院日期。

## 5 性别值集与源值标准化

### 5.1 创建精确枚举值集

入口：数据治理 → 值集管理。

|步骤|操作|预期结果|

|1|点击“新建值集”，选择“精确枚举”。|出现枚举值集表单。|
|2|编码、名称填第 2.2 节性别值集值；值类型选文本或字符串 `STRING`；说明填“男性、女性、未知”；提交创建。|生成值集和初始草稿版本，进入版本编辑。|
|3|点击“新增值项”，按下表创建三个值项。|表格显示三行可编辑值项。|
|4|点击“保存值项”。|三条值项保存成功。|
|5|点击“校验版本”。|返回校验通过，或显示需要修正的诊断。|
|6|校验通过后点击“发布版本”。|版本为已发布；记录版本 ID。|

|值项编码|标签|标准值|

|`MALE`|男性|`MALE`|
|`FEMALE`|女性|`FEMALE`|
|`UNKNOWN`|未知|`UNKNOWN`|

### 5.2 绑定并发布转换规则

## 6 由管理员校验并发布数据域

当前页面没有数据域校验、发布按钮。本节在管理员接口客户端完成，业务操作人员按返回结果核对。默认接口前缀为 `/api/v1`；使用当前环境认证信息，下面 ID 均替换为本次实际 ID。

|步骤|操作|预期结果|
|---|---|---|
|1|发送 `GET /api/v1/meta/data-domains/{domainId}`。|取得数据域详情、最新 `resourceVersion`、主键和默认时间配置。|
|2|发送 `POST /api/v1/meta/data-domains/{domainId}/validate`。|返回 `data.valid` 与 `diagnostics`。|
|3|若要求配置主键或默认时间，按实际语义字段 ID 发送下方 PATCH；完成后重新读取和校验。|诊断项修正；`data.valid=true`。|
|4|使用最新 `resourceVersion` 发送发布请求。|发布成功，数据域状态变为 `PUBLISHED`。|
|5|返回“数据域管理”刷新，进入因子新建页检查数据域候选。|本次数据域可搜索选择，物理表可读取。|

仅在校验要求且字段已核实时，使用：

```http
PATCH /api/v1/meta/data-domains/{domainId}
Content-Type: application/json
```

```json
{
  "resourceVersion": 0,
  "primaryKeySemanticFieldId": "本次VISIT_ID映射的语义字段ID",
  "defaultTimeSemanticFieldId": "本次出院时间映射的语义字段ID"
}
```

发布请求：

```http
POST /api/v1/meta/data-domains/{domainId}/publish
Content-Type: application/json
```

```json
{"resourceVersion": 0}
```

上述 `0` 仅为格式示例，须替换为最新读取的版本号。ID 填字段 ID，不填 `VISIT_ID` 或业务字段编码。返回 409 时重新读取最新详情后处理。若物理表绑定仍不是因子页可选的已发布状态，由管理员按该部署的物理表生命周期接口处理后再继续。

### 16.3 时序 SQL 多表组合展示

本例需要 `vmq_basicinformationzy` 和 `vmq_inpatienttransferdetail` 两张已接入来源表。先查看字段：住院表应有 `In_Hospital_ID`、`In_Date`、`name`、`out_dept_code`、`out_dept_name`、`in_icd10`；转科表应有 `In_Hospital_ID`、`In_Dept_Date`。另记录 `In_Date` 有数据的整月 `J_START`、`J_END`，不直接沿用病案表的出院月份。

使用新会话粘贴：

```sql
WITH total_admissions AS (
  SELECT COUNT(DISTINCT b.In_Hospital_ID) AS total_cnt
  FROM vmq_basicinformationzy b
  WHERE 1 = 1
    [[AND b.In_Date >= {{startDate}}]]
    [[AND b.In_Date < {{endDate}}]]
    [[AND b.name LIKE CONCAT('%', {{patientName}}, '%')]]
), transfer_48h AS (
  SELECT COUNT(DISTINCT b.In_Hospital_ID) AS transfer_cnt
  FROM vmq_basicinformationzy b
  JOIN vmq_inpatienttransferdetail t
    ON b.In_Hospital_ID = t.In_Hospital_ID
  WHERE t.In_Dept_Date >= b.In_Date
    AND TIMESTAMPDIFF(HOUR, b.In_Date, t.In_Dept_Date) <= 48
    [[AND b.In_Date >= {{startDate}}]]
    [[AND b.In_Date < {{endDate}}]]
    [[AND b.name LIKE CONCAT('%', {{patientName}}, '%')]]
)
SELECT transfer_48h.transfer_cnt / total_admissions.total_cnt AS result_value
FROM total_admissions CROSS JOIN transfer_48h;
```

|---|---|---|
|1|点击“解析 SQL”，逐表确认真实映射；在“解析结果预览”查看因子及指标公式。|出现 total_admissions 和 transfer_48h，指标公式为后者除以前者，不能是空对象。|
|2|创建范围选“创建因子及指标”，分类 `QUALITY`。两因子编码分别填 `F_SQL_TOTAL_SHOW_20261014_01`、`F_SQL_TRANSFER_SHOW_20261014_01`，名称分别填“入院住院号总数”“入院48整小时内转科住院号数”，缺行策略均选“按零处理”。|两因子信息齐全且编码不同。|
