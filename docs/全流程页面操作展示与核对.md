## 1. 文档用途与本次结论

本文既是演示人员可以照着逐项点击的操作脚本，也是当前前端与第 22、23 章接口能力的核对记录。演示应当证明：

1. 管理员不需要猜测物理值 `1`、`2`、`9` 的业务含义。
2. 值集统一表达为“男、女、未知”，因子只保存标准值项编码 `MALE`，不直接依赖某一来源系统的 `1`。
3. 每个物理字段映射各自维护源值转换规则；以后接入另一个来源字段 `1/2/0` 时，只需把 `0` 映射到同一个 `UNKNOWN`。
4. 因子筛选同时包含统计周期和枚举值集条件，指标公式引用已发布的分子、分母因子版本。
5. 指标版本创建前，前端使用当前 Formula AST 调用下钻能力预检，根据所有引用因子的共同能力选择路径和最大层级，不再由页面根据 `groupBy` 猜测能力。
6. 指标发布后，必须等正式结果回补成功，才能把分析页和下钻页作为验收结果。

当前前端已能呈现上述核心闭环，并已接入 `POST /api/v1/indicator-versions/drill-capabilities`。连续数值字段的 `GT/GTE/LT/LTE/BETWEEN` 固定值过滤仍未开放；本样例只验证日期周期和枚举值集过滤。

本文将核实证据分为三类，演示记录中不得混用：

- **源码/构建已核实**：页面入口、按钮文案、请求结构、禁用条件和结果渲染逻辑已经从当前源码及构建结果确认。
- **接口文档历史实测**：第 22、23 章记录的 ID、数量、比例和能力上限是真实环境历史结果，只能作为回归对照。
- **本次环境真实结果**：必须以本次浏览器网络响应、任务终态和正式结果为准，并填写第 17 节记录表。只有这一类证据可以判定本次部署通过。

## 2. 演示方式与样例数据

### 2.1 验收路线（包含指标下钻能力预检）

`POST /api/v1/meta/data-domains/{domainId}/semantic-tables/{tableCode}/semantic-fields` 现已支持 `semanticKind`，字段列表接口也会返回该属性。前端字段映射区已增加“业务角色”，因此可以从页面把性别字段明确保存为 `DIMENSION`，再继续绑定值集和维护源值标准化规则。`CODE/STRING` 仍只是数据类型，不等于业务角色，两个选项必须分别填写。

指标阶段不再在基础信息页手工选择固定路径。选择分子、分母后，页面使用完全相同的 Formula AST 进行预检；预检返回 `supported/maxLevel/levels/limitingFactors` 后，操作人再决定本指标版本实际启用哪些路径。预检能力上限只说明“最多可到哪里”，不代表该路径已经启用。

本次采用两种核对方式：

- **从零可写路线**：使用一组未占用的运行标识新建数据域、语义表、字段、值集、规则、因子和指标。这条路线验证页面写入能力。
- **既有对象续跑路线**：当前环境已经存在编码后缀为 `20260813_01` 的演示对象，不要重复创建同编码对象。进入已有数据域，把原先 `semanticKind=null` 的 `PATIENT_SEX` 补录为 `DIMENSION`，绑定已经发布的演示值集，然后继续规则、因子和指标流程。

若需要验证正式回补、分析和多路径下钻，可在新指标回补完成后验证；回补或下钻配置尚未完成时，可使用第 23 章已发布“男性出院率”对象进行只读对照，但不能用只读结果代替本次新建对象的写入验收。

> 编码说明：本文保留 `DEMO_..._20260813_01` 作为当前环境续跑样例。重新从零执行时，请把所有编码末尾统一替换为新的运行标识，例如 `20260814_01`，避免全局唯一编码冲突。

### 5.5 下钻字段说明

若要演示医院 → 出院科室 → 主治医师以及病种 → 病例下钻，仍需按源表实际字段补齐业务键、组织、医生和病种语义字段。当前工作台没有独立的“下钻路径设计器”；指标版本页面通过服务端预检结果提供标准路径和可选层级。

判断因子能否下钻时不要只看因子 DSL 的 `groupBy/output.grain`。服务端会综合数据域、语义字段、已发布路径版本以及公式引用的所有因子，计算共同上限。第 23 章实测两个因子的组织路径共同上限为 `OUT_DEPT`；由于缺少主治医师语义字段，页面不得提供 `ATTENDING_DOCTOR` 作为可选层级。

### 14.4 下钻分析

1. 点击“下钻分析”。
2. 在“下钻维度”中只选择当前可用项：组织维度、病种维度或因子结果追溯。当前页面的“时间维度（待接入）”“场景维度（待接入）”处于禁用状态，即使版本创建预检支持这两条路径，也不能写成前端交互下钻通过。
3. 第 23 章对象选择“组织维度”，页面必须使用带 `hospital_code` 且不含科室键的全院根结果作为下钻锚点；不能使用科室排名行的结果 ID。四月全院汇总应显示 `41.92% / PASSED`。
4. 从“当前层：医院”进入结果项的“查看下一级”，核对进入“当前层：科室”并展示 24 条真实科室结果。
5. 到达版本配置的 `OUT_DEPT` 最大层级后，所有行按钮必须显示“已到末级”。正常情况下接口顶层 `nextLevels` 应为空；若后端错误返回 `ATTENDING_DOCTOR`，前端也必须按指标版本 `maxLevel=OUT_DEPT` 截断，不得继续请求主治医师层。
6. 只有版本实际启用了病种路径且分析响应提供对应路径结果 ID 时，才验证病种、病例层级；路径只是预检支持但未启用时不能验收。
7. 页面当前对医生或病例层只展示后端返回的受控结果和访问提示，并没有填写访问原因的输入框，因此本次不能把“填写访问原因并完成审计”写成前端已通过能力。
8. 点击“查看因子追溯”或在维度下拉中选择“因子结果追溯”，核对：
   - 分子指向“男性出院病案人次”正式因子结果。
   - 分母指向“全部出院病案人次”正式因子结果。
   - 两个引用的版本 ID 与指标公式保存时一致。

如果页面显示“当前指标尚无可下钻的已激活结果”，先回到第 13 节确认回补；这不是前端渲染错误。

## 16. 页面操作核对矩阵

以下核对基于当前源码的路由、模板事件、API 模块和构建结果。状态含义：通过＝页面已有真实入口和请求；条件通过＝依赖后端数据或仍有已知边界；未完成＝当前页面没有对应操作。

本轮对语义角色写入、值集版本引用、周期参数结构、指标试算周期、指标下钻能力预检、多路径版本请求、全院根结果选择以及版本最大层级截断完成源码与自动化核对。自动化测试 27/27 通过，生产构建通过。部署到服务器后仍需按本文件第 5 至 14 节进行一次真实页面写入验收；构建通过和第 23 章历史实测均不能代替本次环境的真实响应。

## 18. 最终验收判定

满足以下条件才能判定“完整链路通过”：

- `PATIENT_SEX` 保存并回读为 `semanticKind=DIMENSION`，`OUT_TIME` 已设置为语义表默认时间字段。
- 值集已发布且成功绑定 `PATIENT_SEX`。
- 所有性别源值均有转换规则，预览未匹配数为 0。
- 分子 DSL 含 `OUT_TIME BETWEEN period`、`PERIOD/RUNTIME` 参数，以及带已发布 `valueSetVersionId` 的 `PATIENT_SEX IN_VALUE_SET [MALE]`。
- 分母 DSL 仅含相同的时间条件，不含性别过滤。
- 两个因子均编译、试算并发布成功，且 `0 < 分子 ≤ 分母`。
- 指标公式引用的正是本次两个发布因子版本。
- 下钻能力预检覆盖的因子版本与公式引用完全一致；实际启用路径均为 `supported=true`，层级未超过 `maxLevel`。
- 指标版本创建响应中的固化路径与页面选择一致，并返回服务端解析的 `pathVersionId`。
- 指标试算为合理百分比并发布成功。
- 正式回补批次成功，分析页显示后端正式结果而非演示数据。
- 下钻验收以版本实际启用路径为准：第 23 章组织路径应从医院进入出院科室，并在科室层显示“已到末级”；未启用路径不能写成通过。
- TIME、SCENARIO 虽可出现在预检和版本配置中，但当前前端下钻页仍未接入交互入口，必须记录为“版本配置通过、前端交互未验证”。

若数据治理、值集、因子和指标试算发布均通过，但回补或下钻尚未完成，应记录为“计算链路通过，正式结果/下钻待验证”，不能写成“全流程通过”。
