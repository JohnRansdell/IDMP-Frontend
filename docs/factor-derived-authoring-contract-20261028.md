## 数据域结论

当前后端复合因子编译分支要求 `schemaVersion`、`dslType=FACTOR`、`primaryDomain` 对象、`expression` 对象和 `output` 对象。

- `DerivedFactorCompiler` 对 `primaryDomain` 检查的是对象存在，没有要求非空 `domainCode`。
- `FactorDefinitionCompiler` 在原子源表解析前分派 `DERIVED`，不会把复合表达式当源表因子解析。
- 创建入口的规范化检查没有增加域编码必填条件；存储中的域字段来自可空的 JSON 提取。
- 对正在运行的 bootstrap 包内嵌 application 包进行了内存检查：`DerivedFactorCompiler.class` 长度为 19161 字节，存在 `primaryDomain` 常量，不含 `domainCode` 常量；该结果仅作为运行包与所核对分支的交叉证据，不替代完整契约分析。
- 因此，新建复合因子可保留 `primaryDomain: {}`；无需创建域、修改上游因子或填写虚构的域编码。已有显式域配置会保留，高级设置允许选填归类。

后端仍校验引用已发布且具有有效编译产物的因子版本、分组对齐、表达式结构和冻结依赖。省略域编码不意味着可以跳过这些约束。

## 输出设置

前端不再给所有复合因子默认填写 `COUNT` 量纲和单位。新建时读取所选版本与其编译产物，匹配结果分组和计算模式；直接引用、相加、相减等可确认的输出属性才沿用声明值。已知属性冲突会提示处理，未声明属性保持未声明，不猜测金额单位。

普通流程为选择计算方式、选择已发布因子、核对预览和结果设置、保存、编译、同周期试算并核对数值、发布。分组、量纲、单位和归类放在默认收起的高级设置中。用户显式调整的高级项和加载已有定义时的原始设置会保留。

技术 JSON 位于页面底部独立的“技术信息（仅供排查）”折叠区，默认收起、不参与步骤编号，展开后直接只读显示，长内容在区域内滚动。普通创建不需要打开；已发布因子可以查看，但仍不能编辑或保存已发布定义。编译失败时可从诊断提示直接定位并展开。
