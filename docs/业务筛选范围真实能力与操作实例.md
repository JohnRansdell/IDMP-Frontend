## 1. 核实结论

当前后端的因子筛选能力不是完整的通用业务条件编辑器。

- 当前实现接口文档 revision 1036 明确说明：已实现的是周期 `BETWEEN` 条件。
- 后端真实已发布因子版本 `101996817981389861` 使用该能力，DSL 为 `DEATH_TIME BETWEEN period`。
- 架构设计中的 `EQ`、`GT`、`LT`、`IN`、`IN_VALUE_SET`、`AND`、`OR`、`NOT` 属于目标设计，当前接口文档没有声明已经实现，不能作为可验收功能开放。
- 第 20 章死亡病例讨论完整率的真实分子使用 `COUNT(DEATH_DISCUSSION)` 表达“已填写死亡讨论记录数”，不需要再添加“非空”业务筛选。

因此，前端现在只展示后端已确认可用的“显式周期条件”，不再展示尚未落地的业务值筛选操作符。

## 2. 可用实例：住院死亡记录按试算周期统计

### 2.1 真实后端对象

- 因子版本：`101996817981389861`
- 数据域：`MORTALITY_V2_DEATH_20260727_1403`
- 语义表：`MORTALITY_V2_DEATH_TABLE_20260727_1403`
- 日期字段：`DEATH_TIME`
- 状态：`PUBLISHED`

### 2.2 前端操作

1. 进入“因子管理”，创建因子。
2. 选择包含可筛选日期字段、并配置了默认时间语义字段的数据域和语义表。
3. 统计方式选择“记录计数”。
4. 在“筛选范围”选择“显式周期条件”。
5. 点击“添加日期条件”。
6. 字段选择死亡时间 `DEATH_TIME`。
7. 判断方式自动设为“在试算统计周期内”。
8. 条件值显示“由下方‘本次试算周期’自动传入”，无需输入固定日期。
9. 保存后点击“查看技术配置”，确认筛选 DSL 如下。

```json
{
  "filters": {
    "nodeType": "AND",
    "children": [
      {
        "nodeType": "PREDICATE",
        "fieldCode": "DEATH_TIME",
        "operator": "BETWEEN",
        "parameter": "period"
      }
    ]
  },
  "parameters": [
    { "code": "period", "type": "DATETIME_RANGE" }
  ]
}
```

10. 保存、编译后，在“本次试算周期”选择起止时间并执行试算。后端用该起止时间替换运行时参数 `period`。

## 3. 原提示一直不消失的原因与修正

原实现同时使用 `v-model` 和更新事件，口径预览可能读取更新前的条件对象；所有错误又都被合并成“请选择字段、判断方式和值”，无法判断缺少哪一步。

现已改为先显式写回字段、操作符或值，再刷新预览。提示也改为逐项显示：

- `请选择筛选字段`
- `请选择该字段的判断方式`
- `请填写或选择条件值`

对于 `BETWEEN + parameter=period`，条件值来自试算请求，选择日期字段后条件已经完整，不再错误要求填写固定值。

## 4. 第 20 章实例应该怎么选

“已填写死亡讨论记录数”不要选择业务筛选范围，应使用：

- 筛选范围：全部记录
- 统计方式：记录计数
- 计数字段：死亡讨论记录 `DEATH_DISCUSSION`

生成 `COUNT(DEATH_DISCUSSION)`。SQL 的 `COUNT(字段)`只统计非空值，正好满足该口径。如果语义表已配置默认时间字段，试算周期仍由平台自动应用，无需重复添加日期条件。

## 5. 当前尚不可用的业务筛选

- 性别等于男性：`SEX EQ MALE`
- 住院天数大于 0：`INPATIENT_DAYS GT 0`
- 诊断编码属于值集：`DIAGNOSIS_CODE IN_VALUE_SET diseaseSet`
- 多条件 AND/OR/NOT 组合

后端若完成这些操作符，应同步提供操作符能力元数据或版本化 DSL 契约、值集版本参数选择接口，以及编译和试算样例；前端再根据服务端能力动态开放。
