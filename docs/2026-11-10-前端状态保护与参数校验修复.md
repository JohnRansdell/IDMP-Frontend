## 关键行为

任务中心“刷新当前状态”先读取当前批次，再按返回的关联任务查询状态；仅有任务 ID 时反向跟随其批次。第一步失败或已被新查询替代时，不继续读取旧关联对象。关联 ID 缺失或改变时，清理对应的旧详情和错误。同批次刷新保留已有数据及依赖图展开状态；切换批次才清理旧详情。

参数名称冲突采用稳定顺序：当前因子优先，其次按依赖遍历顺序使用首个有效名称。`displayName`、`label`、`name` 中与参数编码相同的占位值不视为业务名称。SQL 多因子参数合并也遵循首个有效名称优先。名称变更不改变请求键、类型冲突检查、必填合并或运行模式规则。

参数类型校验在发送前执行：整数不得为小数或超出 JavaScript 安全整数范围，小数必须为有限数值，布尔仅接受现有序列化支持的 true/false，日期需为实际存在的日期，日期时间还需检查时分秒。文本参数应为字符串。合法的 `0` 和 `false` 不视为未填写，查询仍按原参数编码发送。

## 验收步骤

1. 无法序列化的看板组件配置进入编辑失败时，应显示错误，原组件和原配置保持完整，不能出现空白可保存草稿。
2. 连续查询不同批次 A、B，让 A 晚于 B 返回，页面详情、关联任务 ID、错误提示及加载状态应始终属于 B。任务查询同样处理。
3. 查询中离开页面，迟到响应不再更新该页面状态或弹出提示；同一批次刷新仍保留依赖图展开状态。
4. 查看因子未填科室条件，应提示“科室编码”或后端提供的业务名称；非法数值和日期应在前端被拦截；合法零值、false 可提交。
5. 当前因子的“出院科室”与上游无名称的 `deptCode` 合并后，仍展示“出院科室”。若当前无名称，上游为“入院科室”，则补充该名称。
6. 连续提交模板筛选 A、B，使 A 最后成功或失败，列表保留 B 的结果；旧请求不得弹出失败或结束 B 的加载状态。当前请求失败后可以重试。
