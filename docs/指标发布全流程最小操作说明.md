# 指标发布全流程最小操作说明

本文说明如何用前端页面完成一条最小可发布链路：

```text
住院死亡记录数因子 + 住院出院病案记录数因子 -> 住院死亡率指标 -> 试算 -> 发布
```

核心要求：

```text
指标依赖的每个因子，都必须在 DSL 中声明 period BETWEEN 时间过滤。
```

否则发布指标版本时，后端会拒绝发布，并提示类似：

```text
指标自动回补要求每个依赖因子在DSL中声明 filters.PREDICATE(BETWEEN, parameter=period)
```

## 0. 前置检查：确认两个数据域和语义字段已经可用

在创建因子之前，先进入：

```text
数据管理
```

页面应能看到以下两个数据域：

```text
INPATIENT_DEATH_RECORD
INPATIENT_DISCHARGE_RECORD
```

分别点击这两个数据域，在下方“语义字段”表格中确认：

```text
死亡记录数据域 INPATIENT_DEATH_RECORD：能看到 DEATH_DATETIME
出院病案数据域 INPATIENT_DISCHARGE_RECORD：能看到 OUT_DATE
```

如果看不到 `INPATIENT_DISCHARGE_RECORD` 或看不到 `OUT_DATE`，不要继续创建分母因子。先在“源表绑定数据域”中绑定出院病案源表：

```text
源表名：vmq_basicinformationba
域编码：INPATIENT_DISCHARGE_RECORD
域名称：住院出院病案记录
语义表编码：INPATIENT_DISCHARGE_RECORD
语义表名称：住院出院病案记录
默认时间字段：OUT_DATE
```

点击：

```text
确认并绑定源表
```

页面成功提示后，重新点击 `INPATIENT_DISCHARGE_RECORD`，确认语义字段表格中已经出现 `OUT_DATE`。

同理，如果看不到 `INPATIENT_DEATH_RECORD` 或看不到 `DEATH_DATETIME`，先绑定死亡患者明细源表：

```text
源表名：vmq_deathpatientdetail
域编码：INPATIENT_DEATH_RECORD
域名称：住院死亡患者记录
语义表编码：INPATIENT_DEATH_RECORD
语义表名称：住院死亡患者记录
默认时间字段：DEATH_DATETIME
```

这一前置检查对应接口文档中的数据资产链路：

```text
POST /api/v1/meta/source-tables/{tableName}/bind-domain
GET  /api/v1/meta/data-domains
GET  /api/v1/meta/data-domains/{domainId}/semantic-fields
```

页面验收标准：

```text
1. 数据域列表能看到 INPATIENT_DEATH_RECORD 和 INPATIENT_DISCHARGE_RECORD。
2. 点击 INPATIENT_DEATH_RECORD 后，语义字段表格能看到 DEATH_DATETIME。
3. 点击 INPATIENT_DISCHARGE_RECORD 后，语义字段表格能看到 OUT_DATE。
```

## 1. 创建分子因子：住院死亡记录数

进入：

```text
因子管理 -> 新增因子
```

在基本信息中填写：

```text
因子名称：住院死亡记录数
因子编码：DEATH_COUNT_任意唯一后缀
说明：统计住院死亡患者记录数
```

在计算口径配置中选择：

```text
模板：计数类因子
数据来源：INPATIENT_DEATH_RECORD
语义表：INPATIENT_DEATH_RECORD
统计对象：不用选，计数类默认统计记录数
统计周期：按统计周期限定
统计周期依据字段：DEATH_DATETIME
分组维度：不选
结果单位：人次
```

此时 DSL 预览中应出现：

```json
{
  "primaryDomain": {
    "domainCode": "INPATIENT_DEATH_RECORD",
    "semanticTableCode": "INPATIENT_DEATH_RECORD"
  },
  "filters": {
    "nodeType": "PREDICATE",
    "fieldCode": "DEATH_DATETIME",
    "operator": "BETWEEN",
    "parameter": "period"
  },
  "parameters": [
    {
      "code": "period",
      "type": "DATETIME_RANGE"
    }
  ]
}
```

点击：

```text
保存并校验口径
```

效果说明：

```text
POST /api/v1/factors
POST /api/v1/factor-versions/{id}/compile
```

表示因子已保存，并且后端已编译校验该因子 DSL。

然后继续点击：

```text
发起试算 -> 查看试算结果 -> 发布因子版本
```

效果说明：

```text
POST /api/v1/factor-versions/{id}/trial
GET  /api/v1/async-tasks/{taskId}
GET  /api/v1/calc/batches/{batchId}
GET  /api/v1/factor-versions/{id}/trials/{batchId}/results
POST /api/v1/factor-versions/{id}/publish
```

成功后，记下页面显示的：

```text
因子版本 ID
```

该 ID 后续作为指标公式的分子因子版本。

## 2. 创建分母因子：住院出院病案记录数

再次进入：

```text
因子管理 -> 新增因子
```

在基本信息中填写：

```text
因子名称：住院出院病案记录数
因子编码：DISCHARGE_COUNT_任意唯一后缀
说明：统计住院出院病案记录数
```

在计算口径配置中选择：

```text
模板：计数类因子
数据来源：INPATIENT_DISCHARGE_RECORD
语义表：INPATIENT_DISCHARGE_RECORD
统计对象：不用选，计数类默认统计记录数
统计周期：按统计周期限定
统计周期依据字段：OUT_DATE
分组维度：不选
结果单位：人次
```

此时 DSL 预览中应出现：

```json
{
  "primaryDomain": {
    "domainCode": "INPATIENT_DISCHARGE_RECORD",
    "semanticTableCode": "INPATIENT_DISCHARGE_RECORD"
  },
  "filters": {
    "nodeType": "PREDICATE",
    "fieldCode": "OUT_DATE",
    "operator": "BETWEEN",
    "parameter": "period"
  },
  "parameters": [
    {
      "code": "period",
      "type": "DATETIME_RANGE"
    }
  ]
}
```

点击：

```text
保存并校验口径 -> 发起试算 -> 查看试算结果 -> 发布因子版本
```

效果说明：

```text
该出院病案记录数因子已成为可被指标公式引用的已发布因子版本。
```

同样记下页面显示的：

```text
因子版本 ID
```

该 ID 后续作为指标公式的分母因子版本。

## 3. 创建住院死亡率指标

进入：

```text
指标管理 -> 新增指标
```

在基本信息中填写：

```text
指标名称：住院死亡率
指标编码：MORTALITY_RATE_任意唯一后缀
指标分类：医疗质量 / 质量安全
计量单位：百分比（%）
指标定义：统计周期内死亡患者记录数除以出院病案记录数
```

点击：

```text
保存并进入公式配置
```

效果说明：

```text
POST /api/v1/indicators
POST /api/v1/indicators/{id}/versions
```

表示后端已创建指标主对象和指标版本。

## 4. 配置指标公式

在公式与试算页中配置：

```text
分子：选择刚刚发布的“住院死亡记录数”因子版本
分母：选择刚刚发布的“住院出院病案记录数”因子版本
```

公式含义：

```text
住院死亡率 = 住院死亡记录数 / 住院出院病案记录数 * 100%
```

点击：

```text
保存公式
```

效果说明：

```text
PUT /api/v1/indicator-versions/{id}/formula
```

表示指标公式 AST 已写入后端。

再点击：

```text
公式校验
```

效果说明：

```text
POST /api/v1/indicator-versions/{id}/formula/compile
```

表示后端已确认公式结构、依赖因子、输出类型等可以编译。

## 5. 试算指标

点击：

```text
发起试算
```

稍等后点击：

```text
查看结果
```

效果说明：

```text
POST /api/v1/indicator-versions/{id}/trial
GET  /api/v1/async-tasks/{taskId}
GET  /api/v1/calc/batches/{batchId}
GET  /api/v1/indicator-versions/{id}/trials/{batchId}/results
```

如果页面显示类似：

```text
试算结果：0.42%
```

说明指标公式可以基于两个因子计算出结果。

## 6. 发布指标版本

进入：

```text
发布检查
```

如果前面两个因子都带有：

```text
BETWEEN + parameter=period
```

则发布按钮可以点击。

点击：

```text
发布指标版本
```

效果说明：

```text
POST /api/v1/indicator-versions/{id}/publish
```

成功后表示：

```text
该指标版本正式发布。
后端会创建历史月度/年度回补任务，并生成后续日/月/年增量调度。
```

这一步成功，才说明该指标链路从“演示试算”进入了“正式可分析、可回补、可调度”的状态。

## 7. 常见错误与处理

### 7.1 指标发布提示依赖因子缺少 period BETWEEN

错误类似：

```text
依赖因子缺少 period BETWEEN 时间过滤
```

或：

```text
指标自动回补要求每个依赖因子在DSL中声明 filters.PREDICATE(BETWEEN, parameter=period)
```

原因：

```text
指标公式中选择了旧因子版本。
旧因子的 DSL 通常是 filters.TRUE，不具备按统计周期回补的能力。
```

旧因子 DSL 示例：

```json
{
  "filters": {
    "nodeType": "TRUE"
  },
  "parameters": []
}
```

处理方式：

```text
1. 回到因子管理。
2. 重新创建带“按统计周期限定”的新因子。
3. 发布新因子版本。
4. 回到指标公式中，换成新的因子版本。
5. 重新保存公式、公式校验、试算、发布指标。
```

### 7.2 因子发布前提示需要声明 period BETWEEN

原因：

```text
当前因子没有选择“按统计周期限定”，或没有选择统计周期依据字段。
```

处理方式：

```text
在因子编辑页中选择：
统计周期：按统计周期限定
统计周期依据字段：对应业务日期字段
```

住院死亡率推荐字段：

```text
死亡记录数因子：DEATH_DATETIME
出院病案记录数因子：OUT_DATE
```

### 7.3 分母因子校验状态显示 INVALID

如果在第 2 步创建“住院出院病案记录数”时，页面提示：

```text
计算口径校验状态：INVALID
```

优先检查三个页面可见点：

```text
1. 数据来源是否选择 INPATIENT_DISCHARGE_RECORD。
2. 语义表是否选择 INPATIENT_DISCHARGE_RECORD。
3. 统计周期依据字段下拉框中是否能选择 OUT_DATE，并且已经选中 OUT_DATE。
```

最常见原因是：

```text
INPATIENT_DISCHARGE_RECORD 数据域还没有绑定 vmq_basicinformationba，
或者该数据域下没有可用语义表/语义字段 OUT_DATE。
```

处理方式：

```text
1. 回到“数据管理”页面。
2. 点击 INPATIENT_DISCHARGE_RECORD。
3. 确认下方“语义字段”表格中有 OUT_DATE。
4. 如果没有 OUT_DATE，按本文第 0 节重新绑定源表 vmq_basicinformationba。
5. 回到“因子管理 -> 新增因子”，重新创建分母因子。
6. 确认 DSL 预览中同时出现 domainCode、semanticTableCode 和 OUT_DATE。
7. 再点击“保存并校验口径”。
```

修正后，页面应显示：

```text
计算口径校验状态：VALID
```

## 8. 最小验收结论

完成上述流程后，可以证明：

```text
1. 前端可以创建正式口径因子。
2. 因子 DSL 已包含 period BETWEEN 时间过滤。
3. 前端可以编译、试算并发布因子版本。
4. 前端可以创建指标和指标版本。
5. 前端可以保存并编译指标公式。
6. 前端可以发起指标试算并读取结果。
7. 前端可以发布指标版本。
8. 后端可以基于发布指标创建历史回补和增量调度。
```
