## 1. 本次创建什么

本次从零创建“每百出院人次非药非耗材费用”指标，使用“嵌套公式型”。四个因子从同一张病案首页物理表、相同出院周期取数。

```text
T = 住院总费用
D = 药品费用
M = 耗材费用
N = 出院住院人次

指标 = ROUND(((T - (D + M)) / N) * 100, 2)
```

这里的 `100` 表示“每百人次”，不是百分比。指标表单选择单位“元”，在名称和定义中写明“每百出院人次”；公式展示选择“数值”、展示乘数 `1`。

### 1.1 本次对象清单

| 对象 | 本次编码 | 本次名称 |
| --- | --- | --- |
| 测试政策文件 | `UAT_POLICY_COST_20261027_01` | `验收_复杂费用指标依据_CX01` |
| 总费用因子 T | `UAT_CX_TOTAL_20261027_01` | `验收_住院总费用_CX01` |
| 药品费用因子 D | `UAT_CX_DRUG_20261027_01` | `验收_药品费用_CX01` |
| 耗材费用因子 M | `UAT_CX_MATERIAL_20261027_01` | `验收_耗材费用_CX01` |
| 出院人次因子 N | `UAT_CX_VISITS_20261027_01` | `验收_出院人次_CX01` |
| 嵌套公式指标 | `UAT_CX_NETCOST100_20261027_01` | `验收_每百出院人次非药非耗材费用_CX01` |

重做时将编码后缀 `_01` 统一改成 `_02`，名称中的 `CX01` 统一改成 `CX02`。不要覆盖之前已发布的测试对象。

## 2. 登录、准备数据并记录对账基线

### 2.1 登录系统

1. 打开 <http://192.168.123.14/>。
2. 在登录页“工号”填写本人获授权的验收账号，在“密码”填写对应密码，点击“登录”。
3. 按 `Ctrl+F5` 刷新页面。

预期结果：登录成功并能进入相应菜单。只有看板读取权限的普通账号不能完成本手册的创建与发布。

### 2.2 核对物理表和字段

1. 进入“指标配置 → 因子管理”，点击“新建因子”。
2. 在“计算口径配置 → 第一步：从哪里取数？”将“取数方式”选为“物理表取数”。
3. 点击“主物理表”，输入 `vmq_basicinformationba`，选中对应表。
4. 点击“统计周期字段”，检查存在 `out_date`。
5. 在统计字段候选中检查存在 `total_cost`、`drug_cost`、`material_cost`、`VISIT_ID`。
6. 本次检查页可以继续用于第4章创建T因子，不必另建空白对象。

预期结果：选表后字段候选能够加载。若主表或字段不存在，先到“数据治理 → 数据源管理”核对同步情况；此时停止创建，不用相似表、相似字段凑数。

5. 等待“编译校验通过”，确认出现“编译产物”ID。
6. 在当前页面向下找到“本次试算周期”；等待推荐日期加载完成后，将开始时间改为 `2026-01-01 00:00:00`，结束时间改为 `2026-02-01 00:00:00`。

8. 若仍处理中，使用“刷新状态”或“继续查询并查看结果”继续查询同一任务。
9. 在“试算结果”核对总体结果与第2章当天源库 `T` 相同；历史参考为 `233421237.38`。
10. 确认任务成功、质量正常后，点击“发布因子版本”。
11. 在确认框点击“确认发布”。
12. 等待“已发布”，点击“返回因子目录”；按完整编码查询，确认该对象存在且已发布。

### 7.3 进入指标创建前的检查

| 检查项 | 应满足的条件 |
| --- | --- |
| 对象身份 | T、D、M、N是四个不同因子，发布版本ID均已记录 |
| 发布时间 | 四个因子版本均已发布 |
| 周期 | 四次对账都使用同一1月半开周期 |
| 结果 | 四个结果分别等于当天源库T、D、M、N |
| 人数 | N大于0，采用去重计数 |

任一项不满足，先处理该因子，不进入指标公式配置。

5. 找到代表100倍换算的数字设置：若内层显示“百分比乘数”，将其由100改为200；若显示“乘数2”常量输入框，则将该值改为200。不要修改整体展示乘数，后者仍为1。
6. 点击“保存公式”，再点击“公式校验”。
7. 试算周期填1月1日00:00至2月1日00:00，点击“试算并查看结果”。
8. 核对结果与当天源库 `expected_per_200` 一致；历史参考为 `1880667.75`。
9. 切回原已发布版本，核对原公式仍为100倍，原正式结果未被草稿试算覆盖。

此新草稿只用于验证改版，可以不发布。不能把旧显示值 `940333.88` 直接乘2作为正确新结果；应使用原始四因子重新计算后舍入。

## 16. 复合因子扩展验收（可选）

主线已覆盖四个原子因子和嵌套公式。若还需验收“复合因子创建”，单独执行本章，不修改主线已发布对象。

### 16.1 确认引用因子，无需查看技术信息

本章使用已经发布的T、D、M、N创建复合因子链。普通操作人员无需打开技术信息、选择数据域或手填量纲单位。

1. 在因子管理确认本次T、D、M、N均已发布，名称及版本ID与验收记录一致。
2. 确认四个因子使用同一统计周期和总体粒度。本例在主线均选择“时序”、不分组。
3. 进入“新建因子”，选择“复合因子”。页面先显示计算方式、左侧因子、右侧因子及公式预览；“高级设置（选填）”默认收起。
4. 选择引用因子后，等待“正在核对引用因子信息”结束。页面自动带出能够确认的结果分组、计算模式和相加/相减的相同量纲、单位。
5. 本例T、D、M若未声明输出单位，页面可能显示“单位：未指定”，保持即可。系统不再自动填入 `COUNT`；不要把指标的展示单位“元”反填为未经确认的因子类型代码。
6. 若显示单位、量纲、计算模式不一致，或引用因子信息读取失败，按提示选择兼容因子或点击重试；不要打开技术信息来绕过校验。已有因子不得直接改写以凑出结果。
7. 核对公式预览无误后，保存、编译校验并使用同一周期试算。编译通过仍需核对试算值，不能直接签为验收通过。

**数据域说明：**当前后端复合因子创建/编译分支要求保留 `primaryDomain` 对象，但不要求其中有 `domainCode`。因此本次复合因子可以使用空对象，与物理表原子因子未选择数据域的主线兼容。“高级设置”中的“所属数据域”仅在确有归类需要时选择，普通操作可留空，已有显式归类会保留。

**技术信息位置：**仅技术排查时使用“页面右上角 → 更多 → 技术信息（只读）”；已发布因子也可查看，但仍不可修改或保存已发布定义。创建、编译、试算和发布均不要求先打开此处。

## 17. 常见问题与停步位置

| 看到的现象 | 先检查哪里／如何处理 |
| --- | --- |
| 主表或字段下拉为空 | 检查元数据同步、物理表选择和权限，不填另一张相似表继续 |
| 编码重复 | 全套测试编码换新后缀，不覆盖已发布对象 |
| 新因子在公式素材中找不到 | 先确认已发布、编码正确；重新进入指标公式页读取因子目录 |
| 点击模式后整个公式不见了 | 检查是否误点了页面顶部模式；嵌套构造必须使用左侧素材区 |
| 回不到最外层 | 点击公式层级最左侧“完整公式” |
| 结果为 `940334.00` 一类的偏差 | 检查是否把ROUND放到了除法后、乘100前；以源库两列对照 |
| 结果大了100倍或带百分号 | 检查整体展示格式必须“数值”、展示乘数必须1 |
| 人数与源库不一致 | 检查是否用了记录计数，或误选入院表、入院日期；本例用BA表、out_date、VISIT_ID去重 |
| 预检不支持医生 | 检查四个源因子是否都映射out_dept_code和attending_doctor |
| 试算成功但分析无数据 | 先完成正式计算，核对指标版本、期间、目标和激活情况 |
| 正式批次部分成功 | 展开失败目标，不能只凭总体有值就签组织下钻通过 |
| 政策发布后仍提示绑定失败 | 使用“重试保存政策来源”，成功后重新读取 |
| 无数据或N为0 | 保留空值／无数据／质量诊断，不强行改零分母策略以凑出正常金额 |
| 物理表或复合因子未选数据域、未声明单位 | 本例允许；普通创建无需补填，保存后继续编译和试算核对，不编造字符串 |
| 需要技术人员排查配置 | 从右上角“更多 → 技术信息（只读）”查看；普通操作不需要打开，已发布定义仍不可编辑 |
