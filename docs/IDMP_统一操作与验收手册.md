## 1. 如何使用本手册

### 1.1 先选择正确的阅读路径

|目标|建议阅读章节|是否写入数据|
|---|---|---|
|了解页面和状态含义|第 2 章|否|
|接入一张新来源表|第 3 章|是|
|为字段建立标准值或连续范围约束|第 4 章|是|
|创建可计算的统计口径|第 5 章|是|
|批量复用已发布口径|第 6 章|是|
|创建、试算和发布指标|第 7 章|是|
|为指标配置版本化场景|第 8 章|是|
|追踪、取消或重试任务|第 9 章|部分操作会写入|
|查看正式结果、下钻和追溯|第 10 章|否|
|完整演示或部署验收|第 11、13 章|按案例而定|

### 1.2 操作步骤中的标记

- **入口**：按左侧导航进入页面的路径。
- **前置条件**：未满足时不应继续执行下一步。
- **风险提示**：会修改共享对象、替换集合或发布版本的操作。
- **预期反馈**：页面上应观察到的结果；仅弹出“成功”提示不足以作为验收依据。
- **接口证据**：用于 Network 或接口联调核对，不要求日常操作人员手工调用。

### 1.3 两种执行模式不得混用

1. **只读回归**：使用已经发布的对象，查询列表、版本、结果和任务。不修改对象，不以新 ID 覆盖历史样例。
2. **隔离创建**：使用本次唯一标识创建新对象，例如 `TEST_20260827_01`。数据域、值集、因子、指标和场景编码都使用同一后缀。

> 风险提示：不要给已有语义字段重新绑定值集，不要在已有发布版本上试图直接修改定义。需要变更时，应创建新的草稿版本或新的隔离对象。

## 2. 通用约定

### 2.1 当前导航

|导航分组|菜单|主要用途|
|---|---|---|
|总览与分析|指标总览、指标分析、预警中心|查看汇总、趋势和分析结果|
|指标配置|指标目录、因子管理、因子模板、场景管理、指标映射|配置指标计算业务对象|
|数据治理|数据源管理、数据域管理、值集管理|准备计算所需数据语义|
|计算运行|计算任务|查询或处置异步计算|
|平台管理|系统管理|登录会话与系统管理能力|

日常数据准备使用“数据源管理 → 数据域管理 → 值集管理”的分步流程。旧的 `/data` 兼容入口不作为操作路径。

### 2.2 权限和可见性

如果菜单、按钮或字段不可见，先确认当前账号具备对应的查看、创建、编辑、发布权限。页面不应通过直接拼接 URL 绕过权限。

|动作|通常需要的权限或角色|
|---|---|
|同步来源、创建数据域、映射字段|数据管理员|
|维护值集和转换规则|数据管理员或标准管理员|
|创建、发布因子及模板|指标管理员或模板管理员|
|创建、发布指标|指标管理员|
|维护场景|场景管理员|
|取消批次、重试节点|计算运维人员|

后端仍是最终权限判定方；即使页面可操作，接口返回 403 时也应记录权限缺口和 `traceId`。

### 2.3 版本、资源版本和 ID

- 因子、指标、值集、模板和场景均存在版本生命周期。已发布版本通常只读。
- `resourceVersion` 用于并发控制。多人编辑同一草稿时，出现 409 应刷新并比较最新内容，不要盲目重复提交旧内容。
- 所有业务 ID 均按字符串复制、保存和传递；不得在 Excel、JavaScript 或表格软件中转为数值，以免长整型精度丢失。
- 发布、删除、恢复等操作前，优先刷新详情，确保使用当前资源版本。

### 2.4 异步任务的统一判断

提交试算或正式计算后，先记录页面显示的 `taskId`、`batchId` 和时间范围。

|状态|含义|操作建议|
|---|---|---|
|`QUEUED`|已受理，等待执行|等待或刷新状态|
|`RUNNING`|正在执行|继续查询任务或批次|
|`SUCCEEDED` / `SUCCESS`|任务成功结束|读取结果，并检查质量状态|
|`FAILED`|任务失败|查看节点错误、`traceId` 和源数据状态|
|`CANCELLED` / `CANCELED`|已取消|确认是否需要重新创建批次|
|`PARTIAL_SUCCEEDED`|部分目标成功|逐个检查失败目标，不能整体判定通过|

> “任务成功”不等同于“业务结果可用”。还应检查结果是否已读取、`qualityStatus` 是否正常、源数据状态是否为有数据，以及正式结果是否已激活。

### 2.5 验收留证最小集

每次写入或发布应至少记录：对象编码、对象/版本 ID、操作人、操作时间、运行周期、任务/批次 ID、最终状态、异常码和 `traceId`（如有）。

## 3. 数据治理

### 3.1 数据源管理：同步并查看来源结构

**目标**：让后续数据域工作台可以选择真实的来源表或视图。

**入口**：数据治理 → 数据源管理。

**操作步骤**：

1. 点击“同步数据结构”。
2. 在确认框中确认本次同步范围。
3. 等待页面显示同步结果；如失败，先查看错误信息后再重试。
4. 在“数据表与视图”区域按名称、对象类型或注释筛选。
5. 点击“查看字段”，核对字段名、类型、可为空和注释。

**预期反馈**：来源表或视图出现在列表中，所需字段可被读取。

**不通过处理**：

- 列表为空：确认后端来源连接、同步权限和同步任务状态。
- 新建语义表时来源表下拉为空：先回到本页完成同步，不要手工输入未发现的表名。
- 字段类型与预期不一致：以来源结构为准，重新选择语义字段数据类型和业务角色。

**接口证据**：`POST /meta/source-mappings/sync`、`GET /meta/source-tables`、`GET /meta/source-tables/{tableName}/fields`。

### 3.2 数据域管理：创建并进入工作台

**目标**：按业务主题隔离语义表、语义字段和后续因子引用范围。

**入口**：数据治理 → 数据域管理。

**操作步骤**：

1. 点击“新建数据域”。
2. 填写唯一的数据域编码、名称和说明。
3. 点击“确认创建”。
4. 在数据域目录中定位新记录，点击“进入工作台”。

**预期反馈**：目录可查询到新数据域，工作台顶部显示对应名称和编码。

> 风险提示：当前页面重点覆盖创建、语义表和字段映射。若后端要求数据域处于已发布状态才能在因子编辑器中选择，请在创建因子前确认该前置状态；不要为了绕过限制改用其他业务对象。

**接口证据**：`GET /meta/data-domains`、`POST /meta/data-domains`。

### 3.3 数据域工作台：创建语义表

**目标**：将一张已同步的来源表或视图纳入数据域。

**入口**：数据治理 → 数据域管理 → 目标数据域 → “进入工作台”。

**操作步骤**：

1. 在“语义表”区域点击“新建语义表”。
2. 在“来源物理表”中选择已同步对象。
3. 填写语义表编码和名称。
4. 点击“确认创建”。
5. 在语义表列表中选择刚创建的语义表，作为下方字段映射的上下文。

**预期反馈**：语义表列表显示来源物理表、默认时间字段和状态；右侧或下方显示当前语义表上下文。

**接口证据**：`POST /meta/data-domains/{domainId}/semantic-tables`、`GET /meta/data-domains/{domainId}/semantic-tables`。

### 3.4 数据域工作台：映射语义字段

**目标**：将物理字段赋予可被因子和指标理解的标准业务含义。

**入口**：数据域工作台 → 选择语义表 → “语义字段映射”。

**操作步骤**：

1. 在“来源字段”列表中点击目标物理字段。
2. 填写标准字段编码、业务名称和标准数据类型。
3. 选择业务角色：
   - 维度：用于筛选、分组和值集绑定；
   - 度量：用于金额、数量等数值聚合；
   - 属性：用于描述性信息。
4. 必要时标记敏感信息。
5. 点击“保存字段映射”。
6. 刷新或在“标准业务字段”列表核对映射状态、来源字段、数据类型和业务角色。

**重点**：数据类型与业务角色必须分别选择。例如性别通常是 `STRING/CODE + DIMENSION`，金额通常是 `DECIMAL + MEASURE`，不能只凭字段类型推断用途。

**接口证据**：`POST /meta/data-domains/{domainId}/semantic-tables/{tableCode}/semantic-fields`、`GET /meta/data-domains/{domainId}/semantic-tables/{tableCode}/semantic-fields`。

### 3.5 配置默认时间字段

**目标**：为语义表提供统计周期的默认绑定字段。

**入口**：数据域工作台 → 选择语义表 → 页面下方“默认时间字段”。

**操作步骤**：

1. 确认时间字段已经完成映射，数据类型为日期或日期时间。
2. 在下拉框选择该字段，例如“出院时间（OUT_TIME）”。
3. 点击“保存默认时间字段”。
4. 刷新语义表列表，确认“默认时间字段”列已回显。

**预期反馈**：因子编辑器选择该语义表后，能够识别统计周期字段。

**接口证据**：`PATCH /meta/data-domains/{domainId}/semantic-tables/{tableCode}/default-time-field`。

### 3.6 字段画像

**目标**：在建值集或标准化规则前确认真实源值分布。

**入口**：数据域工作台 → 标准业务字段列表 → “字段画像”。

**操作步骤**：

1. 选择已映射字段。
2. 点击“字段画像”。
3. 核对总记录数、空值数、不同值数，以及离散值的记录数和占比。
4. 将真实源值记录到本次验收表，再决定值集项或转换规则。

**预期反馈**：不能根据字段名猜测 `1/2/9`、`Y/N` 等源值含义；应以画像和业务确认结果为准。

**接口证据**：`GET /meta/source-field-mappings/{mappingId}/value-profile`。

## 4. 值集与源值标准化

### 4.1 选择正确的值集类型

|业务数据形态|值集匹配模式|适用示例|
|---|---|---|
|固定编码的一一对应|精确枚举（`EXACT`）|性别、状态、是否标识|
|编码前缀归类|前缀编码（`PREFIX`）|疾病编码、行政编码|
|有限个命名区间|区间档位（`RANGE`）|年龄段、分层档位|
|父子目录|层级目录（`HIERARCHICAL`）|组织、地区、分类目录|
|连续数字或日期|连续值集（`CONTINUOUS`）|金额、数量、日期时间|

连续值集只约束单位、精度和合法边界，不维护“1000 至 5000”这样的值项；实际范围在因子筛选条件中填写。

### 4.2 创建枚举、前缀、区间或层级值集

**入口**：数据治理 → 值集管理 → “新建值集”。

**操作步骤**：

1. 填写值集编码、名称、值类型、来源标准名称和说明。
2. 在“数据组织方式”选择适合的匹配模式。
3. 创建后进入值集详情，打开草稿版本。
4. 在“值项维护”中维护编码、值、名称、排序和必要的区间或父子关系。
5. 点击“保存值项”。这是全量替换操作，保存前确认未误删既有项。
6. 点击“校验版本”，处理诊断信息。
7. 校验通过后点击“发布版本”。

**预期反馈**：版本状态变为已发布；已发布版本可用于字段绑定。

**接口证据**：`POST /meta/value-sets`、`PUT /meta/value-set-versions/{versionId}/items`、`POST /meta/value-set-versions/{versionId}/validate`、`POST /meta/value-sets/{valueSetId}/versions/{versionId}/publish`。

### 4.3 创建连续值集

**入口**：数据治理 → 值集管理 → “新建值集”。

**操作步骤**：

1. 填写编码、名称和说明。
2. 选择数值、日期或日期时间值类型。
3. 选择“连续数值/日期”。
4. 填写连续范围规范：
   - 数值：单位、总精度、小数位、可选最小值和最大值；
   - 日期/日期时间：单位，以及可选时间粒度和时区。
5. 点击创建并进入详情。
6. 在版本编辑页核对“连续值规范”，不维护枚举值项。
7. 校验并发布版本。

**校验要点**：整数不允许小数；小数位不得超过定义精度；最小值不能大于最大值；单位不可缺失。

**预期反馈**：详情页显示连续值规范，值项数为零是正常现象。

### 4.4 将值集绑定到语义字段

**入口**：数据域工作台 → 标准业务字段 → “绑定值集”。

**操作步骤**：

1. 选择已映射字段。
2. 点击“绑定值集”。
3. 确认当前绑定状态。
4. 选择类型和匹配模式兼容的已发布值集。
5. 点击“确认绑定”，再刷新字段列表确认结果。

**风险提示**：重新绑定会影响后续因子筛选可引用的已发布值集版本。共享字段的变更必须经过影响评估；隔离验收应使用新字段。

**接口证据**：`GET /meta/semantic-fields/{fieldId}/value-set`、`PUT /meta/semantic-fields/{fieldId}/value-set`。

### 4.5 源值标准化

**目标**：将各来源系统的物理值转换为统一的标准值项。

**入口**：数据域工作台 → 目标维度字段 → “标准化”。

**操作步骤**：

1. 先完成字段画像和值集发布、绑定。
2. 打开“源值标准化”页面，查看当前源字段和已有规则。
3. 新建或编辑转换规则，将每个真实源值映射为标准值项编码。
4. 预览规则，重点检查未匹配数量。
5. 校验并发布规则。

**验收标准**：所有本次范围内的源值均有明确处置；未匹配值为零，或已得到业务确认并在记录中说明。

**接口证据**：`POST /meta/source-field-mappings/{mappingId}/transform-rules`、`POST /transform-rule-versions/{versionId}/preview`、`POST /transform-rule-versions/{versionId}/validate`、`POST /transform-rule-versions/{versionId}/publish`。

### 4.6 值集改版和归档

已发布值集不可直接覆盖修改。需要调整时，在值集详情点击“复制为新版本”，编辑草稿、校验、发布。当前生效版本不能直接归档。

## 5. 因子管理

### 5.1 新建因子

**入口**：指标配置 → 因子管理 → “新建因子”。

**前置条件**：数据域、语义表、必要语义字段已经准备完成；如需要运行期周期，语义表已配置默认时间字段。

**操作步骤**：

1. 在“基础信息”填写唯一因子编码、名称、业务分类和说明。
2. 在“计算口径配置”选择数据域和语义表。
3. 确认页面显示的统计周期字段是否符合预期。
4. 在“统计方式”选择记录计数、去重计数、求和、平均值、最小值或最大值。
5. 按统计方式选择统计字段；`COUNT` 不选择字段时表示统计全部记录。
6. 按需要选择分组维度；不选择表示总体结果。
7. 在“筛选范围”选择全部记录，或选择显式筛选条件。
8. 点击“保存因子定义”。保存成功后记录因子 ID 和草稿版本 ID。

**预期反馈**：页面进入“编译、试算与发布”步骤，并显示保存后的版本上下文。

### 5.2 因子筛选条件

|条件类型|操作要点|
|---|---|
|统计周期|选择日期/日期时间字段和“使用试算周期”；该条件写入运行期 `period` 参数|
|枚举值集|选择已绑定枚举值集的维度字段，再选择标准值项，不直接填写物理源值|
|连续范围|选择已绑定连续值集的数值/日期字段，填写开始值和结束值|
|逻辑组合|使用 AND、OR、NOT 组织条件，检查口径预览是否符合业务含义|

连续范围按左闭右开区间 `[开始值, 结束值)` 执行。页面应自动引用字段当前绑定的已发布连续值集版本，操作人员不应手工填写版本 ID。

> 注意：页面会显示默认时间字段的自动周期绑定说明；对需要在因子 DSL 中明确限定运行期范围的业务口径，仍应按页面提供的“使用试算周期”条件配置并在“查看技术配置”中核对。最终以发布前编译诊断和接口返回的 DSL 为准。

### 5.3 编译、推荐周期、试算和发布

**入口**：因子编辑页 → “编译、试算与发布”。

**操作步骤**：

1. 点击“编译并校验”。
2. 处理诊断后，确认编译状态为通过或通过且有可接受警告。
3. 等待页面读取后端推荐的真实数据周期；如业务需要，可手工修改为自定义周期。
4. 点击“试算并查看结果”。
5. 任务未结束时点击“刷新状态”或再次点击继续查询。
6. 读取结果，检查结果值、`qualityStatus`、源数据状态和分组维度。
7. 满足发布门禁后点击“发布因子版本”。

**发布前检查**：编译已通过、试算已成功、结果已读取、质量状态正常、版本未发布。

**接口证据**：`POST /factor-versions/{id}/compile`、`GET /factor-versions/{id}/trial-period-recommendation`、`POST /factor-versions/{id}/trial`、`GET /factor-versions/{id}/trials/{batchId}/results`、`POST /factor-versions/{id}/publish`。

### 5.4 编辑已有因子和新建版本

在因子管理中按编码查询并进入编辑。修改后应重新保存、编译和试算。已发布版本不能直接作为可写草稿时，应按后端允许的版本演进方式创建或使用新的草稿版本；不要把历史发布结果当作本次编辑的验证结果。

### 5.5 删除影响、删除和恢复

**入口**：指标配置 → 因子管理 → 目标因子的删除操作；恢复入口为“回收站”。

**操作步骤**：

1. 先查看删除影响，确认依赖指标、模板实例或历史版本。
2. 仅在影响已经确认且具备授权时执行删除。
3. 删除后进入“回收站”，按编码或名称查询。
4. 先查看回收站详情及保留版本，再点击“恢复”。

**风险提示**：删除是软删除，但可能影响对象可见性和后续引用。恢复前需确认不会与已新建的同编码对象冲突。

**接口证据**：`GET /factors/{id}/deletion-impact`、`DELETE /factors/{id}`、`GET /factors/recycle-bin`、`POST /factors/recycle-bin/{id}/restore`。

## 6. 因子模板

### 6.1 模板的适用场景

当多个人工因子只有少量业务输入不同，例如性别、科室、日期范围或标准值项不同，而数据域、统计方式和主体过滤逻辑相同时，应优先使用模板。模板发布后，业务用户只填写显式暴露的预留参数，后端生成对应的实例因子草稿。

### 6.2 创建并发布模板

**入口**：指标配置 → 因子模板 → “新建模板”。

**操作步骤**：

1. 填写模板编码、名称、说明和适用因子范围。
2. 配置数据域、语义表、统计方式、统计字段、输出与允许粒度。
3. 如适用，引用已发布下钻路径版本。
4. 在“模板参数”中添加业务用户可填写的参数，明确编码、展示名、类型、是否必填、默认值和可选值。
5. 在“参数化筛选条件”中选择语义字段、判断方式和对应参数。
6. 创建或保存模板草稿。
7. 执行校验，处理诊断后发布模板版本。

**预期反馈**：模板目录显示已发布版本；页面可进入“创建因子”。

### 6.3 从模板创建因子

**入口**：指标配置 → 因子模板 → 已发布模板 → “创建因子”；也可从因子管理点击“从模板创建因子”。

**操作步骤**：

1. 填写实例因子的编码、名称、分类和说明。
2. 填写模板显示的预留参数。
3. 在“创建确认”核对参数和值。
4. 点击“创建因子草稿”。
5. 继续执行编译、可选试算和发布。

**验收标准**：实例因子能够在因子目录中查询到，且来源显示为模板；实例的最终 DSL 与填写的参数一致。

**接口证据**：`POST /factor-templates`、`POST /factor-template-versions/{id}/validate`、`POST /factor-template-versions/{id}/publish`、`POST /factor-template-versions/{id}/instantiate`、`GET /factor-template-versions/{id}/instances`。

## 7. 指标管理

### 7.1 创建指标和草稿版本

**入口**：指标配置 → 指标目录 → “新增指标”。

**操作步骤**：

1. 在“1 基础与版本”填写指标编码、名称、分类、属性、单位、导向、统计周期、定义、意义和数据来源。
2. 保存基本信息。
3. 为当前指标创建草稿版本；已有指标需要变更公式时也应先创建草稿版本。
4. 记录指标 ID 和指标版本 ID。

**预期反馈**：页面进入可编辑的“2 公式与试算”状态。

### 7.2 配置公式和下钻能力预检

**入口**：指标编辑页 → “2 公式与试算”。

**操作步骤**：

1. 在可用因子中选择已发布且业务口径正确的因子版本。
2. 通过公式编辑器配置单因子、分子/分母或其他支持的公式结构。
3. 保存公式。
4. 点击“预检下钻能力”。
5. 根据返回的 `supported`、`maxLevel`、`levels` 和限制因子，选择可用下钻路径与最大层级。
6. 编译指标公式。

**重要原则**：下钻预检的能力上限只表示“最多可到哪里”，不表示该路径已经在指标版本中启用。实际发布版本的路径配置才是分析页和下钻页的依据。

### 7.3 指标试算、发布和正式结果

**操作步骤**：

1. 选择完整的试算周期。
2. 点击“试算并查看结果”。任务处理中时继续查询状态。
3. 核对结果值、分子/分母、质量状态和失败信息。
4. 点击“发布指标版本”。
5. 如需查看分析，使用“生成正式结果并去指标分析”或在计算任务中创建正式批次。
6. 等待正式批次成功并确认结果已激活，再进入分析页。

**关键区分**：试算结果用于验证定义；指标分析页读取正式结果。不能把试算成功直接判定为分析和下钻通过。

**接口证据**：`POST /indicator-versions/{id}/formula/compile`、`POST /indicator-versions/{id}/trial`、`GET /indicator-versions/{id}/trials/{batchId}/results`、`POST /indicator-versions/{id}/publish`、`POST /calc/batches`。

### 7.4 指标与场景关联

指标详情页可查看当前关联的场景及实际引用的指标版本。指标编辑页的“场景关联”用于查看配置边界；场景的新增、替换和发布操作应在“场景管理”中完成。

**接口证据**：`GET /indicators/{id}/scenarios`。

### 7.5 指标删除和回收站

**入口**：指标配置 → 指标目录 → “回收站”。

执行删除前必须先查看影响。删除后在回收站中查看详情、保留版本并按当前资源版本恢复。恢复后再次检查场景关联和分析入口是否符合预期。

**接口证据**：`GET /indicators/{id}/deletion-impact`、`DELETE /indicators/{id}`、`GET /indicators/recycle-bin`、`POST /indicators/recycle-bin/{id}/restore`。

## 8. 场景管理

### 8.1 创建场景和首个草稿

**入口**：指标配置 → 场景管理 → “新建场景”。

**操作步骤**：

1. 填写场景编码、名称、类型、默认周期、主管部门和说明。
2. 点击“创建并编辑”。
3. 确认页面进入场景编辑页，首个版本为草稿。

### 8.2 编辑基本信息和关联指标

**入口**：场景编辑页 → “基本信息”“关联指标”。

**操作步骤**：

1. 若页面为只读，点击“编辑场景”创建或进入可编辑草稿。
2. 在“基本信息”调整名称、主管部门、默认统计周期、生效日期、说明和默认排除规则。
3. 在“关联指标”中仅选择已发布指标版本。
4. 对每项指标设置是否必选和上报要求。
5. 点击“保存草稿”。

> 风险提示：关联指标保存采用完整集合语义。页面中删除一项再保存，表示该项会从场景版本中移除，不是仅提交增量。

### 8.3 配置覆盖规则、预览、校验和发布

**入口**：场景编辑页 → “覆盖规则”“合并预览”“校验诊断”。

**操作步骤**：

1. 在“覆盖规则”新增场景全局或单指标覆盖。
2. 填写作用范围、覆盖类型、目标路径、覆盖值和优先级。
3. 覆盖值必须是合法 JSON。
4. 保存草稿。
5. 在“合并预览”点击“刷新预览”，核对后端生成的最终有效口径。
6. 点击“校验”，处理错误或警告。
7. 校验通过后点击“发布”。

**预期反馈**：发布后版本转为只读，目录显示正确状态和指标数。

### 8.4 创建下一草稿和处理 409

已发布场景需要继续变更时，基于发布版本创建下一草稿，不修改历史发布版本。

出现 409 时：停止重复提交 → 刷新版本 → 比较当前页面输入和服务端最新数据 → 决定重新录入、合并或放弃本次修改 → 使用最新 `resourceVersion` 保存。

**接口证据**：`POST /scenarios`、`POST /scenarios/{id}/versions`、`PATCH /scenario-versions/{id}`、`PUT /scenario-versions/{id}/indicators`、`PUT /scenario-versions/{id}/overrides`、`GET /scenario-versions/{id}/merged-preview`、`POST /scenario-versions/{id}/validate`、`POST /scenario-versions/{id}/publish`。

## 10. 指标分析、下钻与追溯

### 10.1 查看指标正式结果

**入口**：总览与分析 → 指标分析。

**前置条件**：指标版本已发布，所选周期存在已激活的正式结果。

**操作步骤**：

1. 选择指标和指标版本（如页面提供）。
2. 选择结果周期或趋势粒度。
3. 点击“查看分析”或“查看报告”。
4. 核对当前值、分子、分母、趋势、结果时间范围和状态。
5. 打开“数据说明/数据诊断”，查看可用数据范围、结果追溯和当前可用性状态。

### 10.2 判定结果是否可用

|页面或接口状态|含义|验收结论|
|---|---|---|
|已有正式结果|所选周期可展示真实结果|可继续趋势、排名和下钻验证|
|数据待计算/计算中|存在可计算对象，但正式任务尚未完成|记录为待计算，不判定分析通过|
|无共同可用周期|引用因子的可用源数据范围没有交集|调整周期或检查因子数据|
|部分可探测|部分因子或数据可用|不能将整体结果当作完整可用|
|有数据但计算失败|源数据存在，但计算或配置发生错误|按失败处理，查看节点和错误信息|
|无数据|该周期没有匹配源数据|不是接口故障，按业务规则判断是否可接受|

### 10.3 趋势和科室排名

在“趋势分析”中切换月、季、年粒度或指定日期范围。分析接口的周期查询按日期传递；若试算/正式批次保留日期时间，应以页面实际归一化后的日期参数为准。

在“科室排名”中确认页面标签是否显示“后端维度数据”。若仅显示演示数据，不得作为真实环境验收证据。

### 10.4 下钻分析

**入口**：指标分析 → “下钻分析” → 选择结果，或进入“结果下钻”页面。

**操作步骤**：

1. 确认当前结果来自正式批次，且版本实际启用了相应下钻路径。
2. 从根层级逐级进入下一层。
3. 每次下钻核对当前路径、结果 ID、`nextLevels` 和页面面包屑。
4. 到达版本配置的最大层级时，记录“已到末级”，不要把没有下一层误判为接口失败。
5. 出现 `__UNASSIGNED__` 时，确认其代表缺失维度编码的归桶；它不应被直接删除，否则汇总与明细会不一致。

### 10.5 因子结果追溯

在某一指标结果中打开“因子追溯”，核对分子、分母因子版本和对应因子结果。应同时检查：

- 追溯的因子版本是否与指标公式引用一致；
- 结果是否匹配；
- 质量状态和源数据状态；
- 结果周期是否与当前指标结果一致。

**接口证据**：`GET /indicator-versions/{id}/available-period`、`GET /analysis/indicators/{indicatorId}/analysis`、`POST /analysis/results/{resultId}/drill/search`、`GET /analysis/results/{resultId}/factors`。

## 11. 端到端验收案例

本章给出可复用案例。案例中的编码必须替换为本次唯一标识；固定历史对象和固定数字只可作为回归参考。

### 11.1 案例 A：枚举值集过滤到双因子指标下钻

**目标**：将来源性别值标准化为“男、女、未知”，创建男性分子和全部分母，形成比率指标，并验证正式结果和下钻。

**最短路径**：

1. 同步来源，创建数据域和语义表。
2. 映射性别为维度字段，映射出院时间为默认时间字段。
3. 创建并发布性别枚举值集，绑定到性别字段。
4. 为每个真实来源值配置、预览、校验并发布转换规则。
5. 创建男性分子因子：周期条件 + 性别标准值条件。
6. 创建全部分母因子：仅保留同一周期条件。
7. 编译、试算、读取结果并发布两个因子。
8. 创建指标版本，配置分子/分母公式和下钻能力预检。
9. 编译、试算、发布指标；创建或等待同周期正式结果。
10. 在分析页验证趋势、排名和已启用路径的下钻；再做因子追溯。

**判定**：`0 < 分子 ≤ 分母`；性别转换无未匹配；正式结果而非演示数据可读取；下钻路径未超过版本最大层级。

### 11.2 案例 B：连续值集到费用范围因子

**目标**：为住院总费用建立连续值集，并统计指定费用范围内的记录。

**最短路径**：

1. 准备金额字段（`DECIMAL + MEASURE`）和时间字段（日期/日期时间 + 默认时间字段）。
2. 使用字段画像确认金额列存在有效数据。
3. 创建连续值集，填写单位、精度、小数位及合法边界；校验并发布。
4. 将已发布连续值集绑定到金额语义字段。
5. 创建范围因子：周期条件 + 金额 `BETWEEN` 条件，填写开始和结束值。
6. 编译并使用推荐或自定义周期试算，读取结果。
7. 创建同周期的无费用范围基线因子进行对照。
8. 确认范围因子结果不大于基线，且状态正常后发布。

**判定**：连续值集无枚举值项；费用条件引用当前已发布版本；范围区间按 `[start, end)`；范围结果与基线关系合理。

### 11.3 案例 C：模板实例化因子

**目标**：将通用的筛选逻辑发布为模板，再由业务用户填写参数创建实例因子。

1. 模板管理员创建参数化模板并发布版本。
2. 业务用户从已发布模板创建因子，填写唯一编码、名称和参数。
3. 核对确认信息后创建草稿。
4. 编译、试算（如需要）并发布实例。
5. 在模板实例列表中反查新建因子。

**判定**：实例参数、最终 DSL、来源模板版本和因子目录记录一致。

### 11.4 案例 D：场景版本闭环

**目标**：为多个已发布指标版本创建一个可审计的版本化场景。

1. 创建场景和首个草稿。
2. 编辑基础信息，关联已发布指标版本。
3. 新增合法 JSON 覆盖规则并保存草稿。
4. 查看合并预览，确认最终有效口径。
5. 校验并发布。
6. 返回目录确认状态与指标数。
7. 基于发布版本创建下一草稿，验证历史发布版本未被改写。

**判定**：校验失败时不可发布；发布后只读；旧 `resourceVersion` 保存能被正确识别为并发冲突。

## 12. 常见问题与状态判定

|现象|优先检查|处理建议|
|---|---|---|
|数据域或语义表下拉为空|来源是否同步、对象状态、权限|完成来源同步；确认可用状态；不要手输对象名|
|无法使用试算周期|默认时间字段|回到数据域工作台配置日期/日期时间字段|
|值集绑定窗口没有可选项|值集是否已发布、类型是否兼容|发布正确类型的值集后刷新|
|连续值集详情没有值项|值集类型|正常；检查连续值规范，不维护枚举项|
|范围条件无法填写或校验失败|字段绑定、数据类型、起止值、精度|确认已绑定连续值集，检查 `start < end` 和小数位|
|编译通过但试算无结果|任务状态、批次、周期、源数据状态|查询 taskId/batchId，区分无数据、失败和结果尚未读取|
|发布按钮不可用|编译、试算、结果读取、质量状态|逐项完成门禁，不绕过页面状态|
|分析页没有真实结果|指标是否发布、正式批次是否成功、周期是否正确|创建或等待正式结果；不能用试算结果替代|
|下钻页为空|正式结果、实际启用路径、根结果 ID、最大层级|从分析页重新进入；检查版本配置与 `nextLevels`|
|出现 `__UNASSIGNED__`|源数据维度编码|作为缺失维度归桶保留，修复源数据或标准化规则|
|保存场景返回 409|资源版本过期|刷新最新版本、比较修改、再提交|
|指标或因子不再可见|软删除或权限|检查回收站、删除影响和权限|

### 14.2 当前能力边界

- 批量导入、批量导出和 PDF 导出在页面中可能显示为不可用；不得将入口存在误判为功能已交付。
- 指标分析或排名页面可能存在演示数据标识；只有明确显示后端结果且能回溯到正式批次时，才可作为环境验收结果。
- 场景的全局选择器不等同于场景版本已经参与分析查询；以接口和页面实际联动为准。
- 场景合并预览是配置预览，不是指标结果试算。

### 14.3 后续维护规则

本文件是唯一的长期正文来源。新增或变更功能时遵循以下规则：

1. **新增独立能力**：在对应业务章节末尾新增小节；若无法归类，再在第 11 章新增案例。
2. **已有操作页面变化**：直接更新原操作步骤，不在文末追加一份相互矛盾的旧/新流程。
3. **接口变化**：先更新本页“接口基线”和速查表，再核对正文中的按钮、状态和门禁描述。
4. **历史样例变化**：更新独立验收记录或接口文档，不把新的固定 ID、IP 和结果数写入通用步骤。
5. **每次修改必填**：在下方变更记录增加日期、范围、接口基线、核验方式和负责人。
6. **页面核验**：涉及交互变更时，至少复核入口、按钮文案、禁用条件、成功回显和异常提示。
