# 看板目录重复分页 OOM 修复与验证

日期：2026-10-23。前端工作目录：`D:/IDMP-Frontend-warning-rules`，分支：`tat-dev`。

## 根因

`Dashboard.vue` 把 `fetchAllIndicators` 别名为 `fetchIndicators`，又在外层按页调用。被调用函数本身已加载全部页面，并返回数组；外层无法读到分页总数。当全量指标达到 100 条时，每轮都会再次追加全部指标，循环无法结束。当前环境有 101 条指标，能够复现。

旧全量接口还忽略第二个 options 参数，导致 `cache: 'no-store'` 未生效。缓存命中后，循环可以在微任务中快速增长数组并阻塞事件循环，最终导致 renderer OOM。不能用目录尚未完成加载时的早期内存快照判断页面稳定。

## 修复

- 看板删除外层目录分页，只调用一次 `fetchAllIndicators`，保留并发去重和整体替换目录。
- 全量指标接口透传 request options 到每一页。
- 公共分页器遇到连续完全重复的非空页立即拒绝，保留原有页码、空页和分页信息校验。
- 已发布因子目录改用公共分页器，修复服务端缩小页大小时提前结束的问题。
- SQL 导入的下钻路径目录改用公共分页器，避免独立分页缺少重复页保护。

对 `src/` 的 243 个 JS/Vue 文件进行了 AST 扫描，覆盖 24 个全量接口导入及别名，未发现另一个在分页循环中调用全量接口的调用点。新增回归测试持续检查该规则。

另外人工检查了科室字典、图表下钻、趋势与科室排名的分页循环：它们已有页码/编码去重/总数校验或明确页数、行数上限，不存在本次全量接口被再次分页的错误。
