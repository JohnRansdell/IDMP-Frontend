# IDMP 核心业务闭环完整操作展示样例

本文用于通过前端页面分业务复测 IDMP 当前已经接入的核心闭环。测试参数、接口状态和固定结果必须优先对齐根目录接口文档：

```text
IDMP 当前实现接口文档与测试样例（基于方案 revision 1036）.md
```

本文类比《场景管理核心闭环完整操作展示样例》的结构，把原来交叉在一起的复测步骤拆分为以下可以独立执行、独立留证和独立判定的业务闭环：

|闭环样例|起点|终点|主要证明内容|
|---|---|---|---|
|样例一：数据资产可计算闭环|来源元数据或已有数据域|默认时间语义字段可被编译器使用|物理表、语义表、语义字段与周期绑定准备完成|
|样例二：因子业务闭环|因子目录|因子版本发布|因子定义、编译、异步试算、结果读取与发布|
|样例三：指标业务闭环|指标目录|指标发布并登记回补|指标版本、Formula AST、编译、试算、发布门禁|
|样例四：指标分析闭环|已发布指标|趋势与维度结果可见|历史回补、正式结果、月/年趋势和科室对比|
|样例五：场景业务闭环|场景目录|场景版本发布与版本演进|指标集合、覆盖规则、合并预览、校验与发布|
|样例六：计算任务运维闭环|试算受理|任务或批次终态|taskId、batchId、节点、取消、失败重试与结果追溯|

首次验收建议按一至六顺序执行。日常回归可以只执行发生改动的闭环，但必须满足该闭环自己的前置条件。

本文同时保留两种测试方式：

```text
严格回归：使用 revision 1036 第 18、19 章已经生产实测的固定对象和 ID，不修改已发布版本。
从零演示：通过页面创建新对象，业务编码增加唯一后缀，所有新 ID 以后端实际返回为准。
```

严格回归与从零演示不能混用。相同数据快照下，严格回归结果应与接口文档一致；新建对象使用新 taskId、batchId 属于正常现象。

### 1.1 统一异步任务判断原则

试算返回 `QUEUED` 只表示后端已经受理，不表示计算成功。正确判断顺序是：

```text
提交试算
  → 记录 taskId 和 batchId
  → 查询任务或批次状态
  → 等待 SUCCEEDED / PARTIAL_SUCCEEDED / FAILED / CANCELED
  → 只有成功终态才读取并验收结果
```

页面提示“试算仍在处理中”时，应保留原 taskId、batchId 并稍后再次查看结果，不要立即重新创建因子、指标或重复发起多个批次。

### 1.2 统一留证要求

每个闭环至少保留：

1. 页面最终业务状态截图。
2. Network 中关键请求的方法、路径和 HTTP 状态。
3. 后端返回的主对象 ID、版本 ID、taskId、batchId。
4. 写操作前后的 `resourceVersion`。
5. 失败时的业务 code、message、traceId 和“最近一次后端请求”步骤。

`traceId` 是后端日志定位号，不是业务对象 ID。只记录 traceId 而不记录接口路径和操作步骤，无法有效定位问题。

# 样例一：数据资产可计算核心闭环

## M0.1 数据资产闭环目标

本闭环完整展示：

```text
同步来源元数据
  → 查看源表和物理字段
  → 创建数据域
  → 从已同步源表创建语义表
  → 建立物理字段到语义字段的映射
  → 指定默认业务时间字段
  → 在因子编辑器中按“数据域 → 语义表 → 字段”级联选择
  → 因子编译自动生成 period 绑定
```

这个闭环证明数据资产已经从“可以看到远程表”发展到“可以由业务因子按语义和统计周期安全引用”。

当前 M0 正式页面入口：

|页面|入口|路由|主要能力|
|---|---|---|---|
|来源元数据|数据治理 → 来源元数据|`/data/sources`|同步来源、查看源表目录和物理字段|
|数据域目录|数据治理 → 数据域|`/data/domains`|数据域查询、筛选和创建|
|数据域工作台|数据域目录 → 进入工作台|`/data/domains/{domainId}`|创建语义表、字段映射、默认时间字段|
|数据管理兼容页|数据治理 → 数据资产|`/data`|旧链路查询和开发验证工具，不是日常 M0 主入口|
|因子编辑器|指标配置 → 因子管理 → 新增/编辑|`/factor/edit/{id?}`|消费正式 M0 语义资产|

### M0.1.1 当前已实现范围

本次可以通过真实后端接口验收：

- 来源元数据同步及同步结果统计。
- 已发现源表目录、表名/类型/注释筛选。
- 单张源表物理字段查看。
- 数据域目录、状态筛选和数据域创建。
- 数据域工作台及多语义表显式选择。
- 从已同步源表创建语义表。
- 当前语义表内的物理字段与语义字段双栏映射。
- 语义编码、名称、数据类型、敏感标记配置。
- 从当前表已映射的 DATE/DATETIME 字段中指定默认时间字段。
- 因子编辑器严格执行数据域、语义表、语义字段三级级联。
- BIGINT ID 按字符串保真，查询使用请求版本号忽略过期响应，写操作防重复提交。

当前不在 M0 闭环验收范围：

- 数据源连接和密码配置。
- 采集任务、断点续传及来源结构差异对比。
- 语义字段删除、跨表移动和批量编辑。
- CODE 值集维护；后端未提供值集接口时页面不会伪造选项。
- 数据域、语义表的发布、停用、删除和影响分析。
- 域关系、Join 路径和完整血缘维护。

## M0.2 第一步：同步来源元数据

进入：

```text
左侧导航 → 数据治理 → 来源元数据
路由：/data/sources
```

页面顶部应显示“真实接口”，并出现：

```text
同步来源元数据
刷新目录
来源同步结果卡片
已发现源表目录
物理字段区域
```

点击“同步来源元数据”。页面先进行二次确认，再调用：

```http
POST /api/v1/meta/source-mappings/sync
```

同步期间按钮显示 loading，防止重复提交。成功后检查：

```text
1. 同步状态为成功。
2. 显示同步表数量 tableCount。
3. 显示同步字段数量 fieldCount。
4. 如果响应包含 tables，页面列出本次同步表名和各表字段数。
5. 源表目录自动或手动刷新后包含目标源表。
```

来源同步会更新后端技术元数据，不会创建数据域，也不会自动建立业务语义字段。

### M0.2.1 来源同步失败处理

页面区分未登录、无权限、后端/源数据库不可达和普通网络错误。如果出现：

```text
来源同步失败
服务内部错误 (traceId: ...)
```

处理顺序：

```text
1. 记录接口、HTTP 状态、发生时间和 traceId。
2. 点击“刷新目录”，确认后端是否已经保存过来源元数据。
3. 如果目标源表和字段已经存在，可以继续创建数据域和语义表。
4. 如果目标源表不存在，应先恢复远程源库连接或同步服务。
5. 不要因同步失败而反复创建相同编码的数据域。
```

严格回归时，来源同步不是每次必做步骤；只要 revision 1036 的数据域、语义表和字段已存在，就可以直接进行读取验证。

同步或刷新目录后，在筛选框输入：

```text
表名：vmq_deathpatientdetail
```

```text
源表名
表类型
表注释（后端未返回时显示 —）
字段数
```

```http
GET /api/v1/meta/source-tables/{tableName}/fields
```

确认物理字段表包含：


同理可以查询 `vmq_basicinformationba`，确认存在物理字段 `out_date`。

页面只展示后端返回的物理结构，不允许在这里修改远程只读源库字段。

### M0.4.2 从零演示：创建数据域

点击“新建数据域”，填写：

```text
数据域编码：M0_DEATH_DEMO_{唯一后缀}
```

成功后应出现：

## M0.5 第四步：进入数据域工作台并创建语义表

点击数据域行或“进入工作台”：

```text
/data/domains/{domainId}
```

页面首先显示数据域名称、编码、ID、说明、状态和创建时间，然后读取语义表：

```http
GET /api/v1/meta/data-domains/{domainId}/semantic-tables
```

语义表目录显示：

```text
语义表 ID
语义表编码和名称
来源物理表
源对象类型
默认时间字段
状态
```

### M0.5.1 多表数据域必须显式选择语义表

数据域存在多张语义表时，页面不会默认把第一张表作为字段来源。必须点击目标行或“选择”，让“当前语义表上下文”显示正确编码。

快速切换语义表时，页面通过请求版本号忽略过期响应，避免把上一张表的字段显示到当前表。验收时可以快速切换两张表，确认上下文和字段不串表。

### M0.5.2 创建语义表

从零演示的数据域初始没有语义表。点击“新建语义表”，页面加载已同步源表列表：

```http
GET /api/v1/meta/source-tables
```

填写：

```text
来源物理表：vmq_deathpatientdetail
语义表编码：DEATH_RECORD_DEMO_{唯一后缀}
语义表名称：死亡患者明细演示语义表
```

点击“确认创建”，二次确认后调用：

```http
POST /api/v1/meta/data-domains/{domainId}/semantic-tables
```

成功后页面刷新语义表并自动定位新对象。确认新语义表的 `sourceTableName` 为 `vmq_deathpatientdetail`。

如果来源物理表下拉框为空，应返回来源元数据页面完成同步；不要手工输入一个后端未发现的表名。

## M0.6 第五步：建立语义字段映射

选中语义表后，页面同时调用：

```http
GET /api/v1/meta/source-tables/{sourceTableName}/fields
GET /api/v1/meta/data-domains/{domainId}/semantic-tables/{tableCode}/semantic-fields
```

页面采用双栏结构：

|左侧：物理源字段|右侧：已映射语义字段|
|---|---|
|字段名、物理类型、已映射/未映射状态|来源字段、语义编码、语义名称、类型、敏感标记|

从左侧选择 `death_datetime`。页面会根据物理类型预推导语义类型，但验收人员仍需确认结果正确。填写：

```text
sourceFieldName：death_datetime（只读）
语义编码 code：DEATH_TIME
语义名称 name：死亡时间
数据类型 dataType：DATETIME
敏感字段 sensitive：否
```

点击“保存字段映射”：

```http
POST /api/v1/meta/data-domains/{domainId}/semantic-tables/{tableCode}/semantic-fields
```

请求业务字段等价于：

```json
{
  "sourceFieldName": "death_datetime",
  "code": "DEATH_TIME",
  "name": "死亡时间",
  "dataType": "DATETIME",
  "sensitive": false
}
```

保存成功后页面重新读取当前表字段。检查：

```text
1. 左侧 death_datetime 显示“已映射”。
2. 右侧出现 DEATH_TIME / 死亡时间 / DATETIME。
3. sourceFieldName 为 death_datetime；后端未返回来源时页面明确显示“未返回映射来源”，不会猜测。
4. 字段只属于当前选中的语义表，没有出现在其他表上下文。
```

允许的语义数据类型：

```text
STRING、INTEGER、DECIMAL、DATE、DATETIME、BOOLEAN、CODE
```

映射编辑不接受 SQL 或跨表字段。敏感字段应按业务实际情况标记，因子选择器会显示敏感标识，但字段脱敏仍需要后端权限体系配合。

### M0.6.1 建议补充的业务字段

为了让后续因子配置更可读，可根据源表实际字段继续映射患者、科室或记录标识。每次都必须从当前表左侧真实物理字段选择，不要仅凭接口文档猜测不存在的列。

本闭环最小通过只要求完成用于周期绑定的时间字段；具体计数因子如果使用 `COUNT(*)`，不强制映射统计对象字段。

## M0.7 第六步：配置默认时间字段

字段映射成功后，“默认时间字段”下拉框只列出当前语义表已经映射的 `DATE` 或 `DATETIME` 字段。

选择：

```text
DEATH_TIME（死亡时间）
```

点击“保存默认时间字段”：

```http
PATCH /api/v1/meta/data-domains/{domainId}/semantic-tables/{tableCode}/default-time-field
```

请求体等价于：

```json
{
  "semanticFieldCode": "DEATH_TIME"
}
```

成功后页面重新读取语义表，确认：

```text
1. 语义表列表“默认时间字段”显示 DEATH_TIME。
2. 当前语义表上下文显示 DEATH_TIME。
3. 刷新页面后配置仍然存在。
4. 其他语义表的默认时间字段没有被改变。
```

### M0.10.1 常见问题处理

|页面现象|一般原因|处理方式|
|---|---|---|
|来源同步 500/503|远程源库、数据库或同步服务不可用|记录 traceId；检查已有源表，恢复依赖后重试|
|源表目录为空|尚未同步或当前账号无查看权限|先同步；核对 401/403|
|新建语义表时来源下拉为空|没有已同步源表|回到来源元数据页面同步|
|创建数据域或语义表返回 409|业务编码重复|更换唯一后缀，不覆盖已有对象|
|物理字段加载失败|语义表保存的来源表名与已同步目录不一致|核对 sourceTableName|
|右侧显示“未返回映射来源”|后端语义字段响应缺少 sourceFieldName|记录接口响应，由后端补全；前端不跨表猜测|
|默认时间下拉为空|当前表没有 DATE/DATETIME 映射|先保存正确类型的时间语义字段|
|因子切换表后字段被清空|前端主动清理失效引用|在新表上下文重新选择，这是正确行为|
|CODE 字段没有值集选项|当前后端没有值集接口|记录能力边界，不能使用伪造选项|

## 11. 场景闭环目标与前置条件

完整字段解释可同时参考：

```text
./IDMP-Frontend/IDMP-Frontend/docs/场景管理核心闭环完整操作展示样例.md
```

前置条件：样例三已经发布至少一个指标版本。场景绑定的是确定的 `indicatorVersionId`，不是只有指标名称或指标主对象。

### 11.1 演示数据

|字段|演示值|业务含义|
|---|---|---|
|场景编码|`HQMS_REPORT_DEMO_{唯一后缀}`|租户内稳定且唯一的业务标识|
|场景名称|HQMS 医疗质量月报演示场景|业务人员可读名称|

## 12. 第一步：进入目录并创建场景

进入：

```text
左侧导航 → 指标配置 → 场景管理
路由：/scenarios
```

页面应显示场景编码、名称、类型和版本状态筛选，以及“新建场景”按钮。目录查询对应：

```http
GET /api/v1/scenarios?page=1&size=20
```

点击“新建场景”，填写 11.1 的数据，点击“创建并编辑”：

```http
POST /api/v1/scenarios
```

成功后页面进入：

```text
/scenarios/{scenarioId}/edit?versionId={versionId}
```

记录：

```text
scenarioId
versionId
versionNo=1
publicationStatus=DRAFT
resourceVersion
```

如果返回 409 编码重复，应修改编码后缀，不要覆盖已有场景。

## 13. 第二步：配置基本信息和指标集合

在“基本信息”页签填写主管部门、默认周期、生效日期和说明。默认排除规则填写：

```json
{
  "nodeType": "TRUE"
}
```

`TRUE` 表示场景默认层不额外排除数据，不代表校验已经通过。

进入“关联指标”页签，搜索并选择样例三发布的住院死亡率版本。设置：

```text
必选：开启
上报要求：每月 10 日前完成上月数据上报
```

如果下拉框为空，应返回指标闭环确认是否至少存在一个 `PUBLISHED` 指标版本，不要继续空场景发布。

## 14. 第三步：配置覆盖规则

进入“覆盖规则”，点击“新增覆盖”，填写：

```text
作用范围：刚才关联的指标版本
类型：参数
目标路径：/period/granularity
覆盖值："MONTHLY"
优先级：10
```

覆盖值输入的是 JSON。`"MONTHLY"` 是合法 JSON 字符串，未加双引号的 `MONTHLY` 不是合法 JSON。

覆盖只影响当前场景下的最终有效配置，不会修改指标原始版本，也不会影响其他场景。后端还会检查指标的覆盖策略是否允许修改该路径。

## 15. 第四步：保存草稿并检查乐观锁

点击“保存草稿”。前端按顺序提交：

```http
PATCH /api/v1/scenario-versions/{versionId}
PUT   /api/v1/scenario-versions/{versionId}/indicators
PUT   /api/v1/scenario-versions/{versionId}/overrides
```

三个请求分别保存基本信息、完整指标集合和完整覆盖集合。成功后顶部 `resourceVersion` 应递增。

如果返回 409，表示其他窗口或用户已经修改同一版本。应重新加载服务端最新版本，不要用旧 `resourceVersion` 连续重试。

## 16. 第五步：查看合并后的有效口径

点击：

```text
合并预览 → 刷新预览
```

对应：

```http
GET /api/v1/scenario-versions/{versionId}/merged-preview
```

展开住院死亡率，检查后端返回的最终配置至少能表达：

```json
{
  "effectiveParameters": {
    "period": {
      "granularity": "MONTHLY"
    }
  }
}
```

预览还可能包含 `formulaDefinition`、`effectiveExclusionDsl`、`effectiveDataSourcePriority`、展示规则和阈值规则。合并预览只计算配置，不触发正式指标计算。

## 17. 第六步：执行校验并发布

点击“校验”：

```http
POST /api/v1/scenario-versions/{versionId}/validate
```

校验通过至少证明：

1. 场景版本仍为可发布草稿。
2. 至少关联一个有效的已发布指标版本。
3. 生效日期范围合法。
4. 排除 DSL 可以解析。
5. 覆盖路径和值符合指标允许的覆盖策略。
6. 校验结果对应最新 `resourceVersion`。

任何配置修改都会使旧校验结论失效。修改后必须重新执行“保存草稿 → 合并预览 → 校验”。

校验通过后点击“发布”：

```http
POST /api/v1/scenario-versions/{versionId}/publish
```

成功后页面应显示 `PUBLISHED`、进入只读状态，并且场景主对象的 `currentPublishedVersionId` 指向当前版本。

## 18. 第七步：创建下一草稿版本

回到场景目录，找到刚发布的场景，点击“新版本”。前端基于当前发布版本的 `copyFromVersionId` 创建新草稿。

页面应证明：

```text
1. 新版本号递增，状态为 DRAFT。
2. 原版本保持 PUBLISHED 和只读。
3. 指标集合和覆盖规则按服务端复制结果回显。
4. 对新草稿的修改不改变当前发布版本。
```

## 19. 场景闭环验收标准

```text
1. 场景和首个草稿版本创建成功。
2. 场景绑定的是已发布指标版本 ID。
3. 基本信息、指标集合和覆盖集合保存成功。
4. 合并预览能看到覆盖后的最终口径。
```

# 样例六：计算任务运维核心闭环

## 20. 计算任务闭环目标

本闭环完整展示：

```text
因子或指标试算受理
  → 获得 taskId 和 batchId
  → 查询异步任务
  → 查询计算批次、目标和节点
  → 成功时追溯结果集
  → 失败时查看错误并重试节点
  → 未结束时按权限取消批次
```

## 21. 第一步：进入计算任务中心

进入：

```text
左侧导航 → 计算运行 → 计算任务
路由：/calc
```

使用样例二或样例三本次操作新产生的 taskId、batchId。文档中的历史批次只用于严格回归，不能代表本次新试算状态。

## 22. 第二步：查询异步任务

```http
GET /api/v1/async-tasks/{taskId}
```

状态处理：

|状态|含义|下一步|
|---|---|---|
|QUEUED|已受理，等待 Worker|继续轮询|
|RUNNING|正在执行|继续轮询，观察更新时间|
|SUCCEEDED|任务成功|查询批次和结果|
|PARTIAL_SUCCEEDED|部分目标成功|检查失败目标和节点|
|FAILED|任务失败|记录错误与 traceId，检查节点|
|CANCELED/CANCELLED|任务已取消|不能作为有效结果继续发布|

## 23. 第三步：查询批次、目标和节点

```http
GET /api/v1/calc/batches/{batchId}
```

页面应展示或可以追溯：

```text
批次类型和状态
创建、开始、完成时间
目标对象 ID 和目标状态
DAG 节点 ID、类型和状态
失败节点错误码、错误信息
结果集或快照引用
```

任务显示成功但结果为空时，重点核对 batchId 是否属于当前因子/指标版本，以及结果集是否已经进入 `READY`。

## 24. 第四步：取消批次或重试失败节点

未结束批次可按权限取消：

```http
POST /api/v1/calc/batches/{batchId}/cancel
```

失败节点可重试：

```http
POST /api/v1/calc/nodes/{nodeId}/retry
```

重试前必须确认节点状态为 `FAILED`，并记录第一次失败的 traceId 和错误信息。不要对仍在 `RUNNING` 的节点重复触发。

## 25. 计算任务闭环验收标准

```text
1. 试算受理后能获得 taskId 和 batchId。
2. 页面能区分受理状态与计算终态。
3. 能从批次定位目标和节点。
4. 成功任务能关联到 READY 结果集。
5. 失败任务能显示可用于排查的错误信息。
6. 取消和节点重试受状态与权限约束。
```

# 27. 跨闭环完整回归路线与异常处理

## 27.1 推荐执行顺序

首次完整验收建议按以下顺序执行并传递真实 ID：

```text
1. 数据资产可计算闭环
   确认物理表、数据域、语义表、默认时间字段和 period 绑定。

2. 因子业务闭环
   创建并发布死亡患者数、出院人次等因子版本。

3. 指标业务闭环
   使用已发布 factorVersionId 创建指标，完成编译、试算和发布。

4. 指标分析闭环
   等待回补结果激活，验证指定月份、月度趋势、年度趋势和维度对比。

5. 场景业务闭环
   使用已发布 indicatorVersionId 创建场景，完成覆盖、预览、校验和发布。

6. 计算任务运维闭环
   使用前述 taskId、batchId 验证任务、批次、节点和结果可追溯。
```

跨闭环的 ID 传递关系：

```text
dataDomainId / semanticTableCode
  → factorVersionId
  → Indicator Formula AST.factorVersionId
  → indicatorVersionId
  → Scenario indicator binding.indicatorVersionId
  → taskId / batchId
  → resultSetId / snapshotId
```

名称只用于页面识别，不能替代稳定业务编码和后端 ID 作为验收证据。

## 27.2 常见异常处理

|HTTP 或现象|一般含义|正确处理|必须记录|
|---|---|---|---|
|400|字段格式、JSON、日期或枚举错误|修正输入后重新提交|请求体、message、traceId|
|401|未登录或令牌失效|重新登录后复测|接口路径、发生时间|
|403|缺少接口、对象或数据范围权限|更换授权账号或申请权限|账号、权限点、traceId|
|404|对象不存在或当前用户不可见|确认部署环境和 ID|请求路径、业务编码、ID|
|409|编码重复、乐观锁或状态冲突|编码增加后缀；刷新 resourceVersion；确认状态|旧/新 resourceVersion、traceId|
|422|DSL、公式、依赖或发布门禁未通过|按 diagnostics 修正业务配置|diagnostics、traceId|
|500|未预期后端异常|停止重复创建，按 traceId 查日志|接口、时间、traceId|
|503|数据库、Worker 或外部依赖暂不可用|恢复依赖后复用原业务对象重试|依赖、taskId、traceId|
|请求超时|客户端不知道最终结果|先刷新资源状态，再复用同一幂等键重试|接口、幂等键、开始时间|
|长期 QUEUED|Worker 未领取或队列拥堵|到计算任务中心查询原 taskId|taskId、更新时间|
|长期 RUNNING|节点 SQL 慢、锁等待或 Worker 异常|查询批次和节点，不要重复发起多个试算|batchId、nodeId、节点状态|

# 附录 B：已有指标与因子的编辑持久化验收

## B.1 编辑已有因子

1. 进入“指标配置 → 因子管理”，确认页面显示“列表来自后端因子接口”，不能使用演示目录。
2. 找到目标因子后点击“编辑”。页面应回填因子编码、名称、分类、说明和版本 DSL；因子编码为只读。
3. 修改名称、业务分类、说明或统计口径，点击“保存修改”。
4. 页面应提示“因子修改已保存”，并发起：

```text
PATCH /api/v1/factors/{factorId}
```

5. 刷新页面并重新进入该因子，确认修改后的字段和 DSL 均被回填。若接口返回 409，刷新后按页面提示重新保存。

## B.2 编辑已有指标

1. 进入“指标配置 → 指标管理”，确认页面显示“接口数据”，按编码定位目标指标，点击“编辑”。
2. 修改指标名称、分类、定义、指标意义、统计周期或数据来源，点击“保存基本信息”。
3. 页面应提示“指标基本信息已更新”，并发起：

```text
PUT /api/v1/indicators/{indicatorId}
```

4. 如需修改公式，在“基础与版本”点击“为当前指标创建草稿版本”。页面应发起：

```text
POST /api/v1/indicators/{indicatorId}/versions
{ "copyFromVersionId": "{currentVersionId}" }
```

5. 进入“公式与试算”，调整因子引用后点击“保存公式”；页面应发起：

```text
PUT /api/v1/indicator-versions/{draftVersionId}/formula
```

6. 已发布版本不可直接保存公式；应先创建草稿版本。保存成功后刷新编辑页，确认基础信息与公式都从后端重新回填。
