## 仍未通过及未验收项

1. **定时自动派发未通过。** 新建月、季、年三个 20 秒 cron 验收计划，到期观察 55 秒，均没有 `lastTriggerAt`。worker 的 PowerJob 参与和计划处理器默认关闭，当前进程未提供相应启用配置。PowerJob 服务 7700 端口在监听，但 worker 27777 未监听。本轮没有直接启用全局派发，以免执行已有逾期计划、改写历史结果。三个验收计划均已暂停。必须单独处理既有计划后，才能完成部署级调度验收；配置保存成功不能算自动执行成功。
2. **冻结历史转科结果的同编码名称分支仍有去重限制。** 一月五个科室存在同编码不同名称分支。例如 9011 的分支人次相加为 319，按科室编码重新去重为 317。每个冻结分支与源库按 code+name 的统计相符，但不能把分支相加称为精确去重汇总。遵守不替换原正式结果的边界，本轮未重算这些历史数据。
3. **外部系统与角色边界。** 医务 token 使用本地模拟校验接口，不能代表真实医务系统已联调；企业微信、钉钉真实送达没有配置验收。本轮站内通知闭环使用隔离的质量管理员接收账号，不代表所有科室角色均已开放通知/试算等操作；现有不支持安全科室过滤的操作仍按设计拒绝。
4. **未穷举的测试。** 百兆文件边界/断网恢复、长时高并发、所有 UI CRUD 路径各三完整交互、所有历史版本组合均未完全覆盖。`IdmpApplicationTests.contextLoads` 未连接本机默认业务库执行；特殊源库/迁移库测试和原有条件跳过用例单独列账，不计为通过。

## 复跑入口

这些是会写入隔离测试资源的真实环境测试，**不是日常无副作用单元测试**。先准备管理员凭据 JSON（`username/password`），仅放在 Git 忽略路径；确认目标是测试环境，源库账号只读，SSH 检查工具可用。不要并发执行会写同一个 `resources.json` 的套件，也不要把已有前缀的历史正式结果作为重跑覆盖目标。

公共配置：`IDMP_SYSTEM_API`、`IDMP_FRONTEND_URL`、`IDMP_ADMIN_CREDENTIAL_FILE`、`IDMP_AUDIT_FOLDER`。Playwright 优先从项目依赖加载；非标准依赖位置可设 `IDMP_PLAYWRIGHT_PACKAGE` 为可解析该包的 package.json 路径；`CHROME_PATH` 可指定浏览器。

执行顺序：

1. `comprehensive-system.live.mjs`：目录、分页、因子、值集、文件、指标、看板等，具体模式见脚本分支。
2. `comprehensive-governance.live.mjs`：治理、模板、场景、政策、预警、回收站、调度、导入。
3. `comprehensive-workflows.live.mjs`：映射、看板版本、取消重试。
4. `comprehensive-warning-events.live.mjs`：非法范围回归及真实预警闭环。
5. `comprehensive-additional.live.mjs`：关联路径、参数、目标值报告、复合因子、会话安全。定时触发模式只在明确隔离调度环境使用。
6. `comprehensive-numerical.live.mjs`、`comprehensive-browser.live.mjs`、`comprehensive-interactions.live.mjs`、`comprehensive-filter-ui.live.mjs`、`comprehensive-detail-ui.live.mjs`、`comprehensive-responsive.live.mjs`：数值与页面复核。
7. `comprehensive-cleanup.live.mjs`：核验本轮计划、规则、用户、看板的最终状态，不触碰其他前缀资源。

每份 JSON 的 `checks` 含断言和失败详情，`calls` 仅含方法、路径、状态及耗时，不含令牌。不同阶段存在重复断言、旧脚本契约错误和修复前探测，不应把所有文件简单相加后声称“全系统通过”。
