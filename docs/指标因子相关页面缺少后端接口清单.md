# 指标管理、指标分析、因子管理页面缺少后端接口清单

本文仅整理当前前端页面中与 **指标管理**、**指标分析**、**因子管理** 相关的后端接口缺口。依据《医疗质量指标数据管理平台(IDMP)_系统架构与详细设计.md》中的指标目录、因子版本、发布状态、权限、审计、分析应用等设计要求整理。

## 1. 指标管理页面

当前指标管理页面已经接入部分接口：

```text
GET  /api/v1/indicators
POST /api/v1/indicators
POST /api/v1/indicators/{id}/versions
PUT  /api/v1/indicator-versions/{id}/formula
POST /api/v1/indicator-versions/{id}/formula/compile
POST /api/v1/indicator-versions/{id}/trial
GET  /api/v1/indicator-versions/{id}/trials/{batchId}/results
```

但距离完整指标管理流程，还缺以下接口。

### 1.1 指标目录筛选与字典接口

用于支撑指标列表中的分类、来源、状态、标签等筛选项。

```text
GET /api/v1/indicator-categories
GET /api/v1/indicator-data-sources
GET /api/v1/indicator-tags
GET /api/v1/indicator-status-options
```

也可以采用统一字典接口：

```text
GET /api/v1/system/dictionaries?types=indicator_category,data_source,indicator_status,indicator_direction,period_type
```

用途：

- 指标目录中的分类不再由前端写死。
- 指标数据来源不再由前端写死。
- 指标状态、统计周期、指标方向等选项由后端统一维护。
- 支持后续后台字典配置和权限控制。

### 1.2 指标详情与编辑接口

用于查看和编辑已有指标。

```text
GET   /api/v1/indicators/{id}
PATCH /api/v1/indicators/{id}
```

用途：

- 点击指标列表中的“查看”能够进入真实详情。
- 点击“编辑”能够回显已有指标基本信息。
- 支持修改指标名称、分类、数据来源、定义、说明、统计周期等元数据。
- 页面刷新后可重新从后端加载当前指标，而不是依赖前端内存状态。

### 1.3 指标版本管理接口

用于支撑指标的草稿、历史版本、已发布版本、停用、归档等生命周期。

```text
GET  /api/v1/indicators/{id}/versions
GET  /api/v1/indicator-versions/{versionId}
POST /api/v1/indicator-versions/{versionId}/publish
POST /api/v1/indicator-versions/{versionId}/disable
POST /api/v1/indicator-versions/{versionId}/archive
```

用途：

- 查看一个指标下的全部版本。
- 打开指标编辑页时加载当前草稿版本或已发布版本。
- 支持指标版本发布。
- 支持停用或归档旧版本。
- 保证已发布版本不可直接编辑。

建议版本状态：

```text
DRAFT
WAIT_TRIAL
TRIALING
TRIAL_PASS
TRIAL_FAIL
PUBLISHED
DISABLED
ARCHIVED
```

### 1.4 指标公式详情回显接口

用于打开已有指标版本时回显公式 AST 和展示配置。

```text
GET /api/v1/indicator-versions/{versionId}/formula
```

用途：

- 编辑已有指标版本时回显公式。
- 展示分子、分母、因子引用、展示格式、分母为零策略等配置。
- 支持前端公式编辑器恢复真实后端状态。

### 1.5 指标发布门禁接口

用于发布前检查是否满足发布条件。

```text
GET  /api/v1/indicator-versions/{versionId}/publish-check
POST /api/v1/indicator-versions/{versionId}/publish
```

用途：

- 检查公式是否已保存。
- 检查公式是否已编译通过。
- 检查最近一次试算是否成功。
- 检查引用的因子版本是否已发布。
- 检查 artifactHash 是否过期。
- 检查当前用户是否有发布权限。
- 返回不可发布原因，供前端展示。

示例返回：

```json
{
  "publishable": false,
  "checks": [
    {
      "code": "FORMULA_COMPILED",
      "passed": true,
      "message": "公式已编译通过"
    },
    {
      "code": "TRIAL_PASSED",
      "passed": false,
      "message": "尚未完成成功试算"
    }
  ]
}
```

### 1.6 指标删除、停用与引用检查接口

详细设计要求已发布版本、正式结果、审计记录不得物理删除。因此删除前需要检查。

```text
GET    /api/v1/indicators/{id}/delete-check
DELETE /api/v1/indicators/{id}
POST   /api/v1/indicators/{id}/disable
POST   /api/v1/indicators/{id}/archive
GET    /api/v1/indicators/{id}/references
```

用途：

- 判断指标是否允许删除。
- 判断指标是否已发布。
- 判断指标是否被看板、场景、映射、分析页引用。
- 判断指标是否已有正式计算结果。
- 判断当前用户是否具备删除权限。
- 如果不能删除，返回明确原因。

示例返回：

```json
{
  "deletable": false,
  "reasons": [
    "指标已有已发布版本",
    "指标被质量看板引用",
    "当前用户缺少 indicator:delete 权限"
  ]
}
```

### 1.7 指标权限接口

用于按钮级权限控制。

```text
GET /api/v1/auth/me
GET /api/v1/system/permissions/me
GET /api/v1/system/permission-check?permissions=indicator:view,indicator:create,indicator:edit,indicator:delete,indicator:publish
```

用途：

- 判断当前用户能否新增指标。
- 判断当前用户能否编辑指标。
- 判断当前用户能否删除指标。
- 判断当前用户能否发布指标版本。
- 前端根据权限显示、禁用或隐藏按钮。

## 2. 因子管理页面

当前因子新增、校验、试算、查看结果、发布链路已经接入部分接口：

```text
POST /api/v1/factors
POST /api/v1/factor-versions/{id}/compile
GET  /api/v1/compile-artifacts/{id}
POST /api/v1/factor-versions/{id}/trial
GET  /api/v1/factor-versions/{id}/trials/{batchId}/results
POST /api/v1/factor-versions/{id}/publish
GET  /api/v1/meta/data-domains
GET  /api/v1/meta/data-domains/{domainId}/semantic-fields
```

但因子管理页面中的因子列表、详情、编辑、版本管理仍缺少接口。

### 2.1 因子列表接口

当前 `F-001`、`F-002` 等因子仍是前端演示数据，需要后端提供真实列表。

```text
GET /api/v1/factors
```

建议支持查询参数：

```text
GET /api/v1/factors?code=&name=&category=&status=&domainCode=&page=1&size=20
```

用途：

- 因子管理页展示真实后端因子。
- 支持按编码、名称、分类、状态、数据域筛选。
- 支持分页。
- 支持展示发布状态、引用次数、更新时间、创建人。

### 2.2 因子详情与编辑接口

```text
GET   /api/v1/factors/{id}
PATCH /api/v1/factors/{id}
```

用途：

- 点击因子列表中的“查看”能进入真实详情。
- 点击“编辑”能回显已有因子基本信息。
- 支持修改因子名称、说明、分类等元数据。
- 页面刷新后可重新加载后端数据。

### 2.3 因子版本管理接口

```text
GET   /api/v1/factors/{id}/versions
GET   /api/v1/factor-versions/{versionId}
POST  /api/v1/factors/{id}/versions
PATCH /api/v1/factor-versions/{versionId}
POST  /api/v1/factor-versions/{versionId}/disable
POST  /api/v1/factor-versions/{versionId}/archive
```

用途：

- 查看因子的历史版本。
- 查看当前草稿版本、已发布版本。
- 基于已发布版本创建新草稿。
- 编辑草稿版本 DSL。
- 回显因子编辑页中的计算口径配置。
- 支持停用、归档因子版本。
- 保证已发布版本不可直接编辑。

### 2.4 因子 DSL 详情回显接口

```text
GET /api/v1/factor-versions/{versionId}/dsl
```

用途：

- 因子编辑页打开已有版本时，能回显数据域、统计方式、过滤条件、分组维度。
- 支持从后端 DSL 还原到前端“计算口径配置”。
- 支持用户查看系统生成的 DSL。

### 2.5 因子发布门禁接口

当前已有发布接口，但还缺发布前检查。

```text
GET  /api/v1/factor-versions/{versionId}/publish-check
POST /api/v1/factor-versions/{versionId}/publish
```

用途：

- 检查 DSL 是否已校验通过。
- 检查是否有可用 compile artifact。
- 检查最近一次试算是否成功。
- 检查 artifact 是否过期。
- 检查当前用户是否有发布权限。
- 返回不能发布的原因。

### 2.6 因子删除、停用与引用检查接口

因子可能被指标公式引用，不能直接删除。

```text
GET    /api/v1/factors/{id}/delete-check
DELETE /api/v1/factors/{id}
POST   /api/v1/factors/{id}/disable
POST   /api/v1/factors/{id}/archive
GET    /api/v1/factors/{id}/references
GET    /api/v1/factor-versions/{versionId}/references
```

用途：

- 判断因子是否允许删除。
- 判断因子版本是否已发布。
- 判断因子是否被指标公式引用。
- 判断因子是否已有计算快照。
- 判断当前用户是否具备删除权限。
- 删除前向用户展示影响范围。

示例返回：

```json
{
  "deletable": false,
  "reasons": [
    "因子版本已发布",
    "因子被 3 个指标公式引用",
    "当前用户缺少 factor:delete 权限"
  ],
  "references": [
    {
      "type": "INDICATOR_FORMULA",
      "id": "10001",
      "name": "住院死亡率"
    }
  ]
}
```

### 2.7 可引用因子版本接口

指标公式编辑器需要选择已发布因子版本。

```text
GET /api/v1/factor-versions/published
```

或：

```text
GET /api/v1/factors?status=PUBLISHED&includeVersions=true
```

用途：

- 指标公式只能引用已发布因子版本。
- 前端展示因子名称、版本号、单位、量纲、粒度。
- 公式校验前可以做基础提示。

建议返回字段：

```json
{
  "factorId": "10001",
  "factorCode": "INPATIENT_DEATH_COUNT",
  "factorName": "住院死亡记录数",
  "versionId": "20001",
  "versionNo": "v1",
  "status": "PUBLISHED",
  "output": {
    "valueType": "DECIMAL",
    "dimension": "COUNT",
    "unit": "PERSON_TIME",
    "grain": ["HOSPITAL", "DEPARTMENT"]
  }
}
```

### 2.8 因子权限接口

```text
GET /api/v1/system/permission-check?permissions=factor:view,factor:create,factor:edit,factor:delete,factor:compile,factor:trial,factor:publish
```

用途：

- 判断当前用户是否能新增因子。
- 判断当前用户是否能编辑因子。
- 判断当前用户是否能删除因子。
- 判断当前用户是否能校验、试算、发布因子版本。

## 3. 指标分析页面

当前指标分析页面已经支持从看板跳转、选择指标分析配置，并对住院死亡率等核心指标接入部分结果链路。但要满足详细设计中 M8 分析应用能力，还缺以下接口。

### 3.1 指标分析配置列表接口

```text
GET /api/v1/analysis/indicators
```

或复用：

```text
GET /api/v1/indicators?analysisEnabled=true
```

用途：

- 指标分析页下拉框中的可选指标来自后端。
- 区分哪些指标已经有分析配置。
- 支持按分类、场景、数据来源筛选可分析指标。

### 3.2 指标分析总览接口

```text
GET /api/v1/analysis/indicators/{indicatorId}/overview
```

建议支持参数：

```text
GET /api/v1/analysis/indicators/{indicatorId}/overview?periodStart=&periodEnd=&orgCode=&scenarioId=
```

用途：

- 返回指标当前值、同比、环比、质量状态、预警状态。
- 支持指标分析页顶部核心卡片。
- 避免每个指标分析页由前端硬编码。

### 3.3 趋势分析接口

```text
GET /api/v1/analysis/indicators/{indicatorId}/trend
```

建议参数：

```text
periodType=MONTH|QUARTER|YEAR
periodStart=
periodEnd=
orgCode=
scenarioId=
```

用途：

- 指标趋势折线图。
- 月度、季度、年度趋势。
- 支持不同机构、场景过滤。

### 3.4 维度对比接口

```text
GET /api/v1/analysis/indicators/{indicatorId}/dimension-comparison
```

建议参数：

```text
dimension=DEPARTMENT|WARD|DOCTOR|DISEASE|ORG
periodStart=
periodEnd=
```

用途：

- 科室对比。
- 病区对比。
- 医生对比。
- 病种对比。
- 排名条形图、对比表格。

### 3.5 构成分析接口

```text
GET /api/v1/analysis/indicators/{indicatorId}/composition
```

用途：

- 饼图、环图、构成分布。
- 展示不同科室、病区、病例类型、风险等级的占比。

### 3.6 下钻接口

详细设计中 M8 要求支持时间、组织、病种、因子、场景多维下钻。

```text
GET  /api/v1/analysis/indicators/{indicatorId}/drill-paths
POST /api/v1/analysis/indicators/{indicatorId}/drill
```

用途：

- 查询当前指标支持哪些下钻路径。
- 从全院下钻到科室。
- 从科室下钻到患者明细。
- 从指标结果下钻到分子/分母因子结果。
- 保持面包屑和上下文。

### 3.7 明细列表接口

```text
GET /api/v1/analysis/indicators/{indicatorId}/records
```

建议参数：

```text
periodStart=
periodEnd=
orgCode=
departmentCode=
dimension=
page=1
size=20
```

用途：

- 下钻后的患者或记录明细列表。
- 支持分页。
- 支持权限控制和脱敏。

### 3.8 血缘与解释接口

```text
GET /api/v1/analysis/indicators/{indicatorId}/lineage
GET /api/v1/analysis/indicators/{indicatorId}/explain
```

用途：

- 展示指标由哪些因子构成。
- 展示分子、分母、公式、统计周期、过滤条件。
- 展示当前结果来自哪个计算批次、哪个版本、哪个快照。
- 支持问题追溯。

### 3.9 预警与异常接口

```text
GET /api/v1/analysis/indicators/{indicatorId}/warnings
GET /api/v1/analysis/indicators/{indicatorId}/quality-status
```

用途：

- 展示指标是否超阈值。
- 展示趋势波动异常。
- 展示质量校验状态。
- 支持指标分析页预警区域。

### 3.10 导出接口

```text
POST /api/v1/analysis/indicators/{indicatorId}/export
GET  /api/v1/export-tasks/{taskId}
```

用途：

- 导出指标分析报表。
- 导出下钻明细。
- 支持 Excel/PDF/Word。
- 异步查询导出任务状态。

### 3.11 指标分析权限接口

```text
GET /api/v1/system/permission-check?permissions=analysis:dashboard:view,analysis:drill:view,analysis:lineage:view,analysis:export
```

用途：

- 控制是否能查看分析页。
- 控制是否能下钻到患者明细。
- 控制是否能查看血缘。
- 控制是否能导出。

```text
GET /api/v1/factors
GET /api/v1/factors/{id}
GET /api/v1/factors/{id}/versions
GET /api/v1/factor-versions/{versionId}

GET /api/v1/indicators/{id}
GET /api/v1/indicators/{id}/versions
GET /api/v1/indicator-versions/{versionId}

GET /api/v1/indicator-categories
GET /api/v1/indicator-data-sources
GET /api/v1/factor-categories

GET /api/v1/factor-versions/published
```

### 第二优先级：支撑完整创建、发布、停用流程

```text
GET  /api/v1/indicator-versions/{versionId}/publish-check
POST /api/v1/indicator-versions/{versionId}/publish

GET  /api/v1/factor-versions/{versionId}/publish-check
POST /api/v1/factor-versions/{versionId}/disable

```

```text
GET    /api/v1/factor-versions/{versionId}/references

GET /api/v1/auth/me
GET /api/v1/system/permissions/me
GET /api/v1/system/permission-check
```

### 第四优先级：支撑完整指标分析

```text
GET  /api/v1/analysis/indicators
```
