# 端到端页面可见测试操作指导

本文只说明如何通过前端页面复测 IDMP 端到端链路。测试参数必须优先对齐根目录接口文档：

```text
IDMP 当前实现接口文档与测试样例.md
```

本指导以该接口文档第 18 章“住院死亡率：语义时间字段完整链路实测（包括指标分析）（2026-07-27）”为主线。除非页面必须新建对象，否则不要自行编造业务编码、字段编码、时间范围或结果预期。


### 2.1 来源映射同步说明

接口文档中 `POST /api/v1/meta/source-mappings/sync` 是远程源库技术元数据同步接口，不是第 18 章已发布实测链路的必经前置。

如果点击“同步来源映射”后出现：

```text
服务内部错误 (traceId: ...)
```

处理方式：

```text
1. 记录 traceId，供后端排查远程源库连接或同步任务日志。
2. 点击“刷新数据域”。
3. 如果两个 MORTALITY_V2_* 数据域和 DEATH_TIME / DISCHARGE_TIME 字段已存在，可以继续后续测试。
4. 如果两个 MORTALITY_V2_* 数据域不存在，不要改用 INPATIENT_* 数据自造主流程，应先按接口文档第 18 章准备数据资产或让后端排查。
```

### 2.2 不要用旧参数替代严格复测参数

以下对象属于旧链路或兼容链路，不作为第 18 章严格复测的主验收对象：

```text
INPATIENT_DEATH_RECORD
INPATIENT_DISCHARGE_RECORD
DEATH_DATETIME
OUT_DATE
```

只有在明确做“兼容旧链路验证”时，才使用上述对象。

## 7. 指标发布与分析

接口文档第 18.4 节发布接口：

```text
POST /api/v1/indicator-versions/101996817981380254/publish
```

当前前端发布按钮的实际行为：

```text
用户点击“发布指标版本”后，前端按“缺哪步补哪步”的方式处理。
如果用户已经在“公式与试算”中完成“发起试算”和“查看结果”，点击发布时不会再次保存公式、编译、试算或读取结果。

仅当前置状态缺失时，前端才自动补齐：
1. 缺公式时，将公式引用切换为接口文档第 18 章实测通过的两个已发布因子版本：
   分子 101996817981379998，分母 101996817981380000。
2. 缺公式时，调用 GET /api/v1/indicator-versions/{id} 刷新最新 resourceVersion。
3. 缺公式时，调用 PUT /api/v1/indicator-versions/{id}/formula 保存公式。
4. 缺编译时，调用 POST /api/v1/indicator-versions/{id}/formula/compile 编译公式。
5. 缺试算批次时，调用 POST /api/v1/indicator-versions/{id}/trial 发起试算，默认周期为 2026-03-01T00:00:00 到 2026-04-01T00:00:00。
6. 缺试算结果时，调用 GET /api/v1/indicator-versions/{id}/trials/{batchId}/results 读取试算结果。
7. 前置状态具备后，调用 POST /api/v1/indicator-versions/{id}/publish，发布接口请求体仍为 {}。
```

页面可见检查点：

```text
1. 在“公式与试算”页签点击“发布指标版本”。
2. 如果此前已经看到试算结果 0.26% 或等价展示，页面“最近一次后端请求”应直接进入发布指标版本。
3. 如果此前未保存公式，自动保存公式后，页面中的分子因子应显示 101996817981379998。
4. 如果此前未保存公式，自动保存公式后，页面中的分母因子应显示 101996817981380000。
5. 如果此前未查看结果，自动查看结果成功后，页面应显示试算结果 0.26% 或等价展示。
6. 发布成功后，页面显示“指标版本已发布”或发布状态 PUBLISHED。
```

乐观锁处理说明：

```text
如果页面曾出现“指标版本已被修改，请刷新后重试”，这是 resourceVersion 乐观锁冲突。
当前前端已在保存公式前、编译前、发布前自动刷新 GET /api/v1/indicator-versions/{id}。
如果保存公式或发布时仍遇到一次 409 乐观锁错误，前端会自动刷新后重试一次。
用户只需观察页面最终是否显示发布成功；如果第二次仍失败，记录页面展示的 traceId。
```

服务内部错误处理说明：

```text
如果点击发布后页面提示“服务内部错误 (traceId: ...)”，说明请求已经到达后端，但后端内部执行失败。
这类错误不能通过 Network 面板作为验收依据，也不是前端页面可自行确认通过的状态。
页面验收时应记录 traceId，并以页面显示的错误提示作为失败证据，交由后端排查日志。
```

发布成功的页面预期：

```text
1. 发布状态显示 PUBLISHED。
2. 页面可见已发布版本 ID：101996817981380254。
3. 若页面展示发布返回信息，应能看到 backfillStartDate 为 2025-09-01。
4. 若页面展示回补信息，应能看到 monthlyBackfillBatchCount 为 10、yearlyBackfillBatchCount 为 1。
```

## 9. 若必须重新创建对象

严格复测应优先使用接口文档第 18 章已经存在的对象和 ID。只有在后端环境被清空、这些对象不存在时，才重新创建。

重新创建时必须遵守：

```text
1. 不复用接口文档中已存在的业务编码，否则可能 409 冲突。
2. 业务编码可以在接口文档编码后追加新的唯一后缀。
3. 字段、语义表、公式、时间窗口、display 配置必须保持接口文档参数语义。
4. 数据域必须仍绑定 vmq_deathpatientdetail 与 vmq_basicinformationba。
5. 默认时间语义字段必须仍分别映射为 DEATH_TIME 与 DISCHARGE_TIME。
6. 因子 DSL 应优先使用 filters: {"nodeType":"TRUE"}，依赖语义表默认时间字段自动绑定 period。
```

重新创建时允许变化的内容：

```text
数据域编码后缀
因子编码后缀
指标编码后缀
后端返回的新 ID
后端返回的新 taskId / batchId
```

重新创建时不应变化的内容：

```text
源表：vmq_deathpatientdetail、vmq_basicinformationba
默认时间语义字段：DEATH_TIME、DISCHARGE_TIME
公式结构：死亡患者数 / 出院人次

展示格式：PERCENT
multiplier：100
scale：2
roundingMode：HALF_UP
测试窗口：2026-03-01T00:00:00 至 2026-04-01T00:00:00
```
