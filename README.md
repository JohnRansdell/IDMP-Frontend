# IDMP 医疗质量指标数据管理平台前端

IDMP Frontend 是医疗质量指标数据管理平台的 Web 前端，用于数据资产配置、因子与指标生命周期管理、场景配置、计算任务跟踪、指标分析和结果下钻。

项目基于 Vue 3 和 Vite，当前定位为可连接真实后端的联调与演示版本。核心纵向链路已有页面和接口基础，但浏览器端到端验收、完整权限治理以及部分业务模块仍在建设中，不应视为生产验收完成。

业务页面统一读取真实接口，接口失败时显示错误和重试入口，空结果按空状态展示。已取消指标、因子目录和指标详情的演示兜底，以及看板和下钻的演示入口；`dashboardDemo=1`、`VITE_DASHBOARD_PREVIEW_MODE` 不再启用模拟业务数据。后端保存的旧 `MOCK` 看板只提示重新配置，进入编辑时在本次编辑中清空演示组件，需添加真实指标组件后保存、发布。测试所需的历史演示数据保留在 `test/fixtures/frontend/`，不参与业务构建。

## 快速开始

要求：使用项目声明的 pnpm 版本，并准备兼容当前 Vite 版本的 Node.js 环境。

```powershell
pnpm install
pnpm dev
```

开发服务启动后访问：

```text
http://localhost:5173
```

常用命令：

```powershell
# 运行 Node 自动化测试
pnpm test

# 验证真实数据边界与页面状态（浏览器用例拦截 API，不写入真实后端）
pnpm run test:real-data
pnpm run test:e2e:real-data

# 生成生产构建
pnpm run build:prod

# 本地预览生产构建
pnpm preview
```

## API 配置

前端默认使用同源 API 前缀：

```text
/api/v1
```

如需覆盖，可在本地环境文件中配置 `VITE_API_BASE_URL`。仓库中只应保存不含真实地址的示例：

```dotenv
VITE_API_BASE_URL=/api/v1
```

推荐由网关或反向代理将 `/api/v1` 转发到后端服务。不要把内网 IP、正式域名、端口、账号、令牌或 Cookie 写入源码、README、提交记录和构建产物。

### 看板接口与存量配置

看板目录、定义、查询、编辑保存和发布使用现有服务端接口。目录为空时可以创建服务端看板；接口失败时重试当前请求。旧的预览环境变量和 URL 演示参数不再提供数据，浏览器中保留的演示 Schema 也不会恢复为业务看板。

科室全局筛选显示名称、实际提交编码。前端依据已知科室字段契约及指标版本的组织路径，将同一筛选映射到各数据源实际字段（例如 `OUT_DEPT_CODE`、`科室`）；候选数据来源不等于作用范围，组件的忽略/不继承设置继续生效。名称优先读取正式结果，缺失时使用同源编码限定的名称候选，避免按列表顺序猜测对应关系。候选加载失败会显示错误及重试，缺少名称时明确显示编码。

`pnpm run test:dashboard-department` 验证字段映射与作用范围；配置真实 API 后，可运行 `pnpm run test:e2e:dashboard-department-live` 对现有 `test` 看板进行只读验证，覆盖名称显示、单选、多选、清除，以及卡片和饼图的实际请求。该脚本阻止保存、发布、删除和计算写操作。

## 数据来源与页面状态

业务数据来自真实接口。加载中、空结果和失败状态分别展示，失败时提供重试；缺失字段显示未知或占位符，不补造业务记录、版本、周期或计算数值。顶部仅在看板页面保留真实看板选择器，通用页面不再展示没有筛选作用的固定全局场景。

历史固定数据移到 `test/fixtures/frontend/`，供图表、计算和适配器测试使用。正常枚举、布局配置、样式示意和测试夹具保留；旧演示页面已从源码删除。新增页面回归命令为 `pnpm run test:e2e:real-data`，验证 API 失败、重试、空结果、真实结果和旧配置处理；依赖历史演示入口的旧浏览器脚本不再适用于当前业务入口。

正式验收仍需针对实际部署的后端验证；测试中注入的接口响应不代表真实后端已经通过验收。

### 看板环形图下钻

看板中有同源组织下钻上下文的饼图支持原地展开和面包屑返回，路径遵循结果快照配置，最多到医师；没有上下文的构成图不补造入口。图表与数据表共用当前层数据，以分子值绘制，不把各组织发生率再次换算成占比。刷新、筛选或编辑切换会重置临时下钻状态。

下钻使用在线详细设计的 `POST /api/v1/analysis/results/{resultId}/drill/search`，携带同源快照，区别于离线 DOCX 中的 GET 示例。每页不超过 200 条，整层最多收集 500 条；超限、缺失分子、重复组织或不完整分页仅显示带原因的分页表格。上下文冲突及接口错误不回退为演示成功。

真实联调需要看板提供同源 `drillTarget`，下钻响应提供根结果、快照、指标版本、当前层、父组织上下文、分子和可靠分页信息。只有 `value` 的排名不能替代分子；缺失这些字段属于后端依赖。旧 `source=mock` 下钻链接已停用，需要从真实计算结果重新进入。

## 安全与脱敏要求

仓库及其文档不得包含以下内容：

- 内网或公网真实 IP、域名、端口和服务拓扑。
- 本机绝对目录、服务器目录、共享盘路径和部署账号。
- 用户名、密码、Access Token、Refresh Token、Cookie、密钥或连接串。
- 患者、医务人员或其他自然人的身份信息和业务明细。
- 可定位真实联调环境的资源 ID、批次 ID、对象数量、日志或截图。
- 未经脱敏的数据库表样例、请求响应、错误堆栈和追踪信息。

提交日志、Issue、演示截图和测试附件也应遵守同一规则。示例统一使用语义化占位符或本地同源地址；敏感配置通过受控环境变量或密钥管理服务提供。

## 当前边界

- 通用公式 AST 编辑器仍以简单比率场景为主。
- 场景批量计算、场景结果和跨场景对比尚未形成完整闭环。
- 数据采集、完整清洗转换和独立数据质量模块尚未完整交付。
- 看板布局仍主要保存在浏览器本地，服务端持久化待完善。
- 报表、文件导出和正式预警通知尚未完成。
- 菜单、路由、按钮、字段和数据范围权限尚未形成完整联调闭环。
- 患者或记录级下钻仍需完善访问目的、脱敏、数据范围和审计控制。
- 当前自动化测试以适配器和数据契约为主，尚不能替代浏览器 E2E、性能、安全和生产部署验收。

## 构建与部署原则

1. 在受控 CI 或构建环境执行测试和生产构建。
2. 将完整 `dist` 作为同一版本制品发布，不要混用不同构建生成的哈希资源。
3. 使用环境配置或网关提供后端地址，不在前端制品中固化真实服务地址。
4. 部署前核对前端提交、后端版本、数据库迁移和配置清单。
5. 正式环境确认真实接口及空数据、错误、重试状态，并完成权限、安全和审计验收。

### 静态站点部署

`pnpm build:prod` 后必须将**同一次构建生成的整个 `dist` 目录**上传到 Web 根目录，不能只替换 `index.html` 或单个 `assets/*.js` 文件。构建文件名含内容哈希，混用新旧文件会使入口脚本返回 404，表现为浏览器白屏。

若站点不是部署在域名根目录，例如访问地址为 `https://example.com/idmp/`，构建前设置：

```env
VITE_PUBLIC_BASE=/idmp/
VITE_API_BASE_URL=/api/v1
```

Nginx 需将前端路由回退到同一目录的 `index.html`，并代理后端接口。例如：

```nginx
location /idmp/ {
  alias /srv/idmp/dist/;
  try_files $uri $uri/ /idmp/index.html;
}

location /api/v1/ {
  proxy_pass http://127.0.0.1:8081/api/v1/;
}
```
