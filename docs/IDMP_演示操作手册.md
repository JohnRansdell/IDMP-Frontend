# IDMP 演示操作手册

> 适用版本：IDMP-Frontend 当前工作区页面；接口基线为 revision 1047 的 0907 文档。
>
> 演示方式：每一步先说明“为什么来到这里”，再进行页面操作，最后展示页面结果。

## 1. 演示前准备

### 1.1 准备独立演示标识

**为什么要做**

演示会创建值集、因子、指标、场景、计算批次、映射和预警规则。使用统一且唯一的标识，可以避免修改历史业务对象，也方便演示后查询和清理。

**怎么操作**

1. 确定本次演示后缀，例如 `DEMO_20260908_01`。
2. 后续新建对象的编码均带上该后缀。
3. 记录本次使用的数据域、语义表、字段、因子版本、指标版本、场景版本、任务和批次 ID。
4. 确认当前账号可以访问数据治理、因子、指标、场景、计算任务、指标分析、指标映射和预警中心。

**操作完成后**

本次演示对象能够与历史数据区分，所需菜单和按钮可见。

**展示了什么功能**

这一步不展示业务功能，用于保证后续演示不会误改共享配置。

### 1.2 确认演示数据可用

**为什么要做**

因子试算、正式计算、场景对比和预警都依赖真实数据。若数据周期选择错误，即使配置正确也可能只能得到“无数据”。

**怎么操作**

本手册固定使用以下数据，不在演示过程中临时选择其他相似对象：

|层级|本次查看和使用的对象|业务含义|
|---|---|---|
|来源库|`yunnan-vmq`|医院来源数据所在库|
|来源表|`vmq_basicinformationba`|住院病案首页/出院病案记录；一行代表一条住院病案记录|
|来源性别字段|`vmq_basicinformationba.sex`|患者性别原始编码|
|来源出院时间字段|`vmq_basicinformationba.out_date`|患者出院日期，用于限定月度或年度统计周期|
|来源出院科室字段|`out_dept_code`、`out_dept_name`|患者出院科室编码和名称，用于科室下钻|
|数据域|`DEMO_ENUM_DRILL_20260813_03`|本次男性出院率演示使用的数据范围|
|语义表|`DEMO_INPATIENT_DISCHARGE`|平台统一后的“住院出院病案”业务表|
|性别语义字段|`PATIENT_SEX`|由物理字段 `sex` 映射而来，用于标准性别筛选|
|时间语义字段|`OUT_TIME`|由出院日期字段映射而来，是本语义表的默认时间字段|
|组织下钻层级|`HOSPITAL → OUT_DEPT`|从全院结果下钻到出院科室|
|标准性别值|`MALE`、`FEMALE`、`UNKNOWN`|平台统一使用的男性、女性、未知编码|

**怎么操作**

1. 在数据源管理中确认能够搜索到来源表 `vmq_basicinformationba`。
2. 在数据域管理中确认能够搜索到 `DEMO_ENUM_DRILL_20260813_03`。
3. 进入该数据域，确认存在语义表 `DEMO_INPATIENT_DISCHARGE`。
4. 在语义表中确认 `PATIENT_SEX`、`OUT_TIME`、`OUT_DEPT_CODE`、`OUT_DEPT_NAME` 均可见。
5. 确认 `OUT_TIME` 是默认时间字段。
6. 打开 `PATIENT_SEX` 的字段画像，确认原始值至少包含 `1`、`2`、`9`。
7. 本手册采用已完成业务复核的含义：`1 → MALE（男性）`、`2 → FEMALE（女性）`、`9 → UNKNOWN（未知）`。如果当前页面显示其他映射，停止演示并先修正规则，不能把技术链路成功当作临床含义正确。
8. 记录两个已验证周期：月度 `[2026-04-01, 2026-05-01)`；年度 `[2025-01-01, 2026-01-01)`。
9. 确认预警演示接收用户能正常读取站内通知。

**操作完成后**

已确认本次使用的是 `vmq_basicinformationba` 住院病案数据，且数据域、语义表、性别、出院时间和出院科室字段关系清楚。

**展示了什么功能**

这一步建立后续演示的数据前提，避免把别的数据域、别的时间字段或含义错误的性别映射带入指标计算。

## 2. 主线演示：从原始数据到预警处置

本线使用“男性出院病案人次占比”作为示例：男性出院病案记录数除以全部出院病案记录数。这里的单位是“病案人次”，不是按患者证件号去重后的患者人数。

### 2.1 查看医院来源数据

**为什么来到这个页面**

所有指标结果都必须能够说明数据来自哪里。这里先确认医院源系统提供了哪些表和字段，证明后续指标不是手工填写的结果。

**怎么操作**

1. 点击左侧“数据治理 → 数据源管理”。
2. 在数据源列表定位来源库 `yunnan-vmq`，点击“同步数据结构”。
3. 等待同步完成，在表名搜索框输入完整表名 `vmq_basicinformationba`，不要选择名称相近的费用表或诊断表。
4. 打开 `vmq_basicinformationba` 的字段列表，依次搜索并查看以下字段：
   - `sex`：患者性别原始编码；本次用它判断男性出院病案。
   - `out_date`：患者出院日期；本次用它筛选 2026 年 4 月的数据。
   - `out_dept_code`：出院科室编码；本次用它区分科室成员。
   - `out_dept_name`：出院科室名称；本次用它显示“肾内科”“泌尿外科”“产科”等可读名称。
5. `vmq_basicinformationba` 一行是一条住院病案记录，因此对符合条件的行做 `COUNT`，得到的是“出院病案人次”，不是去重患者人数，也不是床日数。
6. 记录页面显示的字段类型；重点确认 `out_date` 可作为日期条件、`sex` 可作为编码条件。

**操作完成后**

页面明确显示数据来自 `yunnan-vmq.vmq_basicinformationba`，后续计算实际读取 `sex`、`out_date`、`out_dept_code` 和 `out_dept_name`。此时只确认“医院给了什么数据”，尚未解释 `sex=1/2/9` 的业务含义。

**展示了什么功能**

展示来源元数据同步、源表查询和源字段发现能力。

### 2.2 查看统一后的业务字段

**为什么来到这个页面**

上一步看到的是数据库表名和字段名。因子不能直接依赖不同医院各自的技术命名，因此要把物理字段映射成稳定的业务语言。

**怎么操作**

1. 点击“数据治理 → 数据域管理”。
2. 在数据域编码搜索框输入 `DEMO_ENUM_DRILL_20260813_03`，只打开这一数据域，点击“进入工作台”。
3. 在语义表列表选择 `DEMO_INPATIENT_DISCHARGE`。该表的业务名称是本次演示使用的“住院出院病案”，不是另一张同名或相似的来源表。
4. 在字段列表逐项核对：
   - 语义字段 `PATIENT_SEX` 映射物理字段 `vmq_basicinformationba.sex`，表示患者性别。
   - 语义字段 `OUT_TIME` 映射物理出院日期 `vmq_basicinformationba.out_date`，表示出院时间。
   - 组织字段 `OUT_DEPT_CODE`、`OUT_DEPT_NAME` 分别映射来源的 `out_dept_code`、`out_dept_name`，表示出院科室编码和名称。
5. 点击 `PATIENT_SEX`，确认它是可筛选的维度字段；后续分子因子会用它筛选 `MALE`。
6. 点击 `OUT_TIME`，确认它是日期或日期时间字段。
7. 在默认时间字段区域确认当前值为 `OUT_TIME`；如不是，选择 `OUT_TIME` 并点击“保存默认时间字段”。

**操作完成后**

页面建立以下可讲清楚的对应关系：`sex → PATIENT_SEX`、`out_date → OUT_TIME`、`out_dept_code/out_dept_name → OUT_DEPT_CODE/OUT_DEPT_NAME`；默认统计日期是 `OUT_TIME`，组织分析最深到 `OUT_DEPT`。

**展示了什么功能**

展示数据域、语义表、字段映射和统一时间口径管理。

### 2.3 查看性别来源值

**为什么来到这个页面**

知道某个字段代表性别还不够，还要知道源系统实际使用什么值。来源值可能是 `1/2/9`、`M/F/U` 或其他编码，不能凭经验直接配置统计条件。

**怎么操作**

1. 在 `DEMO_ENUM_DRILL_20260813_03` 数据域的 `DEMO_INPATIENT_DISCHARGE` 语义表中选择 `PATIENT_SEX`。
2. 点击“字段画像”。
3. 确认画像指向的真实物理字段是 `vmq_basicinformationba.sex`，而不是其他表中的性别字段。
4. 查看来源值、出现次数、空值和样例分布，重点查看原始值 `1`、`2`、`9`。
5. 使用 0907 文档中的历史实测值现场核对：总计 `95,755` 条，`1` 为 `43,309` 条、`2` 为 `52,445` 条、`9` 为 `1` 条。若现场已新增病案，数量可以增加，但必须仍能解释各编码。
6. 画像只说明“数据库里有哪些原始值”，业务复核后的含义才是 `1=男性`、`2=女性`、`9=未知`。

**操作完成后**

页面显示 `vmq_basicinformationba.sex` 的真实值分布，证明后续筛选男性时应识别原始值 `1`，而不是直接猜测或直接把字符串“男”写入源数据条件。

**展示了什么功能**

展示源字段画像能力，也说明标准化规则必须依据真实数据，而不是依赖人工猜测。

### 2.4 创建并发布性别标准值集

**为什么来到这个页面**

来源系统的内部编码不能直接成为统一指标口径。这里先定义平台认可的标准值“男、女、未知”，后续因子只使用标准值。

**怎么操作**

1. 点击“数据治理 → 值集管理”。
2. 点击“新建值集”。
3. 编码填写 `VS_PATIENT_SEX_DEMO_20260908_01`，名称填写“患者性别标准值集演示”。
4. 值类型选择字符串类型，匹配类型选择精确枚举。
5. 点击“创建并维护值项”。
6. 按下表逐项添加，不使用 `M/F`、`男/女` 等其他临时代码：

   |值项编码|值项名称|本次业务含义|
   |---|---|---|
   |`MALE`|男性|出院病案中患者性别为男|
   |`FEMALE`|女性|出院病案中患者性别为女|
   |`UNKNOWN`|未知|来源系统未明确男或女，本例对应原始值 `9`|

7. 保存值项。
8. 点击“校验版本”。
9. 校验通过后点击“发布版本”，确认发布。

**操作完成后**

值集版本显示为已发布，详情中可以看到三个标准值项。

**展示了什么功能**

展示标准值定义、值集版本、校验和发布门禁。

### 2.5 绑定值集并发布源值转换规则

**为什么来到这个页面**

值集只定义了平台标准，还没有说明医院来源值如何转换。这里把来源编码逐一映射到标准值，形成可执行的标准化规则。

**怎么操作**

1. 返回“数据治理 → 数据域管理”，进入 `DEMO_ENUM_DRILL_20260813_03` 数据域工作台。
2. 选择语义表 `DEMO_INPATIENT_DISCHARGE` 和语义字段 `PATIENT_SEX`；再次确认其物理来源为 `vmq_basicinformationba.sex`。
3. 在值集绑定区域选择刚发布的性别值集版本并保存。
4. 进入该字段的“源值标准化”。
5. 精确配置三条转换：原始值 `1 → MALE`、原始值 `2 → FEMALE`、原始值 `9 → UNKNOWN`。
6. 保存规则草稿。
7. 点击“预览”，逐条核对：`1` 的输出是 `MALE`、`2` 的输出是 `FEMALE`、`9` 的输出是 `UNKNOWN`；同时查看命中数量和未匹配数量。
8. 预览正确后点击“校验”。
9. 校验通过后点击“发布”。
10. 如果页面出现 `1 → FEMALE`、`2 → MALE` 或 `9 → OTHER_1`，立即停止，不继续创建因子。这些是历史测试中出现过的错误示例，不能用于业务演示。

**操作完成后**

`PATIENT_SEX` 显示已绑定 `VS_PATIENT_SEX_DEMO_20260908_01` 的已发布版本，且 `vmq_basicinformationba.sex` 的三个原始编码都被转换为明确的标准值。后续因子写 `PATIENT_SEX=MALE` 时，执行层实际命中源数据的 `sex=1`。

**展示了什么功能**

展示语义字段与值集绑定、来源值转换、预览、校验和发布闭环。

### 2.6 创建“男性出院病案人次”因子

**为什么来到这个页面**

标准化完成后，可以使用统一的 `MALE` 统计男性记录。先建立分子因子，是为了让这项基础统计能够单独试算、单独验证并被其他指标复用。

**怎么操作**

1. 点击“指标配置 → 因子管理”。
2. 点击“新建因子”。
3. 编码填写 `F_MALE_DISCHARGE_DEMO_20260908_01`，名称填写“男性出院病案人次演示”。
4. 主数据域选择 `DEMO_ENUM_DRILL_20260813_03`，语义表选择 `DEMO_INPATIENT_DISCHARGE`。
5. 查看语义表下方自动显示的“统计周期字段”，确认是“出院时间（`OUT_TIME`）”。`OUT_TIME` 映射 `vmq_basicinformationba.out_date`；试算日期会自动作用到该字段，不在“筛选范围”中重复添加时间条件，也不需要手工选择 `BETWEEN`。
6. 统计方式选择 `COUNT`（记录计数），计数字段留空，表示统计符合条件的完整病案记录行；分组维度暂不选择。这里统计的是 `vmq_basicinformationba` 的病案行数，单位解释为“出院病案人次”。
7. 在“筛选范围”选择“显式筛选条件”，点击“添加筛选条件”。字段选择 `PATIENT_SEX`，判断方式选择“属于标准值”，标准值选择 `MALE`。该条件经过已发布值集转换后对应源数据 `sex=1`。
8. 因子页面不配置 `ORGANIZATION`、`OUT_DEPT` 等下钻路径；下钻能力在分子、分母因子发布后，到指标公式页面统一预检和选择。
9. 点击“保存草稿并继续”。
10. 点击“编译并校验”。编译成功后，等待页面自动获取并填入“后端推荐”的试算周期。
11. 普通演示保留页面推荐的开始时间和结束时间，记录页面显示的数据覆盖范围与预计匹配记录数，不必固定改成 2026 年 4 月。
12. 只有需要复现 0907 文档的历史基准时，才将试算周期手工改为开始时间 `2026-04-01 00:00:00`、结束时间 `2026-05-01 00:00:00`。该区间含 4 月 1 日、不含 5 月 1 日。
13. 点击“试算并查看结果”，等待任务结束。
14. 使用推荐周期时，按页面显示的实际周期、结果值和源记录数进行说明，不要求结果必须为 `122`；使用固定 2026 年 4 月周期时，历史基准为 `122`，若结果不同再检查数据是否新增以及 `PATIENT_SEX=MALE` 是否正确转换到 `sex=1`。
15. 核对质量状态和源数据状态正常后，点击“发布因子版本”。

**操作完成后**

因子版本显示已发布。使用推荐周期时，结果表示页面所示周期内 `PATIENT_SEX=MALE` 的出院病案人次；只有手工使用 `[2026-04-01, 2026-05-01)` 时，才以历史基准 `122` 人次进行核对。

**展示了什么功能**

展示因子口径配置、值集标准值筛选、编译、周期推荐、异步试算、质量判断和版本发布。

### 2.7 创建“全部出院病案人次”因子

**为什么来到这个页面**

占比指标还需要一个分母。分母必须与分子使用相同的数据域、语义表和统计周期，只是不限制患者性别，这样两者才具有可比性。

**怎么操作**

1. 返回因子管理，点击“新建因子”。
2. 编码填写 `F_ALL_DISCHARGE_DEMO_20260908_01`，名称填写“全部出院病案人次演示”。
3. 主数据域同样选择 `DEMO_ENUM_DRILL_20260813_03`，语义表同样选择 `DEMO_INPATIENT_DISCHARGE`。
4. 查看自动显示的“统计周期字段”，确认仍是“出院时间（`OUT_TIME`）”。不在筛选条件中重复配置 `OUT_TIME BETWEEN period`。
