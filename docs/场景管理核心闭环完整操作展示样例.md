# 场景管理核心闭环完整操作展示样例

本文用于通过前端页面完整展示 IDMP 当前已实现的场景管理核心闭环：

```text
场景目录
  → 创建场景和首个草稿版本
  → 填写基本信息
  → 关联已发布指标版本
  → 配置场景覆盖规则
  → 保存草稿
  → 查看合并后的最终有效口径
  → 执行发布前校验
  → 发布场景版本
  → 基于已发布版本创建下一草稿版本
```

本流程重点证明：场景不是一个普通分类字典，而是由“场景主对象 + 场景版本 + 指标版本集合 + 覆盖规则”组成的版本化计算配置。

## 1. 本次展示范围

当前页面可以展示以下真实后端能力：

- 场景分页查询和筛选。
- 创建场景及首个草稿版本。
- 查询场景版本详情。
- 基于当前已发布版本复制出新草稿版本。
- 编辑场景基本信息、默认周期、生效日期和默认排除规则。
- 关联一个或多个已发布指标版本。
- 配置场景全局或单指标覆盖规则。
- 查看后端计算出的合并口径。
- 执行发布前校验并查看诊断信息。
- 使用最新 `resourceVersion` 发布场景版本。
- 处理多人同时编辑造成的 409 版本冲突。

当前不在本次展示范围内：整场景复制、JSON/YAML 导入导出、政策文件关联、场景启停/归档、场景批量计算、场景结果和场景对比分析。这些能力尚缺少对应的完整后端接口。

## 2. 演示前置条件

### 2.1 前后端连接正常

前端需要满足以下任一条件：

```text
1. VITE_API_BASE_URL 已指向后端，例如：
   http://后端地址:端口/api/v1

2. 部署环境已经把 /api/v1 反向代理到后端。
```

打开浏览器开发者工具的 Network 面板，进入任意已接入页面时，应能看到 `/api/v1` 请求返回 HTTP 200。

### 2.2 当前用户具有场景权限

建议使用具有以下权限的指标管理员账号：

```text
scenario:view
scenario:create
scenario:edit
scenario:publish
```

如果接口返回 HTTP 401，表示登录状态无效；返回 HTTP 403，表示当前账号没有对应操作权限。

### 2.3 至少存在一个已发布指标版本

场景版本只能关联 `PUBLISHED` 状态的指标版本。

演示前进入：

```text
左侧导航 → 指标配置 → 指标目录
```

确认至少存在一个已发布指标，例如：

```text
指标编码：INPATIENT_MORTALITY
指标名称：住院死亡率
版本：V1 或后端当前已发布版本
状态：已发布
```

如果场景编辑页的指标选择框为空，通常表示后端尚无已发布指标版本，应先完成指标的创建、公式配置、试算和发布流程。

## 3. 本文使用的演示数据

为了避免场景编码重复，实际操作时可将编码末尾替换为当天日期或个人缩写。

|字段|演示值|业务含义|
|---|---|---|
|场景编码|`HQMS_REPORT_DEMO_20260811`|租户内唯一的稳定业务标识|
|场景名称|HQMS 医疗质量月报演示场景|用户可读的场景名称|
|场景类型|考核上报|对应后端 `ASSESSMENT`|
|默认统计周期|月|对应后端 `MONTHLY`|
|主管部门|国家卫生健康委|场景治理责任部门|
|生效日期|2026-01-01 至 2026-12-31|该场景版本允许生效的业务期间|
|关联指标|住院死亡率已发布版本|场景计算配置绑定的是确定的指标版本|
|覆盖类型|参数|对应后端 `PARAMETER`|
|目标路径|`/period/granularity`|被覆盖的指标配置节点|
|覆盖值|`"MONTHLY"`|合法 JSON 字符串，表示按月统计|
|优先级|10|多个覆盖同时存在时的排序依据|

## 4. 第一步：进入场景目录

点击：

```text
左侧导航 → 指标配置 → 场景管理
```

浏览器进入：

```text
/scenarios
```

页面应出现以下区域：

1. 顶部“场景管理”标题。
2. 右上角“新建场景”按钮。
3. 场景编码、场景名称、场景类型、版本状态筛选条件。
4. 场景目录表格。
5. 表格底部分页器。

页面自动调用：

```http
GET /api/v1/scenarios?page=1&size=20
```

表格字段的业务含义：

|页面字段|代表的业务|
|---|---|
|场景编码|稳定业务编码，不随版本变化|
|场景名称|业务人员识别场景的名称|
|类型|考核、评审、专业质控、专项或自定义场景|
|主管部门|负责场景口径治理的组织|
|指标数|当前发布版本或最新版本中已绑定的指标数量|
|状态|场景当前是否已经存在已发布版本|
|更新时间|最近一次场景或版本变更时间|

### 4.1 验证目录筛选

在“场景编码”输入：

```text
HQMS
```

点击“查询”。

Network 中应出现带 `code=HQMS` 的场景查询请求。页面只显示编码中包含 HQMS 的场景，说明筛选条件已经传给后端，而不是只在浏览器本地过滤。

点击“重置”，筛选项清空，页码回到第一页并重新查询。

## 5. 第二步：创建场景和首个草稿版本

点击页面右上角：

```text
新建场景
```

在弹窗中填写：

```text
场景编码：HQMS_REPORT_DEMO_20260811
场景名称：HQMS 医疗质量月报演示场景
场景类型：考核上报
默认周期：月
主管部门：国家卫生健康委
说明：用于演示场景版本、指标绑定、覆盖、校验和发布核心闭环
```

点击：

```text
创建并编辑
```

页面调用：

```http
POST /api/v1/scenarios
```

成功后页面自动进入：

```text
/scenarios/{scenarioId}/edit?versionId={versionId}
```

页面顶部应显示：

```text
场景名称：HQMS 医疗质量月报演示场景
场景编码：HQMS_REPORT_DEMO_20260811
版本：1
状态：草稿
资源版本：0（具体值以后端返回为准）
```

这些信息代表：

- 后端已经创建场景主对象。
- 后端同时创建了版本号为 1 的首个场景版本。
- `DRAFT` 表示配置尚可修改，也还不能进入正式计算快照。
- `resourceVersion` 是乐观锁版本，每次成功修改后都会递增。

如果提示“场景编码已存在”，请修改编码末尾后重新创建，不要复用已经存在的编码。

## 6. 第三步：配置场景基本信息

进入“基本信息”页签，确认或填写：

```text
场景名称：HQMS 医疗质量月报演示场景
主管部门：国家卫生健康委
默认统计周期：月
生效日期：2026-01-01 至 2026-12-31
场景说明：用于 HQMS 医疗质量月度上报和指标口径统一管理
默认排除规则说明：本演示不增加全局排除条件
```

“默认排除规则”的 JSON 输入框填写：

```json
{
  "nodeType": "TRUE"
}
```

这里的 `TRUE` 表示场景默认层不额外排除数据。它不是“校验结果为真”，而是一个始终成立的规则节点。

默认统计周期“月”表示场景基础层使用 `MONTHLY`。后续单指标覆盖规则可以在指标允许覆盖的范围内改变其最终有效配置。

此时先不要发布。场景版本至少需要关联一个已发布指标，才能通过发布校验。

## 7. 第四步：关联已发布指标版本

点击页签：

```text
关联指标
```

点击右上角“选择指标版本”下拉框，输入指标编码或名称进行检索，例如：

```text
住院死亡率
```

选择一个明确标记为已发布的版本，例如：

```text
INPATIENT_MORTALITY · 住院死亡率 · V1
```

选择后，下方表格出现一行指标绑定记录。根据演示需要设置：

```text
必选：开启
上报要求：每月 10 日前完成上月数据上报
```

这些字段代表：

- 选择的是“指标版本”而不是只有指标主对象，保证场景发布后口径可以稳定追溯。
- “必选”表示该指标属于此场景的必备指标集合。
- “上报要求”是该指标在当前场景中的业务说明，不改变指标公式。
- 指标在列表中的顺序会转换为 `displayOrder` 保存。

如果下拉框没有任何选项，不要继续发布，应先到“指标目录”完成至少一个指标版本的发布。

## 8. 第五步：配置单指标覆盖规则

点击页签：

```text
覆盖规则
```

点击：

```text
新增覆盖
```

填写以下内容：

```text
作用范围：选择刚才绑定的住院死亡率指标版本
类型：参数
目标路径：/period/granularity
覆盖值："MONTHLY"
优先级：10
```

注意：覆盖值输入的是 JSON，不是普通文本。因此字符串必须包含双引号：

```json
"MONTHLY"
```

以下写法不是合法 JSON 字符串：

```text
MONTHLY
```

这条覆盖规则表示：

- 仅作用于当前场景中的住院死亡率版本。
- 将该指标的 `/period/granularity` 参数覆盖为月度。
- 不会修改指标原始版本，也不会影响其他场景。
- 后端发布时还会检查指标的 `overridePolicy` 是否允许覆盖该节点。

如果“作用范围”留空，则该规则是场景全局覆盖，后端会尝试对场景内全部适用指标合并该规则。

## 9. 第六步：保存场景草稿

确认基本信息、关联指标和覆盖规则均已填写后，点击页面右上角：

```text
保存草稿
```

前端按以下顺序提交：

```http
PATCH /api/v1/scenario-versions/{versionId}
PUT   /api/v1/scenario-versions/{versionId}/indicators
PUT   /api/v1/scenario-versions/{versionId}/overrides
```

三个步骤分别代表：

1. 保存场景基本信息、默认周期、生效期和默认排除规则。
2. 用页面当前选择结果整体替换该版本的指标集合。
3. 用页面当前编辑结果整体替换该版本的覆盖规则集合。

页面提示：

```text
场景草稿已保存
```

同时顶部“资源版本”应更新为更大的值。这说明后端已接受完整配置，并通过乐观锁为新状态生成了版本号。

重要说明：指标集合和覆盖规则都是整集合替换。页面中移除一项并再次保存，代表从该场景版本中删除该项，而不是只提交增量修改。

### 9.1 保存阶段常见提示

|页面提示|代表什么|处理方式|
|---|---|---|
|请至少关联一个已发布指标版本|场景还没有可发布的计算对象|进入“关联指标”至少选择一项|
|默认排除规则不是合法 JSON|基本信息中的规则 JSON 无法解析|检查括号、引号和逗号|
|覆盖值不是合法 JSON|某一覆盖规则值无法解析|字符串使用双引号，数字和布尔值按 JSON 填写|
|数据或状态冲突 / 版本冲突|其他用户或窗口已经修改同一草稿|按提示重新加载服务端最新版本|
|当前账号无权限|后端拒绝场景编辑操作|申请 `scenario:edit` 权限|

## 10. 第七步：查看合并后的最终有效口径

保存成功后点击：

```text
合并预览 → 刷新预览
```

页面调用：

```http
GET /api/v1/scenario-versions/{versionId}/merged-preview
```

页面按指标展示后端返回的最终有效定义。展开“住院死亡率”后，应重点检查：

```json
{
  "effectiveParameters": {
    "period": {
      "granularity": "MONTHLY"
    }
  }
}
```

实际响应中还可能包含：

```text
formulaDefinition
defaultGrain
effectiveExclusionDsl
effectiveDataSourcePriority
displayRules
thresholdRules
```

业务含义：

- `formulaDefinition` 是已发布指标版本的公式快照来源。
- `effectiveParameters` 是场景默认参数和单指标参数覆盖合并后的结果。
- `effectiveExclusionDsl` 是最终会用于计算的排除规则。
- `effectiveDataSourcePriority` 是最终数据源优先级。
- 预览只计算配置合并结果，不会触发正式指标计算，也不会生成业务结果数据。

如果预览中没有指标，说明指标集合尚未保存成功；返回错误则应根据后端 `traceId` 排查合并服务。

## 11. 第八步：执行发布前校验

点击页面右上角：

```text
校验
```

页面调用：

```http
POST /api/v1/scenario-versions/{versionId}/validate
```

点击后页面自动切换到“校验诊断”页签。

### 11.1 校验通过

页面顶部出现：

```text
校验通过，可以发布。
```

“发布”按钮从禁用变为可点击。

这表示后端已确认：

- 场景版本仍为草稿。
- 至少关联一个有效的已发布指标版本。
- 生效日期范围合法。
- 排除 DSL 可以解析。
- 覆盖目标路径和覆盖值符合指标允许的覆盖策略。
- 校验结果对应当前最新 `resourceVersion`。

### 11.2 校验未通过

页面显示：

```text
校验未通过，请处理诊断信息。
```

诊断区域逐条显示后端返回的问题。“发布”按钮继续保持禁用。

例如覆盖规则被拒绝，通常表示目标指标版本没有允许 `/period/granularity` 被当前场景覆盖。此时应删除或修改该覆盖规则，重新执行：

```text
保存草稿 → 刷新预览 → 校验
```

任何配置修改都会使之前的校验结论失效，必须针对最新配置重新校验。

## 12. 第九步：发布场景版本

只有校验通过后，点击：

```text
发布
```

页面调用：

```http
POST /api/v1/scenario-versions/{versionId}/publish
```

请求中携带校验接口返回的最新：

```json
{
  "resourceVersion": 4
}
```

实际数字以后端返回为准。

发布成功后页面提示：

```text
场景版本已发布
```

并出现以下变化：

1. 顶部状态由“草稿”变为“已发布”。
2. 页面出现“当前为已发布版本，只读查看”的提示。
3. 保存草稿、校验和发布按钮不可继续操作。
4. 后端场景主对象的 `currentPublishedVersionId` 指向当前版本。
5. 后端生成不可变的计算配置快照，后续计算引用确定的场景版本而不是活动草稿。

这一步代表场景配置已经从治理编辑态进入正式可引用状态。发布不会修改该指标在其他场景中的配置，也不会重写历史计算快照。

## 13. 第十步：回到目录验证发布结果

点击页面右上角：

```text
返回目录
```

在场景编码筛选框输入：

```text
HQMS_REPORT_DEMO_20260811
```

点击“查询”。

表格中应看到：

```text
状态：已发布
指标数：至少 1
更新时间：本次发布时间附近
```

点击“查看/编辑”，进入当前发布版本后页面应保持只读。这证明已发布版本不可被页面直接修改。

## 14. 第十一步：基于发布版本创建下一草稿

回到场景目录，在刚才发布的场景行点击：

```text
新建版本
```

页面调用：

```http
POST /api/v1/scenarios/{scenarioId}/versions
```

请求中的 `copyFromVersionId` 为当前已发布版本 ID。

成功后自动进入新版本编辑页。页面应显示：

```text
版本：2（实际值以后端递增结果为准）
状态：草稿
```

同时原版本的基本信息、指标绑定和覆盖规则应被复制到新草稿。

这代表场景版本演进采用“复制发布快照形成新草稿”的方式，而不是直接修改线上版本。旧版本及其历史计算结果保持不变。

## 15. 409 并发冲突展示方法

使用同一账号在两个浏览器标签页打开同一个草稿版本：

1. 标签页 A 修改场景说明并保存。
2. 标签页 B 不刷新页面，修改主管部门后保存。
3. 标签页 B 使用的是旧 `resourceVersion`，后端应返回 HTTP 409。
4. 页面弹出“服务端版本已变化，是否重新加载最新版本？”提示。
5. 选择重新加载后，页面读取标签页 A 已经保存的最新版本。

这证明 `resourceVersion` 不只是页面展示字段，而是在阻止后提交的旧数据静默覆盖先提交的新数据。

## 16. Network 接口验收清单

完成一次从创建到发布的闭环后，Network 中应能找到以下请求：

|顺序|接口|页面动作|成功标志|
|---|---|---|---|
|1|`GET /api/v1/scenarios`|进入场景目录|返回分页 `items`|
|2|`POST /api/v1/scenarios`|创建并编辑|返回 `scenario` 和首个 `version`|
|3|`GET /api/v1/scenario-versions/{id}`|进入编辑页|返回完整场景版本|
|4|`GET /api/v1/indicator-versions?publicationStatus=PUBLISHED`|加载指标选择器|返回已发布指标版本|
|5|`PATCH /api/v1/scenario-versions/{id}`|保存草稿|`resourceVersion` 递增|
|6|`PUT /api/v1/scenario-versions/{id}/indicators`|保存指标集合|响应包含指标编码、名称、版本号|
|7|`PUT /api/v1/scenario-versions/{id}/overrides`|保存覆盖集合|响应包含覆盖规则，响应字段为 `value`|
|8|`GET /api/v1/scenario-versions/{id}/merged-preview`|刷新预览|返回 `effectiveParameters` 等有效口径|
|9|`POST /api/v1/scenario-versions/{id}/validate`|校验|返回 `valid`、`diagnostics` 和新 `resourceVersion`|
|10|`POST /api/v1/scenario-versions/{id}/publish`|发布|返回 `PUBLISHED` 和 `currentPublishedVersionId`|
|11|`POST /api/v1/scenarios/{scenarioId}/versions`|新建版本|返回复制配置后的新草稿|

## 17. 最终页面验收标准

满足以下条件，可以判定场景管理核心闭环展示通过：

```text
1. 场景目录读取的是后端分页数据，不显示原静态绩效考核演示页。
2. 能创建一个编码唯一的场景，并自动获得首个草稿版本。
3. 能为草稿选择至少一个已发布指标版本。
4. 能保存一条合法的参数覆盖规则。
5. 保存后资源版本递增，重新进入页面仍能看到指标和覆盖规则。
6. 合并预览能看到该指标的最终 effectiveParameters/effectiveExclusionDsl。
7. 校验结果来自后端；校验失败时不能发布。
8. 校验通过后能发布，发布版本立即转为只读。
9. 返回目录后能看到已发布状态和正确指标数。
10. 能从已发布版本创建下一草稿，旧发布版本保持不变。
11. 使用旧 resourceVersion 保存时，页面能识别并处理 409 冲突。
```

## 18. 当前边界说明

- “合并预览”是计算配置预览，不是指标结果试算。
- 当前场景发布成功不代表已经触发场景内全部指标计算。
- 当前全局场景选择器尚未与场景版本及分析查询完成联动。
- 当前页面以 JSON 文本编辑排除 DSL 和覆盖值，后续可继续接入结构化规则编辑器。
- 页面权限元数据已经配置，但正式菜单、按钮和字段级权限仍需结合后端权限集合完成联调。
- 所有成功结论应以真实接口响应和刷新后的后端回显为准，不能仅以页面弹出成功提示作为最终验收依据。
