# 查询链路整理与验收

## 本轮边界

本轮收敛看板跳转、指标分析报告期查询、下钻周期请求之间的周期与筛选协议。
前端分支为 `feature/medical-sso-dashboard`。已对照后端 `feature/ruoyi-user-permissions` 的正式分析和即时汇总接口；本轮未修改后端接口、计算口径、组织权限、历史正式结果或数据库。
这不是整个系统的重构完成声明，也不批量删除现有测试指标。

## 代码职责

| 文件 | 唯一负责的内容 |
| --- | --- |
| `features/analysis/reportPeriod.js` | 报告期口径、正式/即时分流、路由读写、筛选参数编解码；旧链接日期兼容只放在路由读入口 |
| `features/analysis/reportQuery.js` | 将确定的周期、指标版本、筛选与运行参数构造成正式或即时请求 |
| `features/dashboard/analysisNavigation.js` | 看板来源标识、固定/独立周期到分析路由的转换；复用报告期规则，不另写查询方式判断 |
| `views/IndicatorAnalysis.vue` | 用户交互、请求执行、结果状态；查询方式为推导值，不再单独维护可变状态 |
| `features/analysis/useAnalysisPeriod.js` | 排名/下钻的月季年正式周期选择、按版本与筛选隔离缓存、定位所选周期的正式结果 |

表中路径均相对 `src/idmp/`。

## 保持的业务约束

- 月、季、年只有完整且对齐的单周期查询正式汇总；自定义区间走即时查询，即使恰好覆盖一个季度或一年。
- 页面和新路由使用包含结束日的日期。正式接口接收相同日期；即时接口在请求构造层转换为不包含结束时刻的时间区间。
- 静态查询不传统计日期，不把存储用起止哨兵日期显示为实际报告期。
- 指标版本、科室多选和病种筛选保持不丢失；权限拒绝不切换接口，不退回全院数据。
- 趋势仍单独请求 `TREND`，不混入报告期即时汇总。科室排名和下钻仍按各自选中的正式周期定位结果。
- 查询失败不借用另一个周期结果，也不自动切换为另一种查询方式。

## 删除与修正

- 删除页面内的 `reportQueryPayload` 和 `nextDayStart`；正式/即时请求改用同一个构造入口。
- 删除页面和看板跳转中重复的模式判断，以及页面单独可写的 `reportQueryMode`。
- 看板跳转、报告期查询、下钻周期请求共用筛选序列化，保留原始字段编码及多选成员。
- 合并查询开始、编辑条件、页面刷新时的结果失效处理为 `invalidateReportSummary`，同步清空参数快照。
- 修正新查询缺少版本或被权限拦截时，旧的进行中请求仍能回写的问题。
- 旧链接将多月范围标为月度时，统一识别为自定义区间，不再把 `CUSTOM` 传给正式汇总接口。

## 保留的兼容与后续范围

- 历史 `granularity=CUSTOM` 链接的结束日期是排他的，仍在 `analysisReportContext` 中转换一次。删除前需迁移已保存链接，不能直接去掉。
- 看板历史来源标识优先级（分析指标 ID、指标 ID、编码）仍在导航边界保留，不能把数据源编码直接当指标版本。
- 后端旧结果结构、下钻结果 ID 推导和组织字段映射未在本轮重写。它们涉及正式快照和历史配置，需单独列出迁移与回归范围。
- 静态指标未配置下钻路径时仍可能出现默认下钻入口，这一既存问题不属于本轮周期协议重构，不能据本次验收声称已修复。
- 后续应分别收敛结果字段适配、下钻上下文、组织字段映射；不应把这些含义不同的内容塞进一个通用查询对象。
