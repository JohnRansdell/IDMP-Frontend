## 1. 设计书中的前端责任边界

详细设计书明确采用前后端分离：

- 前端 Vue 3 单页应用负责页面渲染、交互状态、展示逻辑。
- 后端 Spring Boot 负责 REST API、业务用例编排、领域规则执行和数据访问。
- Nginx 负责静态资源托管和 `/api/v1` 反向代理。
- 前端不得直接访问数据库、Redis、MinIO 或调度服务。

因此，前端 Demo 的目标不是“替代后端业务”，而是把后端已提供的业务能力以可操作、可展示的方式串起来。

## 2. 核心业务模块判断

从设计书看，当前 Demo 最应该围绕以下主线推进：

| 模块 | 设计职责 | 前端 Demo 关联 |
|---|---|---|
| M0 数据资产 | 数据域、语义字段、源表映射 | 作为因子 DSL 选择字段和数据域的基础 |
| M1A 因子管理 | 因子模板、因子版本、编译、试算、发布 | 指标计算的基础配置能力 |
| M1 指标管理 | 指标目录、指标版本、公式、试算 | 核心指标配置入口 |
| M7 计算引擎 | 批次、DAG、试算、结果、任务状态 | 试算链路、任务轮询、结果查询 |
| M8 分析展示 | 指标看板、指标分析、趋势对比、下钻、预警、导出 | Demo 展示结果和业务价值的核心页面 |

其中，M8 是演示效果最直观的模块。设计书中将其拆成：

- `IndicatorDashboard`：指标卡、目标值、同比/环比、趋势和科室对比。
- `IndicatorAnalysis`：趋势、对比、排名、分布和场景差异。
- `ResultDrill`：当前层汇总、趋势、明细、面包屑和下一层入口。
- `WarningCenter`：预警规则、事件、处理状态、通知记录。

## 3. 当前前端已完成进度

### 3.1 页面原型与导航

当前前端已经具备一套可运行的 IDMP 原型页面：

- 指标看板：`src/idmp/views/Dashboard.vue`
- 指标管理：`src/idmp/views/IndicatorManagement.vue`
- 指标编辑：`src/idmp/views/IndicatorEditor.vue`
- 因子管理：`src/idmp/views/FactorManagement.vue`
- 指标分析：`src/idmp/views/IndicatorAnalysis.vue`
- 场景管理：`src/idmp/views/SceneManagement.vue`
- 指标映射：`src/idmp/views/IndicatorMapping.vue`
- 预警中心：`src/idmp/views/AlertCenter.vue`

这些页面已经能支撑一条较完整的演示路径：

```text
指标看板 → 点击指标卡 → 指标分析 → 查看趋势/排名/下钻明细
指标管理 → 查看后端指标列表
指标编辑 → 演示公式配置与因子拖拽
```

### 3.2 指标看板编辑能力

看板已经实现：

- 组件拖拽。
- 组件 resize。
- 编辑模式和非编辑模式切换。
- 添加组件。
- 删除选中组件。
- 新增组件时先选择数据源，再选择展示类型。
- 支持 KPI、柱状图、折线图、饼图。
- 默认排版保持原有状态。
- 自定义布局保存到 `localStorage`。

当前这部分属于前端交互能力，已经可以作为 Demo 展示亮点。

### 3.3 多指标分析页

指标分析页已经从单一“手术患者并发症发生率”扩展为多指标配置：

- 住院死亡率
- 门诊人次数与出院人次数比
- 手术患者并发症发生率
- 抗菌药物使用强度
- 基本药物处方占比
- 医疗服务收入占比

看板指标卡可以点击进入对应分析页：

```text
/analysis?indicator=MORTALITY_INPATIENT
/analysis?indicator=SURGERY_COMPLICATION
```

这些封装为后续接入完整业务操作奠定了基础。


### 4.2 当前不可完全依赖的后端能力

接口文档明确说明，以下方案端点当前尚未形成 Controller 或不可推断为可调用：

- 因子列表/详情/新版本。
- 指标详情/修改/删除/发布。
- 场景管理。
- 指标映射。
- 采集转换。
- 数据质量。
- 结果下钻。
- 报表导出。
- 完整用户角色授权。

此外，M8 看板接口虽然文档列出：

```text
GET  /api/v1/analysis/dashboards
GET  /api/v1/analysis/dashboards/{code}
POST /api/v1/analysis/dashboards/{code}/query
```

但当前实测：

```text
GET /api/v1/analysis/dashboards
返回空数组

GET /api/v1/analysis/dashboards/quality-overview
返回 404
```

这说明后端目前没有初始化或发布 `quality-overview` 这个 `DashboardDefinition`。因此当前看板布局仍由前端本地配置兜底，住院死亡率数据则单独读取后端结果。

## 6. 完成核心业务 Demo 的建议目标

建议将 Demo 范围收敛为一条“住院死亡率核心链路”，不要一次性铺开所有模块。

推荐 Demo 主线：

```text
1. 指标管理页查看后端真实指标
2. 看板展示真实住院死亡率
3. 点击住院死亡率进入指标分析
4. 查看趋势、分子、分母、任务状态、质量状态
5. 展示住院死亡率完整链路说明：
   数据域 → 因子 → 公式 → 试算 → 结果 → 看板/分析
```

如果需要更进一步，可以加入“受控试算”：

```text
选择统计周期 → 触发住院死亡率试算 → 轮询任务状态 → 查询结果 → 更新看板
```

这条链路最符合当前后端已实现能力，也最容易形成可讲清楚的业务闭环。

## 9. Demo 验收标准建议

建议把 Demo 验收标准定义为三档。

### 基础可演示

- 页面可以部署并访问。
- 看板页面正常显示。
- 指标管理能显示后端真实指标编码。
- 住院死亡率显示真实后端结果。
- 点击指标卡进入分析页。

### 核心业务闭环

- 住院死亡率从后端获取分子、分母、结果值。
- 可以展示因子、公式、试算批次、任务状态。
- 可以手动触发一次住院死亡率试算，并刷新结果。
- 接口失败时页面有明确错误态。

### 接近正式系统

- 看板定义来自后端 `DashboardDefinition`。
- 指标分析来自后端 `AnalysisQueryService`。
- 下钻来自后端 `DrillQueryService`。
- 预警来自后端 `WarningRuleService` / 预警事件。
- 登录、权限、数据范围生效。

## 10. 当前建议结论

当前前端进度已经达到“可展示原型 + 部分真实后端数据接入”的阶段。

最值得继续推进的方向不是继续铺更多静态页面，而是围绕住院死亡率完成一个清晰的核心业务闭环：

```text
后端真实指标列表
→ 住院死亡率真实结果
→ 看板展示
→ 指标分析
→ 因子/公式/任务状态说明
→ 可选试算刷新
```

这条路径能最好地体现 IDMP 的核心价值：不是简单展示页面，而是把医疗质量指标从数据域、因子、公式、计算到分析展示串成一条可追踪链路。
